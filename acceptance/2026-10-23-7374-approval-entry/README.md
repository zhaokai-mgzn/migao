## 读图判定（逐条「看到了什么」）

| # | 验收点 | 读数 |
|---|---|---|
| 1 | 🔴 服务端原话在 | 顶部提示逐字：「盘点有差异（合计 2），必须先有已通过的「盘点差异」审批：objectType=stocktake_diff，objectRef=PD202610220001，金额 ≥ 2」——不含糊成「完成失败」 |
| 2 | 🔴 申请入口自动摆出 | 无需再点任何按钮，直接弹出「申请审批」 |
| 3 | 🔴 对象已填好 | 「申请对象：PD202610220001」= **盘点单号**（与闸门 `consume` 找的键一致），不是内部 id |
| 4 | 🔴 金额已预填门槛 | 审批金额 = `2`（差异合计的绝对值），下方提示「审批金额要 ≥ 本次差异合计（2），否则批了也用不上」 |
| 5 | 只要一句「为什么」 | 输入框带示例占位（「盘库时发现帘头受潮，实物已报废」）；必填 |
| 6 | 不误导 | 弹窗顶部写明「提交后要有人在『审批中心』通过才会放行；同一对象同时只能有一条待审申请」 |

## 未覆盖（照实登记）

- **价格本的低成本改价入口未截**：与盘点同构（对象 = SKU id、金额不预填只给门槛提示），由
  `price-books.test.tsx#低于成本被拒 ⇒ 就地开「改价」审批` 承担。
- **超授信**的口径纯函数已写好（ref = 客户手机号、金额 = 超出额），但订单创建页的入口**本段未接**。
- **退款 / 采购超量不做入口**：`ApprovalService.consume` 的调用点只有三处（改价 / 超授信 / 盘点差异）
  ⇒ 这两个类型目前**没有闸门在消费**，做入口就是假入口。
