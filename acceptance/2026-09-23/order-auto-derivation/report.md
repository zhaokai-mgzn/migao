**原判**（§7 第 1 条；§3 的 UA-1 / UA-2「证据」列）：UA 未做的原因是「**无浏览器环境**」。

### 11.2 订正 §7 第 3 条：`type="number"` 的判定从「Chromium **推断**」改为「真浏览器**实测**」，结论**推翻** jsdom 那条

**原判**（§7 第 3 条 + §4 末行）：「独立复核者同样无浏览器 ⇒ 其对 `type="number"` 站点
（`ProductForm` / `OversizeThresholdPreview` / `routings`）的判定是**代码 + jsdom 实证 + Chromium 推断**」；
§9.2 也如实记下了那场**谁也没说服谁**的分歧（修复侧：真浏览器 `0→.→5` 得 `0.5` ⇒ 无缺陷；
复核侧：jsdom 实测 `0.` ⇒ `""`（吞））。

**订正**：这条分歧**已有真浏览器判定** —— 见 **issue #5228 的最后一条评论**（本报告成文时作者 `zhaokai-mgzn`；
**内含自带源码、可直接重跑**的探针）：四种形态（非受控 / 受控按 React 真实写入规则 / 受控 + falsy 映射 /
受控 + 数值化回写）各敲 `0` → `.` → `5`，逐击读 `el.value` 一律为 `"0" → "0" → "0.5"`，
