# S28/S29：车间现场端（worker-h5）的**登录前链路**验通，并查出**一条试用阻断项**

## 🔴 高价值发现（试用前必须处理）：**本租户没有企业编码 ⇒ 工人端登录不了**
- worker-h5 登录要**三个字段**：**企业编码** + 工号 + PIN（页面自己写着「企业编码（向商家索取）」）；
- 实测本租户：`/api/auth/me` 的 `tenantId=25 / tenantName=观星台测试环境`，**设置页的企业编码为空**
  （源码 `settings/page.tsx` 的 `value={settings.code || ''}`；设置接口由 `GET /api/admin/settings` 下发，`data.code` 空）；
- ⇒ **工人拿不到可用凭据 ⇒ 车间现场端对客户不可用**，直到商家在「企业基础设置 → 企业编码」里设一个；
- ⇒ 这也**解释了本批一直存在的覆盖缺口**：bmini / worker-h5 的"登录后内容"从未被任何包验过（登录这一关就过不去）。
- **我没有擅自设置编码**：设置页原文警告「修改后员工需改用新编码登录（原「用户名@旧编码」立即失效）—— 改完立即生效」⇒ 属**全员登录凭据变更**，交人工。

## 🟡 观察项（登记，暂不开单）
1. **「参数校验失败」是内部口径**（服务端 422 原文直显）⇒ 工人看到的是开发术语，不是"企业编码不对"。同类先例在本批 P2/P3 治过。
2. 工人端登录**未做大小写归一**：企业编码格式要求小写，用户照屏抄成大写即被 422；
3. **工人档案弹窗的输入框没有 id / label 关联 / testid** ⇒ `getByLabel()` 绑不上（登录页的「手机号」是绑得上的 ⇒ 全站不一致）。属可访问性缺口，**不影响可见外观**。
