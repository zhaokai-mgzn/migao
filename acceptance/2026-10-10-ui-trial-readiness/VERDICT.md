## 十、今日的**自我更正**与**环境陷阱**（为什么值得信这份裁决）

**被当场推翻的，是我自己的结论**：
1. 空态行骗过行数统计（`tbody tr` 数到的那行是「暂无发货单」）⇒ 差点误判打印包前提。
2. "纸面不可验"是错的 ⇒ 补做并真抓到 P26。
3. **读图会骗人**：把 `累计金额(元)` 读成 `累…` 报"列头截断"；机械复核 7 张表 **0 处截断**。
4. 静默假阴性：真实数据探针取不到 token ⇒ 拿回 HTML ⇒ 把"读不到"打成"未命中"。
5. 读数无效**我先识别出来**：会话页注入读数缺锚 ⇒ 判定服务端不是 HEAD ⇒ 拉 main + 复位后重测。
6. 我的工具误伤别人：复位脚本原用 `pkill -f "next-server"` 杀全机器实例 ⇒ 改为端口作用域。
7. **#6707 的触发前提被我写错**（"大写企业编码 ⇒ 422"）：生产实测大写 + PIN 有值 = 反枚举 **401**；
   真身是 **@Valid 形状失败**（空 PIN 触发），而可行动的 `details[].message`「PIN 不能为空」在同一响应里被前端丢掉了
   ⇒ **真修的是文案通道**（#6739 已修）。我在 #6738 上**当众收回**了原判断。
8. 差点把 P23 判反：兜底腿命令看起来"跑全部 spec" ⇒ 看了**触发器**才发现它已停用。

**环境陷阱（今天最贵的一条，值得进规范）**：
- 本机 dev server 在**冷启动时路由扫描会非确定性残缺**（实测：一次只认 `/`，一次认 `/login` 却不认 `/dashboard`），且**永不重扫**；
  两次启动的唯一差别是**启动时的机器负载**（26~36 vs 3.6）。
- ⇒ **就绪门必须校验多个业务路由**，不能只看 TCP/`/login`/首页；否则会产出**看似有效的无效读数**（我因此废掉两轮）。
- 另两条同族教训：**清缓存与起服务必须严格顺序**（并发 ⇒ 服务端起在半删的 `.next` 上，永远 404）；
  **服务端必须作为长驻作业的主进程**（当子进程起，作业一结束它就被带走）。
- 顺手做了个自愈脚本：`acceptance/2026-10-10-ui-trial-readiness/scripts/serve-admin-web-3001.sh`
  （杀端口 → 清 `.next` → 起服务 → **校验四路由** → 不齐重来 ≤3 次 → 守住）。
- 我还两次栽在**非 ASCII 紧跟变量**上（`$SRV（` 把全角括号吞进变量名）⇒ 临时命令里也必须写 `${VAR}`。
