## 六、未覆盖 / 有意不做（**如实清单**，含重启条件）

1. **真机硬件**：打印机、扫码枪、短信通道 —— 不可得（无设备）。重启条件：拿到设备或客户现场。
2. **bmini / worker-h5 登录后内容**：无可用工人凭据（PIN 为 BCrypt，仓库无种子），只验到登录页与首屏。重启条件：拿到一个测试工人账号。
3. **写提交步骤**（下单/发货/报工/新建）**有意不点** —— 避免污染客户数据；只读面全验。
4. `1680×1050` 视口未测（已测 1440×980 / 1280×800 两档）。
5. `shipments` / `after-sales` / `production/pool` 的宽表**运行时**不可测（真数据行 0 或 1）。
6. 服务端下发文案（改服务端才能改的）不在前端射程。
7. 内容驱动的列宽（数据变长后是否溢出）未做压力样本。

## 九、今日的**自我更正**清单（为什么值得信这份裁决）

> 这份裁决里被我当场推翻的自己的结论，比留下的结论更有说明力 —— 每一条都记了证据：

1. **空态行骗过行数统计**：我用 `tbody tr` 数行得到 `/shipments` "有 1 行"，据此差点判打印包前提错误 —— 那个 `tr` 是空态行（末格 `data-testid="shipments-empty"`）。
2. **"纸面不可验"是错的**：我从 `/shipments` 无数据推断纸面不可验，其实订单详情页一直有打印入口（只读）⇒ 补做并真抓到 P26。
3. **读图会骗人**：我把 `累计金额(元)` 读成 `累…` 报了"列头截断"；机械复核 7 张表 **0 处截断**。
4. **静默假阴性**：我的真实数据探针 token 取不到 ⇒ 拿回 HTML ⇒ 脚本把"读不到"打成"未命中"。
5. **读数无效我先识别出来**：会话页首次注入读数缺 #6721 的锚 ⇒ 判定服务端不是 HEAD，**拉 main + 复位后重测**才采信。
6. **我自己的工具误伤别人**：复位脚本原用 `pkill -f "next-server"` 杀全机器 next 实例，可能带走并发包的 dev server ⇒ 已改为端口作用域。
7. **差点把 P23 判反**：兜底腿的命令看起来"跑全部 spec" ⇒ 看了**触发器**才发现它已停用。
