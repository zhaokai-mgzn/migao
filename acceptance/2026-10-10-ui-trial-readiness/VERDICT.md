## 五、本次收尾里**被我自己推翻**的东西（为什么这份裁决可信）

1. **`run-all.sh` 的"五支全绿"曾经是假的**：S7 明明含一行 ❌，整套却 exit 0 —— 因为 `run.mjs` / `run-count-row.mjs` / `run-live-reprobe.mjs`
   **只有打印、没有 `process.exit`** ⇒ 永远 0。**修法**：三支各自从已采集读数做**具名断言**并 `process.exit(红项数?1:0)`（不新增请求）；当场取到红证（S7 → 退出码 1）。
2. **`RESET=1` 一按就停**：它调的 `$ROOT/scripts/dev-web-reset.sh` **在本仓与包里都不存在**（README 却写成可用路径）⇒ 改为调包内真实存在的自愈脚本 + `nohup` 脱离 + 四路由门。
3. **版本自证印错了对象**：第一版印"证据包 worktree 的 HEAD"，而服务端编译的是**主检出**的树 ⇒ 已改为印主检出 HEAD/脏文件数/origin/main。
4. **打印判据三处过度/写错**（产品都是对的）：① 全域搜 `0.00` ⇒ 把**真 0**（该单本就无优惠）误报成缺陷 ⇒ 改成显式**独立值判据**（两轮逐字相同 ⇒ 独立已知 ⇒ 允许保留）；
   ② 按"以某词开头的行"解析明细行 ⇒ 该格文本含换行，只取到第一行 ⇒ 改为相邻制表位形态 `—\t—`；③ 明细路由要 **UUID** 不是 18 位订单号（用号会进"找不到"态）。
5. **差点误领功劳**：我曾声称修了"main 侧全 PR 阻塞红"（弱断言门禁）——查明那次红是**与 #6740 合并撞车**的运行时，而 #6740 **已经**把那两处一并去掉
   ⇒ 我的修复是 **no-op**，已在 PR body 里更正为诚实说明（含判据自带扫描器读数：main 版本 0 处）。
6. 更早、同族的自我更正见 v2 §十（空态行骗过行数统计 / "纸面不可验"是错的 / 读图把 `累计金额(元)` 读成 `累…` / 静默假阴性 / 无效读数我先识别 / 我的脚本误伤过并发包 / #6707 触发前提我写错并在 issue 上当众收回）。
