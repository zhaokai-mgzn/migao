## 二之二、**逐像素对照的实测边界**（我一开始把这条写过火了，如实改正）

我第一版写「`/dashboard` 与 BEFORE **逐像素级同构**」—— **这句话不成立**，`sha256` 对照就否掉了：

| 页 | `sha256` 对照 | 真因 |
|---|---|---|
| `/orders`（参照组） | **逐字节相同**（唯一一页） | 静态过滤结果，两侧同一批数据、无时钟 |
| `/dashboard` | **不同**（`160f9432…` vs `835360b5…`，字节数 148091 → 148108，**差 17 字节**） | 读图确认：**只差页头那行「数据更新时间：2026年10月16日 10:57 → 11:00」**。整版布局、17 个卡、每个数值（126 / 123 / ¥534 / ¥8,098…）**逐值相同**，连折线形状都一样 |
| `/settings` | 不同（−129 字） | 该页**未迁移**；差异来自被点开的折叠区块数量 |

⇒ **正确说法**：本轮的「未动」证据是 **`/orders` 逐字节相同**（1 页）；
`/dashboard` 是**人眼+读图确认的「只差时钟」**（不是逐像素）。
两条都能用，但**不能混着说** —— 「时间戳必然导致像素差」正是那种「听起来对、其实没验过」的话，
写进验收记录就会让下一个人以为存在一个不存在的逐像素判据。

**为什么原样留着这段而不是删掉**：验收记录的价值在于**读者能看出我验到哪一层**。
把「我以为是逐像素 → 实测只有 1 页逐像素 → 另 1 页是时钟差」这条链留住，
下一个人就知道**去哪里复算**（`shasum -a 256`），而不是相信我的一句形容词。

## 三、结论

- **用户的原话问题已修**：「只有订单页精美」的根因是**共享件缺失**（26 处手写页头各自为政、
  15 处内层容器无阴影），不是订单页做得特别好。现在**同一套原语**（`PageHeader` / `PageCard` /
  `SearchPanel`）被 14 页使用 ⇒ 「精美」从**一页的特例**变成**全站的默认**。
- **无回归**：`/orders`（参照组）**逐字节相同**；`/dashboard`（原本就对的页）读图确认**只差页头时钟**、布局与 17 个卡的数值逐值未动（见「二之二」的边界说明）。
- **观感判断（主观，如实标注）**：改善是**结构性的**（层级 / 分区 / 对齐），不是「变花」。
  配色反而**更克制**：冷色族 74 处收口后，暖色文字只剩 `primary`/`accent`/`neutral` 三族
  （改前 `blue`+`indigo`+`purple` 三色相服务的其实是**同一组状态轮换**）。

### 顺手抓到的三个更隐蔽的东西（截图与肉眼都看不见）

1. 🔴 **一条真假绿断言**：`className.toContain('w-[4.5em]')` 对 **`min-w-[4.5em]`** 也成立，
   而 `min-w` 正是被测的病灶 ⇒ 那条断言**永远绿**。已改为 className **切词后精确 token** 断言；
   回头把 7 个组件的**真实渲染 token 集**逐个 dump 比对，确认其余文件无同类前缀陷阱。
2. 🔴 **`PageCardProps.children` 标成必填** ⇒ `React.createElement(PageCard, { padded: false })`
   这种**合法**用法报 `TS2769`（3 条）。容器本就允许为空 ⇒ 改为可选。
3. 🔴 **一条时序假绿**：`CustomerPanel` 的「复制态 2 秒复位」用同步 `vi.advanceTimersByTime`
   ⇒ 只推进假时钟、**不冲刷 React 提交**，**单跑绿、与其它组件测试同批跑时红**（读到上一帧 DOM）。
   实测三种写法后定为 `await act(async () => { … })`；连跑 2 次批量 **61/61 绿**。

> 这三条都说明同一件事：**「本文件单跑通过」不是证据**。前两条靠「按真值 dump 对照」发现，
> 第三条靠「与邻居同批跑」发现 —— 与真浏览器验收同族的道理：**判据要在会被打破的条件下跑**。
