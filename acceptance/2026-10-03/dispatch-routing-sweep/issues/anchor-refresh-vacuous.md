## 现象：活锚自检**空比对却报绿**（读数逐字）

执行（业务仓）：`MIGAO_PRESET_MIRROR=$HOME/migao-dev-preset-anchor ./scripts/preset-anchor-refresh.sh`
尾部输出逐字：

```
      - .git/FETCH_HEAD
      - .git/HEAD
      …
   ✅ 活锚新鲜：内容与 origin/main 逐字节一致（0 个文件）（sha 关系未判：活锚 HEAD 0668b129a0ff 不在基准仓对象库里
      —— **活锚是 git 检出**，只是两边的对象库不同刻）

✅ 活锚自愈完成：镜像已跟随 origin/main，且自检绿。
```

🔴 **两个可疑点**：
1. **「0 个文件」**：它拿**业务仓**（基准 = `--repo` 默认本仓）的 `origin/main` 当对照，而业务仓**已不再承载 `.agent-presets/**`**
   （`git ls-tree -r origin/main --name-only .agent-presets | wc -l` = **0**；提交 `0e059836e` / #6034 明确「业务仓不再承载预设」）
   ⇒ **比对面为空集**，任何内容都能过 ⇒ 这条自检在当前拓扑下**没有信息量**。
2. **它仍然打印 `✅ 自检绿` 并以 exit 0 收尾** ⇒ 一个**永远绿的空检查**被当作"刷新成功"的证据
   （同族地雷 = `migao-acceptance` 的「不会红的断言 = 空断言」）。

**这次为什么没造成事故**：我用**独立判据**兜了底 —— 直接读加载点
（`~/.dsh/.agent-presets/migao/skills/migao-dev-flow/SKILL.md` ⇒ `version: 1.106.0`、`## 30.` 在位、四条规则记号齐全）。
但**下一个只看脚本退出码的人会以为"刷新即生效"**。

## 要求

1. 让自检在**当前拓扑**下真正判事：活锚目标 = **预设仓检出**（`preset.yml` 在仓根）时，对照必须是**预设仓的 `origin/main`**。
   ⚠️ 业务仓 `AGENTS.md` 的「开发环境准备」节已声明「自检**按拓扑自动选判定**（换链后 = 拓扑 A：活锚 = 预设仓检出的仓根）」
   —— 若代码已实现而这次仍走了空比对，那是**实现与声明不符**，以实际读数为准（**禁读工作树**：读 `origin/main:<path>` 核）。
2. 🔴 **空集不得报绿**：比对面解析出 0 个文件、或对照 ref 在目标仓里不存在 ⇒ **fail-closed**（明说"判不了"+ 处置指引），
   不许打印「✅ 活锚新鲜」。
3. **红证**：① 注入"比对面为空" ⇒ 判据红（不是绿）；② 正常拓扑 ⇒ 真比对通过（两侧夹住）；
   ③ 活锚落后于预设仓 main ⇒ 红并指名落后。
4. **判据按现取**（去读真 ref，不钉手抄清单）；别把"对象库不同刻"这类**预期**情况判成失败（它是正常的，只是**不能**作为"一致"的依据）。
