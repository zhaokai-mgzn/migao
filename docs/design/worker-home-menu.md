## 0. 一句话

工人工作台的菜单按**工人这一天怎么干活**重排：一个**常驻主按钮（扫码领活）** + 三组功能（干活 / 物料 / 出货）+ 「我的」；
菜单条目由**服务端** `GET /api/worker/me` 的 `pages` 驱动 —— 这份真值**今天已经存在**，而 bmini 工人工作台**一个字节都没消费它**。

![工人工作台菜单原型（390×844）](./assets/worker-home-menu-390.png)

（原型 = throwaway 静态 HTML，非线上代码；实心块 = 今天已有面，虚框块 = 菜单应该有的、今天还没有面的条目。）

## 3. 呈现规则（每条都能落成会红的判据）

1. **首屏必须见到「扫码领活」**（§31 五问之「第一眼能不能看到要做的事」）。390×844 实测：身份卡 + 主按钮 + 「干活」组落在首屏内，其余可滚。
2. **主按钮唯一**：全屏只有「扫码领活」是 primary（现状它与其它入口等权）。
3. **分组标题是工人的话**：干活 / 物料 / 出货 / 我的 —— 按**动作发生的地点与时刻**分组，不按系统模块分组。
4. **条目 = 人话名 + 一句「拿它干什么」**；屏上**不出现**内部标识（页面键、路由字面量、权限码）—— §31 P3。
5. **未开的面不渲染**（不是置灰、不是点了报错）—— 与「工人端页面」开关的既有语义一致（**菜单显隐，不是访问拦截**，2026-09-29 用户逐字改判）。
6. **读不到页面集 ⇒ fail-open**：按全开渲染 + 一句显式提示（沿用 worker-h5 既有口径 `permUnreadNotice`：把「开关没读到」变成「活干不了」是更坏的失败）。
7. **触控目标与车间现实**：≥44px（PAD 断点更大）、间距足够（戴手套）、对比度足够（弱光 / 反光屏）。

## 4. 机制：菜单由服务端 `pages` 驱动（本设计的主要结构变更）

```
商家端「设置 → 工人端页面」            WorkerPageConfigPanel（V141）
        │  写
        ▼
WorkerPages 闭词表 { report, order, cut_calc, shipment }      ← 全仓唯一真值
        │  GET /api/worker/me → pages（+ labels）
        ▼
工人端渲染 ──┬── worker-h5 `/w/`：`effectivePages()` 已消费（report / cut_calc）
             └── bmini 工人工作台：**零消费**（3 条硬编码入口）  ← 本设计要补的这一半
```

**顺带收口一条「声明存在 ≠ 可达」**：bmini 工作台不消费 `pages` ⇒ 商家在「工人端页面」里关掉某一页，在 bmini 上**不生效**（开关是死的）。本设计把两端的消费口径统一到同一份服务端真值。

## 5. 命名：两份标签，都在服务端

商家说「订单」，工人说「我的活」—— 同一把键、**两种视角**。⇒ 标签也放服务端（建议在 `WorkerPages` 旁增 `workerLabels()`），端侧**不硬编码任何中文**（否则是第二份会漂的真值）。

| 键 | 商家面标签（现状） | 工人面标签（建议） | 副标（工人面） |
|---|---|---|---|
| `report` | 报工 | 扫码领活 | 扫一次码 = 把这道活领走（先领活再生产，做完不用再扫） |
| `order` | 订单 | 我的活 | 订单 / 套号 / 还要做哪几道 |
| `cut_calc` | 裁高计算器 | 裁高计算 | 这块布裁多长（一体机那台屏也在用） |
| `shipment` | 发货 | 拍照发货 | 拍运单 / 商品标签 ⇒ 生成发货单 |
| `piecework`（建议新增） | — | 我的计件 | 本月做了多少、这一笔怎么算的 |
| `to_ship`（建议新增） | — | 待发货单 | 不用先记住单号，从列表点进去 |

## 6. 分批与待裁定

### 6.1 第一批（零后端 / 现有端点，可立即落码）

① 服务端 `pages` 驱动菜单（含「拿不到 ⇒ fail-open + 显式提示」）② 扫码领活升为唯一主按钮 ③ 四组分组与工人话命名 ④ 现有四个面接上（拍照发货等 #6761）。

### 6.2 第二批（需新端点；一条已裁定，两条待裁定）

| 条目 | 需要的端点（形状示意） | 待裁定 | 不裁时的安全默认 |
|---|---|---|---|
| **我的活** | `GET /api/worker/production/my-tasks`（我在制的单 / 套 / 待做工序） | 范围 = **我经手的** 还是 全厂待做？ | 我经手的（不泄露他人计件归属） |
| **待发货单** | `GET /api/worker/shipment/to-ship`（admin 侧 `/api/admin/shipments` 工人 403） | 范围与字段：全厂 / 我经手的；是否显示客户名、金额？ | 全厂待发货，只显示单号 + 客户简称 + 件数，**不显示金额** |
| **我的计件** | `GET /api/worker/piecework?month=`（**合计金额** + 件数 + 逐笔工序/单价快照） | ✅ **已裁定（2026-10-12 用户逐字「需要给工人看」）** —— 口径见 §6.3 | —— |

### 6.3 「我的计件」口径（2026-10-12 裁定：**金额给工人看**）

涉钱面，六条钉死：

1. **单一真值（最重要）**：金额聚合**复用商家端既有计件读面**（`GET /api/admin/production/piecework/summary` 的实现，`backend/admin-api/src/main/java/com/migao/admin/service/ProductionService.java` + `ProductionController`）——工人面**只做**「按当前工人 + 期间」的**过滤投影**，**不许**写第二份求和实现（涉钱面两份口径必然分叉，而分叉不会变红）。
2. **作用域**：`worker_id` **只**由 `X-Worker-Session-Id` 解（服务端），前端**不许**传、也不许能传（与发货留痕同一条纪律：责任/工资凭证不能由前端自称）。
3. **期间**：默认当前自然月（Asia/Shanghai），可切上月；按报工时间归月，半开区间 `[月初 00:00, 次月初 00:00)`。
4. **未定价**：`unit_price IS NULL` 的行**不计入合计**，但必须在屏上**显式列出**「N 道未定价（未计入合计）」——**绝不**印 0 元（既有口径：未定价 ≠ 0 元，V90 / #4696）。
5. **只读**：工人面恒只读；不做确认、不做锁定、不做结算（用户 2026-09-19 裁定 2 保留）。
6. **口径风险登记**：若商家端计件报表对「已取消 / 返工 / 改价」有扣减口径，工人面**照同一份**，不许自行发明；实现 PR 的 body 必须写明它复用的那个实现位置与复算命令。

## 7. 判据形态（会红 = 才算判据）

| # | 判据 | 红证（怎么单独变红） |
|---|---|---|
| 1 | 端侧渲染的条目集合 == 服务端 `pages` **逐值相等**（多一个 / 少一个 ⇒ 红） | 端侧写死多一条入口 ⇒ 红 |
| 2 | **未开的面在屏上取不到**（`queryByTestId` 为 `null`，不是 CSS 隐藏） | 关掉 `shipment` 仍渲染 ⇒ 红 |
