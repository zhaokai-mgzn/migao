# 企业基础设置 = 配置指挥台（重新设计）

> **状态**：设计真值源（2026-10-09 起）。承接 issue #6573（IA 调整 + 配置主线，已合并）与 #6580（收拢配置面）。
> 触发（用户 2026-10-09 逐字）：
> 「我希望**重新设计企业基础设置这个页面功能**，让他能**清晰的引导用户完成配置**，并且**用户体验好**」
> 以及「我希望**加工项管理和工艺配置全部功能都收拢到参数总揽里面**……**我的目的是要能移除加工项管理和工艺配置这两个菜单**」。
>
> **本页的目标不是「把参数集中列出来」**，而是：**商家不知道改这个会变什么、也找不到**（§22.1 的两条真实痛点）
> ⇒ 这页要回答的问题是「**我还缺什么、下一步去哪、改它会发生什么**」。

## 0. 一句话形态

**企业基础设置 = 配置指挥台**：顶部一条**配置主线**（还缺什么 / 下一步），下面按**配置域**分栏；
每个域自带状态、计数与**就地编辑面**；主线的「去配置」**跳到本页内那个域**（不把人送出页面）。

```
┌ 企业基础设置 ───────────────────────────────────────────────────────────────┐
│  配置主线   配置完成 3/8 · 2 项待配置 · 下一步「加工费组合」        [展开 ⌄]   │ ← 常驻一行
├──────────────┬─────────────────────────────────────────────────────────────┤
│ ① 工序与单价 ✅ │  加工费组合                              ⚠️ 待配置           │
│ ② 工艺路线   ✅ │  一组选配特征 → 一个单价（元/米）                              │
│ ③ 加工费组合 ⚠️ │  现在 3 组组合，有 2 种特征组合命中不到 ⇒ 那一行**收不到价**     │
│ ④ 加工项与分类 ✅│  ───────────────────────────────────────────────────────    │
│ ⑤ 算料口径   🕐 │  [就地编辑：组合列表 + 单价 + 命中预览]        [改完预览影响面] │
│ ⑥ 余料回收   —  │                                                             │
│ ── 经营面 ──    │                                                             │
│ ⑦ AI 客服        │                                                             │
│ ⑧ 工人端页面     │                                                             │
│ ⑨ 企业信息       │                                                             │
│ ⑩ 通知设置       │                                                             │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

三态沿用 #6573 已落地的口径：**已配置 / 待配置 / 读不到**（`读不到` 绝不画成 `待配置`）。
读数一律来自服务端（聚合端点见 #6579），前端只格式化、不重算（§31.3）。

## 1. 为什么是「主线 + 域」而不是「tab 平铺」

| 形态 | 问题（今天真实存在） |
|---|---|
| **tab 平铺**（今天的 `/settings`） | 四个 tab 之间**没有顺序**：商家不知道先配哪个；「参数总览」曾经是第五个 tab，但它既不告诉人缺什么、也不给去处 |
| **纯列表**（今天的「工艺配置」页） | 一屏 2600 行的编辑面，首屏就要人读表；缺配置只在页内某处提示，跨页的缺口看不见（#5858 实测「同屏两个矛盾的数」就是这么来的） |
| **主线 + 域**（本设计） | 首屏先回答「还缺什么、下一步」；域内才是编辑面；「去配置」跳到本页那个域 ⇒ **一条走得完的路**（不把人送出页面再让他自己找回来） |

## 2. 分区逻辑：**按「一笔单的钱与活怎么走」排**（不是按旧页面排）

用户 2026-10-09 逐字：「新的页面功能**不能再是散乱的配置乱放**，必须有**逻辑性和条理**」。
⇒ 分区的**唯一依据**是**因果关系**：一张订单进来，先算多少钱 → 再去车间怎么做 → 然后料怎么省 → 最后才是这家店长什么样。
每个域只回答一个问题，**同一件事只在一个域里出现**（不重复、不交叉）。

| 区 | 这一区回答的问题 | 域（**按依赖顺序编号**） | 内容来自今天哪里 |
|---|---|---|---|
| **一 · 报价与计费** | 这一单**收多少钱**？ | ① **算料口径**（每片用料怎么算） | 工艺配置页「算料公式参数 + 术语与口径」= 原「参数总览」算料域 |
| | | ② **加工项与分类**（这家做哪些加工） | 加工项管理页「加工项 + 分类」 |
| | | ③ **加工费组合**（什么特征 → 什么价；含**未定价缺口**） | 加工项管理页「加工费组合 + 未定价组合」 |
| **二 · 生产执行** | 这一单**在车间怎么走**？ | ④ **工序库**（车间有哪些活） | 工艺配置页「工序目录」 |
| | | ⑤ **工序与部位单价**（每道活给工人多少钱 = 计件） | 工艺配置页「工艺项 · 计件单价」 |
| | | ⑥ **工艺路线**（走哪些工序、什么顺序；含**默认路线**） | 工艺配置页「工艺路线」 |
| | | ⑦ **路线规则**（什么条件走哪条路线） | 工艺配置页「路线规则 / 适用条件」 |
| **三 · 余料与省料** | 裁下来的料**怎么不浪费**？ | ⑧ **余料尺寸**（小件用料尺寸表） | 原「参数总览」余料域（`processing:manage`） |
| **四 · 企业与账号** | 这家店**长什么样、谁能进来**？ | ⑨ **企业信息**（名称 / Logo / 手机端入口） | 今天 `/settings` 的「基本设置」 |
| | | ⑩ **AI 客服**（名称 / 欢迎语） | 今天「AI 客服设置」 |
| | | ⑪ **工人端页面**（页面开关） | 今天「工人端页面」 |
| | | ⑫ **通知设置** | 今天「通知设置」 |

**四区的因果链**：一 → 二（路线要用到工序与加工项）→ 三（裁料依赖算料口径）→ 四（与前三个无依赖，放最后）。

🔴 **配置主线就是这个链条的「体检表」**：主线的步骤顺序 ≡ 域编号顺序中**必配**的那些
（工序库 → 工序与部位单价 → 工艺路线 → 默认路线 → 加工项 → 加工费组合 → 算料口径），
所以「主线说的下一步」永远能在左栏**往下**找到那个域 —— 这就是「清晰引导」的可断言形态（G2/G3/G4）。

🔴 **不许出现的东西**（判死线）：
1. **同一份配置在两个域各挂一次**（旧形态：算料口径既在「工艺配置」页又在「参数总览」页）；
2. **一屏里两个就绪度**（旧形态：`/production/routings` 自带的「配置就绪度」卡 + 新页主线）；
3. **域内再套一层 tab**（旧形态：加工项管理页内 tab + 页面 tab ⇒ 三层导航）；
   ⇒ 域内的编排由**本页左栏**独占表达。

## 3. 引导怎么做到「清晰」（每条给可断言的形态）

| # | 设计动作 | 可断言形态（判据口径） |
|---|---|---|
| G1 | **主线常驻**：进页第一眼就是「完成 3/8 · 2 项待配置 · 下一步『X』」 | 折叠态**只有一行摘要**，逐项 DOM 不渲染（§31 P1；#6573 已有实例判据） |
| G2 | **下一步永远只有一个**：摘要点名的那一步，就是「去配置」该点的那个 | 摘要文案里的步骤名 ≡ 主线里第一个非 `done` 步 |
| G3 | **去配置 = 页内跳转 + 高亮**（不再跳走） | 点击后 URL 带 `#domain-<key>`、该域进入展开态并被标记为当前域 |
| G4 | **域导航带状态点**：与主线**同源**（同一次读数） | 域的徽标文字 ≡ 主线里该步的徽标文字 |
| G5 | **每域三件套**：这是什么 / 现在什么状态 / 改它会怎样 | 每域都有 `hint` + 状态 + `impact`，且**键集覆盖**由守卫钉住（§22 基线③） |
| G6 | **改钱的东西给预览**：算料与加工费域提供「按当前口径 vs 按你改的值」双列对照 | 预览走服务端真值重算，**不发 PUT**（§22 P4） |
| G7 | **术语就地可查**：参数旁锚到术语条目 | 复用 `glossaryAnchorOf` 先例（§22 P5） |
| G8 | **保存有回执**：域级「已保存 · 刚刚」+ 失败给可行动话术（**按 HTTP 状态归因**，不再一律猜「没权限」） | 403 ⇒ 权限话术；其余 ⇒ 「读数/保存服务暂时不可用（不是你的权限问题）」 |

## 4. 首屏与信息密度的纪律（§31 P1~P4）

- **P1 常驻面克制**：首屏 = 标题 + **主线一行** + 域导航 + **当前域摘要**；不摆全部表单，不摆两处进度。
- **P2 信息不重复**：摘要只说「几项没配」；域内只说「这一项为什么、去哪」——**同一句话不在两处各写一遍**。
- **P3 不摆内部标识**：上屏只有菜单名与人话，不出现权限码 / 端点 / 表名 / 配置键（键名只在输入框的等宽副标位置）。
- **P4 语调**：只陈述事实 + 该做什么，不催促、不惊叹号。

## 5. 权限模型（**待人工裁定，见 #6580**）

合并后这一个菜单节点只能挂**一个**码，而内容跨两个码的域：
`production:view`（①~⑤）与 `system:manage`（⑥~⑩）。

| 选项 | 代价 |
|---|---|
| **A（推荐）** 节点码取 `production:view`，域按各自码显隐；同批把 `production:view` 补给 `system:manage` 持有岗位 | 生产岗看得到菜单但只见生产域；**授权 delta 必须逐条可复算**（写进 PR body） |
| **B** 节点码保持 `system:manage`，把 `system:manage` 补给生产五岗 | 授权面更大（他们同时拿到 AI 客服 / 通知等设置面），与最小授权相抵 |
| **C** 不删菜单，只做只读镜像 | 不满足「移除两个菜单」的目标 |

**不裁时的安全默认**：按 **A** 落地，并把授权 delta 逐条列在 PR body。

### v1 的已知债务（**照实登记，不许读成"已经做到"**）

1. 两个 board 自带**内部 tab**（原页面的编排）—— 与左栏域导航并存，属设计 §2 判死线第 3 条的**已知例外**；
   页面源码头部与本节都写明「v2 拆解」。
2. `ProcessConfigBoard` 自带一块**配置就绪度**（原 `/production/routings` 的第一块）——
   在 `craft-route` 域里会出现**同屏第二处就绪面**（判死线第 2 条）。v1 用「本页主线是唯一常驻就绪面」+
   域内那块属 board 内部来兜，v2 拆解时删除。
3. 「余料尺寸」域没有主线步骤（主线今天不含它）⇒ **不显示徽标**（宁缺勿滥）；补主线步骤见 #6579。
4. 「加工项」域与「加工费组合」步的对应：域 `processing-fee` 覆盖主线步 `fee-combinations`；
   「加工项与分类」本身还没有主线步骤（同上，见 #6579）。

## 7. 不在射程（如实登记）

- **不重写**既有编辑面：S2/S3 是**搬运 + 域化包装**，编辑逻辑复用既有组件（重写 = 造第二份口径）。
- 不改算料存储形态（仍为结构化列，D6′ 方案 A 的裁定不翻）。
- 不做「一键修复缺配置」（改动钱的东西必须人确认）。
- 本设计**不新增门禁、不改任何通过条件**；P1/P3/P6/P7 里只有 P1 有实例判据（§22.4 的边界照旧）。
