## 0. 一句话

商家只填**三项**：**商品颜色 + 净窗宽 + 净窗高**。其余全部由系统推导 ——
**加工类型（定高买宽 / 定宽买高）/ 用料 / 工艺 / 超高 / 超宽 / 倒幅 / 拼接（拼N次）/ 接高 / 接宽**，
且**每一项都可人工改**；改过的项不再被推导覆盖。

## 1. 用户裁定（2026-09-22，逐字留档）

1. 「如果出现要拼几次的情况，那只能单色」
2. 「这里的拼几次和拼色是不同的概念，拼几次默认都按单色韩折公式或者倍数公式算」
3. 「优先倒幅，如果倒幅后仍然无法满足，那么再重算是接高，还是接宽，还是倒幅后接宽接高，可以多自动化推算出一个最优结果」
4. 「根据第三题的回答来自动判定，可人工加，接高，拼接也允许人工加」
5. 「接高和接宽都只能最多接0.1米，且不参与算料」
6. 「自动推导的工艺配置仍然能人工修改」

## 2. 推导输入（系统侧，非用户输入）

| 符号 | 含义 | 来源 | 缺失时 |
|---|---|---|---|
| `D` | 门幅（米） | 所选颜色的 SKU 门宽（`product_skus.door_width`） | **不可判定**（没有缺省门幅）⇒ 显式告知，不猜 |
| `hem` | 上下卷边（米） | 租户算料配置 `hem_margin` | 引擎默认值 |
| `formula` | 用料公式 | 工艺推导（韩褶 ⇒ 褶数法 / 打孔 ⇒ 倍数法） | 配置 `default_formula` 兜底 |
| 档位 / 褶倍 | 用料档位 | 租户算料配置 `tiers`（默认标准档） | 引擎默认值 |
| `style` | 款式 | 默认**单色** | — |

推导的**唯一实现**在算料引擎 `backend/ai-agent-service/app/tools/curtain_calc.py`（Java 与前端**不复制第二份**）。

## 3. 推导规则：候选枚举 + 选优

定义：
- `T` = **单色**定高买宽单幅用料（米）= 现有单色公式值（韩褶公式或倍数公式）。
- `need_h` = `H + hem`；`P` = `ceil(T / D)`（倒幅分幅数）。

| # | key | 方案 | 可行条件 | 用料 | 拼接 | 接高/接宽 |
|---|---|---|---|---|---|---|
| 1 | `fixed_height` | 定高买宽 | `need_h ≤ D` | `T` | 0 | — |
| 2 | `fixed_height_join_height` | 定高买宽 + **接高** | `0 < need_h − D ≤ 0.1` | `T`（**接高不进算料**） | 0 | 接高 gap = `need_h − D` |
| 3 | `fixed_width` | **倒幅**（定宽买高） | 恒可行（拿到 `D` 即可） | `P × need_h` | `P − 1` | — |
| 4 | `fixed_width_join_width` | 倒幅 + **接宽** | `T − (P−1) × D ≤ 0.1` 且 `P ≥ 2` | `(P−1) × need_h`（**省一整幅**） | `P − 2` | 接宽 gap = `T − (P−1)×D` |
| 5 | `fixed_width_join_height` | 倒幅 + **接高** | **几何上恒不成立** ⇒ 恒 `feasible=false` | — | `P − 1` | — |

**选优顺序**（**用户 2026-09-23 裁定「甲」**）：结构 = 「**约束优先 + 目标最省**」
（= **字典序多目标**：约束键在前、目标键在后）—— 先把「拼接」当**档位**，再在**同一档内**比目标：

| 档位 | 键 | 性质 |
|---|---|---|
| **约束档** | 拼接次数（拼幅数 / 拼缝数） | **硬约束** —— 先保证不拼、尽量少拼；**不许**被「省料」交换 |
| 同档目标 ① | 用料（米） | 同一个拼接档内先比它 |
| 同档目标 ② | 接高 / 接宽次数 | 同档内的次级目标 |
| 收敛 | 候选表顺序 | 同档内完全并列时的**确定性**收敛（不是一条口径） |

⇒ 写成一串（**键序的唯一源 = 引擎 `_rank`**，上屏文案同源）：

**① 拼接次数最少 → ② 用料最少 → ③ 接高/接宽最少 → ④ 候选表顺序**

- **术语**：结构名 = 「**约束优先 + 目标最省**」；本行业口语叫法 = 「**无拼接优先 / 整幅优先**」——同一条约束的两种说法。
- ⚠️ **「用料最少优先」不是另一种行业惯例**：它只是把「目标」那一半拎出来说，**丢掉了约束档**
  （把硬约束降级成可被「省料」交换的软指标）⇒ 是不完整的说法，读起来像「用料是首要目标」。
- **为什么不把「用料」放第 ①**（v1.1 曾如此，**已按用户裁定对调**）：那会让「定高买宽可行、但倒幅用料更少」的算例去选倒幅 ——
  **省 0.6 米布换 3 道可见拼缝**（实证 `economy / 门幅 3.2 / 宽 6.6 双开 / need_h 2.8`：倒幅 11.2 米拼 3 次
  vs 定高买宽 11.8 米零拼接）。拼缝是**客户看得见**的品质项，且带工序与计件 ⇒ 属**硬约束**。
- **量化依据**（纯函数网格，可复算）：(门幅, 净窗高, `T`) 空间里 2130 个「有可行候选」的算例中，
  **793 例（37.2%）**两种顺序选出不同候选，且**全部**是「定高买宽·零拼接 ↔ 倒幅·有拼接」；
  维持现口径 = 平均多花 **1.593 米**布、少 **3.314 道**拼缝。
- ⚠️ **§1 裁定 3 的「优先倒幅」是当时的逐字留档**（历史），已被本口径**覆盖**（不是并存关系）：
  同理 `CHANGELOG.md` 与 `acceptance/**` 里的旧表述也是历史记录，**不回改**（§9「当时时点的诚实记录」）。

**为什么候选 5 恒不成立**：倒幅下每幅的**幅长按米购买、不受门幅上限约束** ⇒ 高方向不存在缺口，既不需要也无法接高。
它仍**保留在候选清单里**（裁定 3 要求系统逐个「再算一遍」），以 `feasible=false` + 理由返回，**不得**为它编一个用料公式。

**由此两条归属**：**接高只出现在「定高买宽」**（高方向受门幅约束）；**接宽只出现在「倒幅」**。

**候选 4 的条件方向**（易写反，红证在此）：正例 `T=5.65, D=2.8 ⇒ P=3`，`5.65 − 2×2.8 = 0.05 ≤ 0.1`
⇒ 用 2 整幅 + 一条 **≤0.1 米接宽布条**顶掉第 3 幅 ⇒ 用料 `2 × need_h` **小于**纯倒幅的 `3 × need_h`；
反例 `T=6.0, D=2.8 ⇒ P=3`，`6.0 − 5.6 = 0.4 > 0.1` ⇒ 不可行（此时丢掉一整幅还差 2.8 米）。
写成 `P×D − T ≤ 0.1` 是**反的**（会得出「丢掉一整幅却仍需要 2.7 米布」的荒谬结论）。

### 硬规则

- **R1** 接高 / 接宽缺口上限 **0.1 米**（裁定 5）。缺口 > 0.1 ⇒ 该候选**不可行**。
- **R2** 接高 / 接宽**不参与算料**（裁定 5）：不另买布、不改米数、不改加工费米数。接宽布条来自边角料。
- **R3** **拼N次用单色公式**（裁定 2）：拼N次 ≠ 拼色，**不得**给拼次叠加任何「每折吃布」系数。
- **R4** **出现拼接（N ≥ 1）时款式只能是单色**（裁定 1）：`style=拼色` 且 `N ≥ 1` ⇒ 显式冲突告知，**不静默改款式**。
- **R5** `N ∈ {1,2,3}` ⇒ 归一到特殊选项名 `拼1次` / `拼2次` / `拼3次`（进工序与计件，
  见 `backend/ai-agent-service/app/production/routing.py` 的 `SPECIAL_OPTION_ROUTINGS`）；
  `N = 0` 或 `N ≥ 4` ⇒ `splice_option = null`，**不得发明「拼4次」**。
- **R6** 全部候选不可行 ⇒ 用料 `null` + 全部候选与不可行理由，**fail-closed，不静默兜底、不给估算值**。
- **R7** 人工覆盖（裁定 4 / 6）：显式传入的加工类型 / 拼次 / 接高 / 接宽**逐字采用**，`auto=false`，不再自动改判；
  人工加仍受 R1 的 0.1 米上限与 R2 的零用料约束。

## 4. 两条必须区分的概念（本仓最易搅在一起的一处）

| 概念 | 是什么 | 用料口径 | 取值来源 |
|---|---|---|---|
| **拼N次** | **几何分幅**：一幅帘由 `N+1` 幅布拼接而成 | **单色公式**（本页 §3） | **自动推导**（`panels − 1`） |
| **拼色** | **款式**：主布 + 配布边两种面料分料 | 每折吃布 `1个折 0.65` / `2个折 1.2` 米（纸质速查表表头，用户 2026-09-19 裁定为**用料**） | 商家选款式 + `拼1次`/`拼2次` 特殊选项 |

⇒ 「拼1次/拼2次/拼3次」这两个字在两个概念里都出现，**但不是同一件事**：几何分幅用它命名**拼接缝数**，
拼色用它承载**每折吃布系数**。**判断依据**：`resolve_per_fold` 只在 `style=拼色` 时才读那张系数表；
拼N次本身（`style=单色`）**一律走单色公式**。

## 6. 判据（每条必须能红）

1. `need_h ≤ D` ⇒ 定高买宽 / 拼接 0 / 用料 `T`；把门幅调小 ⇒ 变定宽买高。
2. `D=2.8, T=6.0` ⇒ `P=3`、拼2次、`拼2次`、用料 `3×need_h`；把 `splice_option` 映射改成 `P` ⇒ 红。
3. 候选 4 的正例可行且被选优、反例不可行（数值见 §3）；把条件写成 `P×D − T ≤ 0.1` ⇒ 红。
4. 缺口 0.25 米 ⇒ 所有接高候选 `feasible=false`；把上限从 0.1 改成 0.25 ⇒ 红。
5. 接高/接宽可行时用料与不加时**逐值相等**（R2）；把加高条米数加回去 ⇒ 红。
6. `style=拼色` 且 `splice_times ≥ 1` ⇒ 显式冲突告知（R4）；删掉该告知 ⇒ 红。
7. 拼次 3 ⇒ `拼3次`；拼次 4 ⇒ `null` + 告知（R5）；补一个「拼4次」⇒ 红。
8. 不传 `fabric_width` ⇒ 结果与接线前**逐值一致**。
9. 显式传加工类型 ⇒ `auto=false` 且逐字采用；`join_height_m=0.2` ⇒ 422。
10. `data.plan.meters === data.fabric_meters`。
