## 一、参考图设计语法拆解

截图（豆包 App 首页）的输入框之所以「合理自洽」，核心是 5 条语法：

| # | 语法 | 图中证据 |
|---|------|---------|
| G1 | **单一容器**：文本输入、能力开关、附件、语音全部住在同一个大圆角浅灰容器里，结构不随输入方式改变 | 一整块圆角容器，placeholder「发消息或按住说话」 |
| G2 | **placeholder 承担双语义提示**：「发消息**或**按住说话」一句话说明两种输入方式，无需模式切换键 | 输入区占位文字 |
| G3 | **能力 chips 在容器内左下**：⚡深度思考 / 🌐智能搜索，icon+文字胶囊，能力可见可切 | 容器左下两枚胶囊 |
| G4 | **动作键右下成组、自适应**：[+] 与 (·)) 两个圆形细线 icon 键靠右下（拇指区）；有文字时语音键位被「↑ 发送」顶替 | 右下两枚圆形 icon |
| G5 | **图标语言统一**：同一粗细线性 icon，无 emoji、无字符凑数 | 全部图标同一风格 |

附带一条（本次不展开）：欢迎屏是「logo + 问候 + 模式 pill + 输入框」垂直居中成组——输入框是空态的主角。

## 四、目标设计

### 4.0 三条设计原则

1. **一个容器**（G1）：预览、状态、chips、输入、动作键都住在同一个圆角容器内；容器结构不因输入方式而改变。
2. **角色语法统一，按设备摆放**：控件按「内容输入 / 添图 / 语音 / 主动作（发送⇄停止）」四个角色定义；移动端动作键全部落右下拇指区（豆包式），桌面端保持「工具左、动作右」惯例。自洽 = 同一套角色与视觉语言，不是两端像素复制。
3. **图标一统**：禁 emoji、禁裸文本字符；两端同一份图标清单（§4.4），C 端用 SVG 补齐。

### 4.1 C 端目标布局（对齐参考图，改动主体）

```
┌────────────────────────────────────────────┐
│ [缩略图 64×64 ×n] [＋上传进度遮罩]  (×)     │ ← 有草稿图才出现（两种模式一致）
├────────────────────────────────────────────┤
│ 发消息或按住说话…                    ← textarea 常驻（placeholder 双语义）
│                                            │
│                (ImagePlus) (AudioLines)    │ ← 右下动作组；有草稿时 AudioLines → (↑)
└────────────────────────────────────────────┘
```

- **删除 🎤/⌨️ 模式切换键**：textarea 常驻，键盘自然唤起；语音变成右下一个「按住说话」圆键（对齐参考图，消灭模式制）。
- **语音键 = 按住说话**：按下开始录音（容器顶部浮录音条：红点脉冲 + 计时 +「松开发送 · 上滑取消」），松开 → 转写文本**直接发送**（评审决策 D1：保持 UI-007 现行为「松开直接发送」不变，见 §5-D1）；转写失败 toast「未听清，请重试」，不发送。
- **自适应主动作键**（G4）：草稿（文本或图）为空 → 右下是 [添图][按住说话]；草稿非空 → 语音键位顶替为 [↑ 发送]；流式中 → [■ 停止]。
- **添图统一草稿语义**：ImagePlus 一律「选图进草稿」，删除语音模式 📷 直接发送旁路；「拍窗帘照片识别」场景不受影响——选图后直接点 ↑ 即为纯图消息（UI-013 协议原样）。
- 上传进度画在预览块遮罩上（spinner + 「上传中」），添图按钮只置灰不换 icon。

### 4.2 B 端目标布局（保持桌面惯例，语法对齐）

```
┌────────────────────────────────────────────┐
│ (ImagePlus)(AudioLines)  textarea…   (↑/■) │ ← rounded-2xl 容器（现状保持）
│ [预览缩略图 ×3，内嵌容器内顶部]              │ ← 从容器外移入容器内
├────────────────────────────────────────────┤
│ ⚡快捷 chips（收纳 QuickActions，P2 可选）   │ ← 参考图 G3
└────────────────────────────────────────────┘
        AI 生成内容仅供参考
```

- 添图/语音保持左侧（桌面鼠标行为，右下是发送键位），**icon 与角色对齐 C 端**（ImagePlus / AudioLines）。
- **录音状态条**替代 placeholder 文案：录音中在预览区位置显示「● 正在录音 0:07 · Esc 取消 / Enter 完成转写」（红点脉冲动画），placeholder 恢复短句「输入消息…」。
- 发送键 Send → **ArrowUp**、停止键 StopCircle → **Square**，与 C 端同形（端到端视觉记忆一致）。
- 上传态同样「按钮置灰不换 icon，进度在预览块」。

### 4.3 状态机矩阵（两端合并视角）

| 状态 | textarea | 预览区 | 添图键 | 语音键 | 主动作键 |
|---|---|---|---|---|---|
| 空闲·无草稿 | 双语义 placeholder | 隐藏 | 可用 | 按住说话 | 隐藏（C）/ 置灰（B） |
| 有草稿（文本或图） | 正常编辑 | 显示（含删除 ×） | 可用（<3 张） | — | ↑ 可发送 |
| 录音中 | 置灰 | 录音状态条 | 禁用 | 红色脉冲 | — |
| 转写中 | 「转写中…」 | — | 禁用 | spinner | 隐藏 |
| 上传图片中 | 可编辑 | 缩略块进度遮罩 | 置灰（不换 icon） | — | ↑ 可点（发已就绪部分）* |
| 流式生成中 | 置灰（B 端现状） | — | 禁用 | 禁用 | ■ 停止生成 |
| 会话已结束 | 替换为「会话已结束…」 | 隐藏 | 禁用 | 禁用 | B 端：新建对话；C 端：置灰 |

\* 现状语义保持：有未完成上传时禁止发送（避免丢图），仅在「全部就绪或全部失败」时可发。

> **D1 决策注**：转写完成后的去向两端为既定差异——C 端**直接发送**（UI-007 现行为）、B 端**追加进 textarea**。本次不改该差异，仅统一其交互容器与状态呈现。

### 4.4 图标规格（单一来源清单）

| 语义角色 | B 端（lucide-react） | C 端（新增 SVG，同源造型） | 备注 |
|---|---|---|---|
| 语音输入（按住说话） | `AudioLines` | `audio-lines.svg` | 替代参考图 (·)) 语义；弃用 Mic（录音设备视角）与 🎤 |
| 添图（进草稿） | `ImagePlus`（现有） | `image-plus.svg` | 弃用裸 `+` 与 📷；如未来扩多附件类型再升级为 `+` 面板 |
| 发送 | `ArrowUp`（替换 Send） | `arrow-up.svg` | 圆形实底键，激活=主色，禁用=中性 |
| 停止生成 | `Square`（替换 StopCircle） | `square.svg` | 实底方形白 icon，红色系键 |
| 移除草稿图 | `X`（现有） | `x.svg` | 角标常显（弃 hover 才显），挪进缩略图内右上避免溢出裁切 |
| 键盘（仅 C 端 H5 降级提示用，可选） | — | `keyboard.svg` | H5 stub 环境无语音键即自然消失，可不引入 |

**C 端实现方案**：Taro 小程序不支持内联 `<svg>`，沿用仓库既有 `data:image/svg+xml;base64` + `<Image>` 模式（见 ProductCard PLACEHOLDER_IMAGE 先例），新增 `components/chat/icons.ts` 导出图标组件；线稿烧双色（中性 `#5A6B7C` / 反白 `#FFFFFF`），禁用态用 opacity，不依赖 currentColor。

### 4.5 分端视觉 token 对照（布局统一、颜色分端）

| Token | B 端（织物质感） | C 端（深蓝金） |
|---|---|---|
| 容器 | 白底 + `neutral-200` 描边 + rounded-2xl（保持现状） | `$bg-secondary` 浅灰底 + `$radius-xl` 大圆角（对齐参考图） |
| 主动作键激活色 | `primary-600` 靛蓝（去渐变，降视觉噪音） | `$gradient-brand` 或 `$brand-blue` |
| 录音警示 | red-500 系（现状） | `$error-color` `#E5484D`（现状） |
| 禁用 | `neutral-300` | `$text-tertiary` + opacity |
| icon 默认色 | `neutral-400→600` hover | `$text-secondary` |

## 五、关键交互决策（评审点）

### D1 语音转写：直接发送 vs 进草稿 —— **已拍板（2026-09-06）：保持「松开直接发送」**
原推荐「进草稿」以求两端一致；评审结论：**C 端保持 UI-007 现行为「松开直接发送」**（高频语音用户路径短；微信式肌肉记忆），B 端维持「转写追加进输入框」。两端语音语义差异为**既定产品行为**明示于此，本次只统一交互结构（单容器/图标/键位），不动该行为。UI-007 用例修订范围随之缩小为「交互结构」描述（textarea 常驻、删模式切换键、语音改右下按住键），行为断言不变。

### D2 C 端语音模式 📷 直接发图旁路 —— **推荐删除，统一草稿**
同一入口两种语义必删其一；识图场景由「选图进草稿 + 空文本直接 ↑ 发送」等价覆盖（后端 vision 链路、UI-013 纯图协议均不动）。

### D3 B 端 QuickActions 收进输入容器 —— **推荐做（P2 可独立）**
对齐参考图 G3，减少输入框上方一条割裂横幅；chips 样式已是胶囊，迁移成本低。注意 e2e 中快捷操作定位方式。

### D4 发送键形态 —— **推荐两端统一 ↑ / ■**
参考图 G4；B 端 Send→ArrowUp 是一行改动，换来两端同一肌肉记忆。

### D5 C 端语音大胶囊 —— **推荐降级为圆形 icon 键**
胶囊把视觉重心压在「输入方式」而非「输入内容」上；录音态信息移到容器顶部录音条（与 B 端同构）。
