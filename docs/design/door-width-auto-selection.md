## §2 口径与公式

```
g_eff(g) = g − allowance                    # allowance 缺省 0（租户级配置键未落地，见 §6）
T        = 定高买宽用料                       # 由既有公式算出（倍数法 / 褶数法皆可），本单不改公式
k        = 开数（open_count）
```

### 2.1 自动选择（两条分支，**无第三分支**）

**① 定高买宽（正幅）** —— 可行集非空时

```
可行 = { g | H + HEM_MARGIN ≤ g_eff(g) }
非空 ⇒ 取 min(可行)          # 用料 T 与门幅**无关** ⇒ 取小 = 不占宽幅布（宽幅布留给真正超高的窗）
M    = T
```

**② 倒幅（定宽买高）** —— 可行集为空时

```
panels(g) = ceil(T / g_eff(g))
取 panels 最小者（并列取**较小**门幅 —— 不占宽幅布）
M = panels × (H + HEM_MARGIN + 花距)
```

> ⚠️ **为什么可行集为空时不走接高**：行业实践是超高窗用**倒幅**（左右拼接，**竖缝藏进褶皱**），
> 而接高是**上下拼接、横缝可见**（见 §5 证据）。自动选接高 = 系统性推荐可见横缝。
> ⇒ 接高退为**人工覆盖项**（裁定 4/5）。

### 2.2 接高（**仅人工覆盖时**算料，口径 A）

> ⚠️ **该「人工覆盖」当前无活入口**（issue #5040 复核）：工具 schema（`CurtainCalcTool.parameters`）、
> `CurtainCalcTool.execute` 签名、admin-web 的加工类型 chips **都没有**「接高」这一档 ⇒
> 本节口径今天只在**引擎 API 层**（`build_quote(cutting_mode=...)` / `resolve_fabric_plan`）可达。
> 详见 §6。

```
g_max = max(g_eff)                       # 用最宽门幅 ⇒ 缺口最小
d     = H + HEM_MARGIN − g_max           # 缺口（米）
d_eff = d + (花距 if 对花 else 0)         # 对花：每条加高条 +1 个花距（同倒幅「每幅 +1 花距」）
Wp    = T / k                            # 片宽
段数   = ceil(k / floor(g_max / d_eff))   # 一段布（长 = Wp）能在门幅内并排裁出 floor(g_max/d_eff) 条
M     = T + 段数 × Wp
```

## §3 为什么接高口径是 A，不是「按缺口面积折料」

「按缺口面积折料」（`M = T × (1 + d/g)`）**会算出买不到的布**。

算例（`W=3.0` / `H=3.0` / `N=2` / `g=3.2` / 双开）：`T = 6.6`，`Wp = 3.3`，`d = 0.1`。

| | 算式 | 结果 |
|---|---|---|
| 按缺口面积折料 | `T × d/g = 6.6 × 0.1/3.2` | **0.206 米** |
| 加高条的**长度硬下限** | 加高条长 = `Wp`（为与主幅**同纹理方向**，`Wp` 必须沿布卷长度方向） | **3.3 米** |

`0.206 < 3.3` ⇒ **买 0.206 米布裁不出那条 3.3 米长的加高条**。这不是「余料能不能回收」的差别，
是**量纲错位**（把「面积 ÷ 门幅」当成了买料米数，而买料米数受「条子长度」这个下限约束）。

该口径唯一能成立的形态是「把加高条**旋转 90°** 裁」，但那让加高条纹理/花型与主幅**错 90°**
（同「倒幅花型倒了」之病），且本例 `Wp = 3.3 > g = 3.2` **连转都转不下** ⇒ 车间不会这么做。
它另有「余料折回本单」的隐含前提（**材料成本**口径），与本系统「顾客按米付面料费」的
**本单采购**口径不符。

## §4 判据（每条都要有能**单独**让它变红的红证）

| # | 判据 | 算例（`W=3.0` / `N=2` / 候选 `{2.8, 3.2}`） | 期望 |
|---|---|---|---|
| 1 | 定高买宽可行 ⇒ 取**最小可行门幅** | `H=2.75`（`2.75+0.3=3.05`）：2.8 不可行、3.2 可行 | 门幅 **3.2**，`M=6.6` |
| 2 | 可行集为空 ⇒ **倒幅** | `H=3.0`（`3.3>3.2`） | 定宽买高，`panels=ceil(6.6/3.2)=3`，`M=9.9` |
| 3 | **不自动选接高**（接高更省也不选） | 同上 + 四开：接高 `8.25` < 倒幅 `9.9` | 仍选**倒幅** |
| 4 | 人工覆盖接高 ⇒ 口径 A 算料（**仅引擎 API 层可达**，见 §6） | 同上双开：`6.6 + ceil(2/32)×3.3` | `M=9.9` |
| 5 | 对花 ⇒ `d_eff = d + 花距` | 同上 + 花距 `0.4` ⇒ `d_eff=0.5` | 段数按 `floor(3.2/0.5)=6` 算 |
| 6 | 自动结果**可覆盖** —— 可覆盖的档位 = **定高买宽 / 定宽买高**；**接高当前无活入口**（见 §6） | 显式传 `cutting_mode=定宽买高` 覆盖自动解 | 显式值生效（不再按自动规则改判） |
| 7 | 缺口大到一段裁不完 ⇒ 段数递增 | `d_eff` 使 `floor(g/d_eff) < k` | `段数 = ceil(k / floor(g/d_eff))` |

> **红证形态**：把任一条的期望值写成「恒真」都算空断言。判据 3 尤其关键 ——
> 它钉的是「**接高不参与自动比较**」这条业务裁定，改回「米数小的赢」必须让它红。
>
> ⚠️ **可达性（issue #5040）**：判据 4 / 6 里的**接高**档当前**无活入口** —— 工具 schema、
> `execute` 签名、admin-web 加工类型 chips 都没有该档 ⇒ 它只在**引擎 API 层**可达；
> 判据 6 里**能**被用户覆盖的只有「定高买宽 / 定宽买高」两档（引擎层另有
> `backend/ai-agent-service/tests/test_curtain_calc_fabric_plan.py` 的
> `test_explicit_rotated_mode_is_respected` 钉住）。

## §5 裁定 4 的依据（行业证据）

`docs/curtain-selling-method-industry-research.md` §3.3（标注【背】= 背景知识、**不参与系统推导**；
来源 S16 = 媒体/从业者，**证据强度中**，**非实证**）：

## §5.1 「定高买宽不可行」的判据与**行业标准的有无**（2026-09-21 核查）

### 判据（**纯几何，硬约束**）

```
定高买宽不可行 ⟺ 成品高 + hem_margin > 门幅有效值
```

| 门幅 | 成品高上限（`hem_margin` = 默认 0.3） |
|---|---|
| 1.4（窄幅） | 1.1 米 |
| 2.8 | 2.5 米 |
| 3.0 | 2.7 米 |
| 3.2 | **2.9 米** |

⇒ 这也解释了候选门幅集的价值：**2.8 → 3.2 能把「成品高 2.5~2.9 米」这一段从倒幅救回正幅**。

> 🔴 **2026-09-22 改判（issue #5130，用户裁定 D1 / D2 / D3 / D7 / D10）**：上面的几何判据管的是
> **用料与加工类型**（几何层）—— 它**已不是**自动特征「超高 / 超宽」的判据。用户裁定：
> 「超高 / 超宽」改为**企业阈值参数**判定（`净窗高 > oversize_height_threshold` /
> `净窗宽 > oversize_width_threshold`，默认值见真值源 `docs/curtain-fabric-quote-rules.md` §0 的
> `OVERSIZE_*_THRESHOLD` 两行）⇒ **判定面不读门幅**；
> 原三条判定面裁定（#4661 按加工类型分流 / #4662 超宽须含褶倍 / #4877 缺门幅不判）**一并退役**。
> ⚠️ 本节其余内容（门幅选型 / 接高 / 几何约束）**一字未动** —— 它们本就属于几何层。
> 两条「超高」判据的**分层**登记见
> `docs/design/oversize-threshold-and-enterprise-params.md` §4.4（几何层 vs 特征层）。

### 行业标准：**分三层，只有第一层是硬的**

| 层 | 内容 | 性质 | 证据强度 |
|---|---|---|---|
| ① 几何约束（本系统在用） | `成品高 + 卷边 ≤ 门幅` | **物理硬约束** | 无需来源 —— 布做不出就是做不出 |
| ② 门幅标准值 | 定高布 2.8m（亦有 2.7 / 3.0）；窄幅 1.4m | 行业标准值【标】 | `docs/curtain-fabric-quote-rules.md` §2 |
| ③ 选型经验阈值 | 「层高 ≤ 2.7 / 2.75 / 2.8 ⇒ 用定高布；超过 ⇒ 倒幅」 | **经验建议，非约束** | **弱**：三处口径互不一致，最强只到「媒体 / 从业者」（S16）；其中引用的《国家住宅建筑设计规范》层高条文，调研文档**自标「未溯源·待确认」** |

**结论：没有一条可引用的国标 / 行标规定「定高买宽何时不可行」。** ①②可编码，③**不编码**（只作话术背景）。

### ⚠️ 一处真实的口径裂缝（**已登记，未改**）

三处阈值**不可直接比较**：本系统真值源 §3 说的是**成品高** ≤ 2.5~2.6（门幅 2.8），而行业说的是**层高** ≤ 2.7~2.8。
本系统已裁定「顾客给的尺寸**直接就是成品高**，不做离地 / 轨道换算」（#4877）⇒ 顾客说「层高 2.7」会被当成品高 2.7
⇒ `2.7 + 0.3 = 3.0 > 2.8` 判不可行，而行业口径说 2.8 定高布「最合适」。

差在 **`hem_margin`（默认 0.3）**：行业口径隐含卷边 ≈ 0.1，否则 2.7 层高根本做不出 2.8 定高布。
**处置**：`hem_margin` **已是可配的算料配置键**（#4976 包 1b，第 7 个键）⇒ 该裂缝**商家可自行校准，无需改代码**
（前提：算料配置页露出该键，属 #4976 前端接线）。**本单不改默认值**（改默认值 = 改钱）。

### 接高**没有自动触发条件**（照实登记）

倒幅几何上**永远可行**（`幅数 ≥ 1` 恒成立）⇒ 在「定高买宽 > 倒幅」的自动规则下，**接高在自动模式下永不被选中**，
只能在**引擎 API 层**显式传 `cutting_mode=接高`（**当前无活入口**，见 §6）。
行业里接高**唯一「必须」**的场景是**花型 / 纹理有方向**（竖条 / 大花型 / 提花 / 绣花 / 绒布顺毛 ⇒ 不能倒幅）；
而 #4877 已裁定「**默认都能倒幅**（不需要『花型是否有方向』字段）」⇒ 系统今天**会对有方向的花型照样倒幅，且无任何告警**。
用户 2026-09-21 裁定：**暂不加「不可倒幅」输入**（先不着急）。本缺口保持登记。

## §6 未裁定 / 缺口（照实登记）

- **接高的加工费**已有且本轮**不动**：工序 `接高-布`（`unit=幅`，单价仍是占位 1）、
  特殊选项 `接高` / `双眼皮接高`（按**套**收费，V77 `customer_unit_price`）。本单只补**面料米数**。
- `allowance`（门幅有效余量：缩水/边损/对花回）今天缺省 `0`，租户级配置键**未落地**（#4877 已登记）。

- 🔴 **金额不进目标函数**（用户 2026-09-21 裁定「**暂不加**」）：目标函数 = **用料米数**。
  ⇒ 定高买宽取最小可行门幅、倒幅并列取较小门幅，**都只看米数、不看单价** ——

  倒幅加项与接高工序的**加工费差异**同样不进比较（比米数 ≠ 比总价）。
  该口径与 `frontend/admin-web/src/lib/door-width-plan.ts` 自述的「**不做金额最优化**」同源。
  ⚠️ 副作用已实测：成品宽 3.0 / 高 3.0 / 2 倍褶 / 四开时，**接高 8.25 米 < 倒幅 9.9 米**，

- 🔴 **库存与门幅有效余量暂不做**（用户 2026-09-21 裁定「**都暂不做**」）：
  ① 候选门幅集**是否按库存过滤由调用方决定** ⇒ **缺货门幅也可能被选中**；
  ② `allowance` 缺省 `0` ⇒ 判定用的是**标称门幅**（偏乐观）。
