# 商家可见文案规范（去「研发腔」）

> issue **#6488**（用户 2026-10-07 逐字：「我们系统中暴露了大量的这种研发过程产生的文字，适当的文档可以
> 引导和教育用户如何使用我们的产品，但是这类文案明显不是一个好的引导文案」「最好是扫描下全部商家后台
> 页面，目标是提高文案的真实价值和作用，去除这类看不懂的文字」）。
> 机械判据 = `frontend/admin-web/scripts/user-copy-scan.mjs`（规则单一源）+ 守卫
> `frontend/admin-web/tests/unit/user-copy-jargon-guard.test.ts`（未登记即红）。

## 1. 判的是什么（口径）

**判的是「会不会被商家看到」，不是「源码里有没有这个词」。**
上屏面 = JSX 文本、JSX 属性（`label` / `title` / `hint` / `placeholder` / `aria-*`）、toast 与错误提示、
`src/lib/*-glossary.ts` / `tenant-params.ts` / `meters-formula-legend.ts` 这类**文案助手**。

**不在射程**：注释与 JSDoc、`console.*`、CSS 与打印样式表、`data-testid`、字段名与接口契约、
设计文档（`docs/design/**`）—— 那里本来就该写实现细节。

## 2. 六条机械规则（命中即红，判据源见扫描器；另加 §6 的四条副标题规则）

| 规则 | 形态 | 出口（改法） |
|---|---|---|
| **R1** 接口/协议细节 | 端点 / 入参 / 返回体 / 分页参数 / 拉全量 / 读面 / 写面 / 幂等 / 落库 / 数据库 / 服务端 / 内核 | 换成商家视角：「系统查不到」「请先选中商品」「这一列只读」；细节留注释 |
| **R2** 内部机制名 | 组合键 / 派生值 / 真值源 / 单一源 / 快照 / 状态机 / 兜底 / 插值 / 落账 / 静默 | 换成**对商家的后果**：「会走另一档加工费」「这个数是算出来的」 |
| **R3** 研发过程编号与判据语 | `issue #NNNN` / `#NNNN` / `PR #NNNN` / `V1xx` / 判据 / 待查明 / 死亡条件 / 回归测试 | 整句删掉；要留追溯写进注释 / PR body |
| **R4** 代码标识符上屏 | `oversize_height_threshold`、`scan_url / part_token`、`pending_review`、`PC-yyyyMMdd-NNNN` | 用中文名（「超高阈值」）；键名留给注释与文档 |
| **R5** 行内代码片里塞标识符 | `` `HEM_MARGIN` ``（`InlineMarkdown` 会把它渲染成一个代码小片，issue #5194） | 代码片只放商家看得懂的名字，或整段去掉反引号 |

复算（一条命令，退出码 ≠ 0 就是还有命中）：

```bash
node frontend/admin-web/scripts/user-copy-scan.mjs            # 汇总 + 命中清单（退出码 ≠ 0 = 仍有命中）
node frontend/admin-web/scripts/user-copy-scan.mjs --rule R2  # 只看某条规则
```

## 3. 三档处置（散文级：规则判不了，靠这条）

| 档 | 判据 | 动作 |
|---|---|---|
| **A 保留** | 告诉商家「这是什么 / 我该做什么 / 做了会怎样」的**行业语言** | 不动 |
| **B 改写** | 意思有用，但站在**系统/研发的视角**说 | 换成商家视角，**不改**它承载的承诺 |
| **C 删除** | 对商家**没有下一步动作**的实现细节与设计辩解 | 删掉 |

**P1（B 档）**：主语换成「你 / 系统」，动词是商家的动作。
　· 反例：「判据是客户口径（企业参数，可配），非 ERP 实证 ⇒ 系统标注为「推算」」
　· 正例：「这个阈值是你们家自己的口径，不是 ERP 里的固定值 —— 系统会把它标成「推算」」

**P2（C 档）**：**设计辩解**一律删 —— 「本页宁可不查，也不做「一次拉全量」的假方便」
（读者是商家，不是评审）。
　· 正例：「批次余量要按商品查：先在上方搜一个商品再点选。」

**P3**：**长句拆成「一句做什么 + 一句怎么做」**，不写实现流程图。
　· 反例：「建单（草稿）→ 过账（自动生成批次号 + 自动加库存 + 移动加权平均成本）→ 批次可追溯」
　· 正例：「先建单（此时不动库存）；确认无误后过账，系统才会生成批次号并加库存。」

**P4**：**保留承诺与边界**（这是文案的真实价值所在）。改写不得弱化以下信息：
　· 「未定价 ≠ ¥0.00」（#4886 口径）
　· 「拼接 / 接高要你自己选，系统不会自动判断」+「勾了只影响加工费，不会多排一道工序」
　（**死亡条件**：绑 issue #4569，改口径时文案与守卫一起改判 —— 见 `docs/design/craft-calc-glossary-and-terms.md` §6）
　· 算例里的数字**一律由真值渲染**，不许写死（同 §6 判据 5）

**P5**：**同一条口径只有一处措辞**。文案助手（`craft-calc-glossary.ts` / `tenant-params.ts`）是单一源，
页面引用它；页面里再抄一份 ⇒ 漂移起点。

## 4. 明确**不**在射程（别改坏）

- **行业术语**：用户 2026-09-21 裁定「界面用行业术语」（#4678）。裁床 / 车位 / 门幅 / 净窗高 / 缸号 /
  余料 / 拼色 / 倒幅 / 韩褶 一律保留。
- **业务对象名**：「余料台账」「批次账」「工艺路线」是**商家在用的名词**（也是菜单项）⇒ 保留。
- **行内强调**：`**加粗**` 由 `InlineMarkdown` 渲染（issue #5194 用户裁定）⇒ 保留；只有**代码片内容**
  受 R5 约束。
- **`(corporate)` 官网**：同一纪律适用，但它的话术目标是「建立信任」而非「教操作」，
  改判口径单独走（本规范 §2 的机械规则照旧适用）。

## 5. 边界（照实登记）

1. **机械规则只覆盖「词」**：散文级的啰嗦、辩解、系统视角（§3）**判不了** —— 那是纪律，靠人 / AI 评审。
2. **扫描器只抽三类候选**：JSX 文本、JSX 属性、含中文的字符串与模板串字面块。动态拼出来的句子
   （`.map()` 里 JSX 混合）会抽成碎片 ⇒ 可能漏（只会**少扫**，不假红）。
3. **豁免台账 `EXEMPT` 当前为空**；守卫会逐条复算，**失效的豁免当场判红**（只许缩短）。
4. 本规范**不改**任何行为、接口、字段名、权限、算料口径。

## 6. 页面副标题：讲「这个功能干什么」+ 关键规则加粗（用户 2026-10-08 定的标准）

用户 2026-10-08 在验收线上页面时给了**正例**与**两条补充**：

> 应该按这样的标准来设计这种文案，参考客户管理的「客户管理 / 管理客户信息、标签和互动记录」
> 智能派单这种也好，把一些特殊规则也加黑加粗表示出来

### 6.1 形（照着写）

- **一句话说清这个页面/这个功能是干什么的**（正例 `管理客户信息、标签和互动记录`）；
- 允许补**关键规则/边界**，但**关键那半句必须加粗**：
  正例 `待派订单按料（商品 × 颜色 × 门幅）合并 —— 同料合并领料，减少接头损耗；**加急单不参与合并，立即单独派单**`；
- 加粗的落法：JSX 文本里用 `<strong>…</strong>`；字符串/数据模块里用 `**…**`
  （经 `@/lib/inline-markdown` 渲染，并登记 `tests/unit/lib/copy-no-markdown-emphasis.test.ts` 的表）。

### 6.2 不写（每一条都有真实病灶）

| 不写 | 病灶（逐字） |
|---|---|
| 机制链路 / 推导箭头 | `工序与计件单价 → 工艺路线 → 算料 / 裁高口径`、`⇒` |
| 表达式 | `每一行 = 一次库存变动` |
| **本企业各自的数值口径** | `含 0.5 米级尾料`、`0.1 米粒度` —— 用户原话「**每个企业的标准不一样，我们不用写明这种数值，只需要告诉用户这个功能是解决什么问题的即可**」 |
| 占位符字母 / 模式代号 | `库存为什么从 X 变成 Y`、`A 模式 · 只查「没开工」` —— 用户原话「**用户不理解这句话是啥**」 |
| 机制名 / 字段清单 / 营销话术 | `按移动加权平均重算成本`、`数字经校验 · 数据安全隔离` |

### 6.3 判据（机械可判的四条，`SUBTITLE_RULES`）

只扫**商家后台** `src/app/(dashboard)/**` 的页面头（`h1` 的兄弟 `<p>`）；官网有自己一套对外口径，**不在射程**。

| 规则 | 形态 | 出口 |
|---|---|---|
| S1 | 副标题里的箭头链路（`⇒` / `→`） | 拆成一句「这个功能干什么」；链路留给设计文档 |
| S2 | 副标题里的表达式（`每行 = 一次…`） | 改成陈述句 |
| S3 | 副标题里的本企业数值口径（`0.5 米级` / `0.1 米粒度`） | 讲解决什么问题；精度留给输入校验提示 |
| S4 | 副标题里的占位符字母 / 模式代号（同 R9） | 换成商家的话 |

**复算**（在仓库根跑；两个面一起报，退出码 ≠ 0 = 还有命中）：

```bash
node frontend/admin-web/scripts/user-copy-scan.mjs
```

### 6.4 边界（判不了的那半句）

**「这句话讲的是不是用途」判不了** —— 机械判据只能否掉五种坏形态，剩下的靠**评审**：
写副标题时先回答「这个页面是给商家解决什么问题的？」，答不上来就说明原句是写给研发看的。
错误态（如「无权访问」）**允许写长**：它必须给出「缺什么 + 去哪儿开」，登记在 `SUBTITLE_EXEMPT`（只许缩短）。
