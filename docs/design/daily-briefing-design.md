> 版本：v0.2（已确认三项决策）

> 定位：商家后端智能经营简报——企业级开关 + LLM 行动清单
> 依赖文档：[admin-dashboard-design.md](admin-dashboard-design.md) · [Frontend.md](../wiki/Frontend.md) · [RBAC](../wiki/RBAC.md) · [gb47746-2026-compliance](../wiki/gb47746-2026-compliance.md)

## 一、产品定位

**每天清晨，系统自动把「商家昨天经营得怎么样 + 今天必须处理什么」凝练成一份带证据、带优先级、可一键直达行动的报告。**

核心价值不是"看数据"，而是**替管理者把今天该做的决定和动作想好、排好序**——管理者打开只做三件事：**看、问、点**。

**已采纳的三个设计决策**：

| # | 决策 | 内容 |
|---|------|------|
| 1 | 简报口味 | **行动清单**（少而精，只给 Top 3-5 待办），数据细节自己去看板 |
| 2 | LLM 落点 | 放 **ai-agent-service**（Python，与米宝共享推理基建） |
| 3 | MVP 范围 | **只做后台首页**（首页简报卡 + 企业开关 + 定时生成），推送/小程序延后 |

## 二、企业开关（核心机制）

> 用户明确要求：**只有企业开启后，才每日自动生成并显示菜单。** 开关 = 功能的唯一总闸，同时是成本与合规的熔断器。

### 2.1 开关位置与权限

- 位置：`系统设置 → 租户配置`（复用现有 `settings/tenant` 页，admin 独占）
- 字段：`daily_briefing_enabled`（boolean，**默认 false**——新租户默认不开启）
- 权限：仅 `admin` 角色可修改；开关变更写入操作日志（复用 `GET /api/admin/audit-logs`）

### 2.2 开关状态机

```
                开启(admin)
   ┌────────────┐ ──────────► ┌─────────────────┐
   │  关闭状态    │             │   开启状态        │
   │ 菜单: 隐藏   │ ◄────────── │ 菜单: 显示「每日简报」│
   │ 生成: 不调度  │   关闭(admin) │ 生成: 每日定时任务 │
   │ 推送: 不发   │             │ 推送: 按配置      │
   └────────────┘             └─────────────────┘
```

### 2.3 开关语义细节

| 场景 | 行为 |
|------|------|
| 开启瞬间 | 菜单立即显示；**当日立即触发一次生成**（不等次日），让管理员当天就看到效果 |
| 每日生成 | 每日按租户配置时刻（**默认 06:00，Asia/Shanghai，开放租户自定义**）由定时任务扫描**已开启租户**，逐个生成 |
| 关闭瞬间 | 菜单隐藏（**历史简报保留但入口隐藏**，不删数据）；定时任务跳过该租户；待推送任务取消 |
| 再开启 | 立即生成当日简报，历史简报入口恢复可见 |
| 关闭期间 | LLM 调用次数为 0（硬性熔断：调度层按开关过滤，生成入口双重校验开关状态） |

### 2.4 配置项（MVP 内，租户级）

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `daily_briefing_enabled` | false | 总开关 |
| `briefing_generate_time` | 06:00 | 每日生成时刻，**租户可自定义**（MVP 开放；调度按各租户时刻扫描） |
| `briefing_push_enabled` | false | 推送开关（MVP 不实现，字段预留） |

> MVP 只做后台首页，故推送配置仅预留字段，不做 UI 与逻辑。

## 三、用户与场景（复用 RBAC，按角色裁剪内容）

| 角色 | 简报可见内容 | 数据源 |
|------|-------------|--------|
| 企业管理员 | 全貌 + 财务 + 员工 + 风险 | 混合 Dashboard 全部 |
| 运营经理 | 经营指标 + AI 配置健康度 + 客服质量 | 业务看板 + AI 配置 + 服务质量 |
| 客服主管 | 客服绩效 + 待处理工单 + 会话风险 | 客服看板 + 售后工单 |
| 商品管理员 | 库存预警 + 商品异常 + 订单 | 商品管理 + 订单 |

菜单显隐 = **企业开关 ∧ 角色权限**（双条件，开关关闭时任何角色都看不到）。

场景：早上开工第一屏（web 首页）。移动端与推送为后续版本。

## 四、简报内容构成

一份简报 = 四个区块，按角色过滤，**行动清单优先**：

1. **昨日回顾（1 句话 + 3-5 个关键数）**：订单/营收/AI 会话量/解决率 vs 前日环比
2. **今日必办 TOP N（核心价值）**：从所有待办中选出最该先处理的 3-5 件，每条带：
   - 优先级（紧急/高/中）+ **理由**（为什么是它）
   - **证据数字**（如"3 个工单已超时 2 小时"）
   - **一键直达**（跳转对应工单/订单/客户页面）
3. **风险预警**：工单超时、负面情绪会话集中、AI 解决率骤降、库存告急、退款率异常抬头
4. **优化建议**：AI 无法回答 TOP3 → 建议补知识库；转人工率异常 → 检查快捷回复/话术

> 数据侧严格遵循「**行动清单口味**」：数量少而精，只给决策；数据细节留在看板，简报只给结论与理由。

## 五、智能分层管道（确定性 + LLM + 校验）

```
① 确定性计算层（admin-api / 规则）     ② LLM 组织层（ai-agent-service）
SQL 聚合全部指标与异常            ←喂→   结构化输入（只含数字+事实，无原始会话/无PII）
异常检测用规则兜底（阈值、环比）          LLM 生成：标题/摘要/TopN/理由/建议
                                       输出 JSON Schema，逐条附数字来源
③ 校验层（防幻觉，必做）           ④ 渲染/分发层
数字回填校验：LLM 输出的每个数      后台首页简报卡（MVP）
与 SQL 结果比对，不一致即丢弃       后续：推送 + 小程序
```

**红线：LLM 只负责组织/归因/措辞/排优先级，绝不允许产生任何数字。**

## 七、技术落地方案（对齐现有架构）

| 层 | 落点 | 说明 |
|----|------|------|
| 生成引擎 | **ai-agent-service** | 新增定时任务 + LangGraph workflow（collect→detect→generate→verify），输出结构化 JSON |

| 前端 | admin-web 首页 | AIInsightPanel 演进为 BriefingCard；菜单按开关+角色渲染 |

## 八、数据安全设计（重点章节）

> 用户明确要求：**最重要的是确保数据安全。** 本节为硬性约束，实现时必须逐条满足并通过安全验收。

### 8.1 安全原则（四条红线）

1. **数据最小化**：进 LLM 的只有聚合指标与事实条目，**绝不传原始会话、绝不传客户 PII**
2. **租户隔离**：所有数据带 `tenant_id`，RLS 强制隔离；LLM 输出只归属当前租户
3. **开关即熔断**：企业开关关闭 = LLM 调用、生成、推送全部归零
4. **校验兜底**：LLM 输出数字与 SQL 对账，不一致丢弃；LLM 失败绝不 fallback 假数据

### 8.2 数据流与脱敏（进 LLM 之前）

```
DB(RLS) ─► 聚合SQL ─► 指标快照 ─┬─► 脱敏层 ─► LLM ─► 校验层 ─► daily_briefing表 ─► 前端
                                └─ 规则异常检测（不进LLM，直接落快照）
```

| 数据类型 | 能否进 LLM | 处理 |
|---------|-----------|------|
| 聚合数字（订单量/营收/解决率/环比） | ✅ | 直接可用 |
| 工单/订单编号（内部标识） | ✅ | 保留（非 PII） |
| 商品名 / 分类名 / 加工项名 | ✅ | 业务词，非 PII，可保留 |
| 客户昵称 | ⚠️ 仅按权限 | 简报展示层默认脱敏为「客户A/B」；**可点击查看真名**（复用客户详情页 RBAC，无权限角色点击无效/不可见） |
| 客户手机号 / 地址 / 身份证 / openid | ❌ **禁止** | 任何环节不得进入 prompt 与简报展示 |
| 完整会话原文 | ❌ **禁止** | 只允许聚合统计（如"负向情绪会话 5 条"） |
| 员工姓名/绩效 | ⚠️ 仅主管+ | 按 RBAC 数据权限过滤后才可入 prompt |

**实现约束**：prompt 输入用白名单 Schema（只允许预定义字段，禁止自由文本拼接）；脱敏层位于 admin-api 聚合之后、ai-agent-service 调用之前，脱敏逻辑有单测覆盖。

### 8.3 租户隔离

- `daily_briefing` 表含 `tenant_id`，PostgreSQL RLS 强制隔离（沿用全库规范）
- API 的 `tenant_id` 一律从 JWT Claims 提取，客户端禁止传参（沿用现有规范）
- LLM 调用上下文携带租户标识，输出仅回写当前租户
- 简报历史按租户隔离，开关再开启后只恢复本租户数据

### 8.4 开关即熔断（成本 + 合规双保险）

- 调度层：定时任务只扫描 `daily_briefing_enabled=true` 的租户
- 生成入口：二次校验开关状态，关闭租户直接返回（防调度遗漏）
- 关闭期间 LLM 调用次数 = 0，**计费与数据出境同时归零**
- 开关变更记操作日志（谁、何时、开/关）

### 8.5 权限与审计

| 项 | 设计 |
|----|------|
| 菜单显隐 | 企业开关 ∧ 角色权限（双条件） |
| 简报内容 | 按角色数据权限裁剪；`support_agent` 只看客服指标摘要（沿用现有「仅本人会话」数据范围） |
| 脱敏别名查看真名 | 复用客户详情页 RBAC（`customers:view`），无权限角色看到别名但点击不可见真名 |
| 审计 | 开关变更（audit-logs）+ 生成记录（briefing 表本身含生成时间/校验状态）+ 推送记录（后续版本） |
| 直达跳转 | 复用页面既有 RBAC，不因简报绕过权限 |

### 8.6 合规（GB/T 47746-2026）

- 简报属 AI 生成内容，按 [gb47746-2026-compliance](../wiki/gb47746-2026-compliance.md) 要求标注「AI 生成」标识
- 生成内容不得超出该角色数据权限（数据范围与 RBAC 一致）
- 涉及客户个人信息的内容一律不出现在简报展示层（只出聚合数）

### 8.7 降级策略（不信任 LLM 是常态）

| 故障 | 行为 |
|------|------|
| LLM 超时/失败 | 简报显示「今日生成失败」，**不展示假数据、不展示昨日数据冒充今日** |
| 校验不一致条目 | 丢弃该条目，保留其余通过项；校验通过率为 0 时整份显示失败 |
| 聚合 SQL 失败 | 不触发 LLM，记录告警 |
| 无数据租户 | 引导式空态：「昨日无会话，可先完善知识库 → 点击直达」 |

### 8.8 安全验收清单（实现后逐条勾选）

- [ ] 全链路无客户 PII 进入 prompt（脱敏单测覆盖）
- [ ] `daily_briefing` RLS 策略 fail-closed 兜底生效（应用层 TenantLineInnerInterceptor 注入 tenant_id 为主，RLS 策略为纵深防御；非 super_admin 连接无法跨租户读到简报数据）
- [ ] 开关关闭后：调度跳过 + 生成入口拦截 + 菜单隐藏（三处都验证）
- [ ] LLM 失败不展示假数据（故障注入测试）
- [ ] 非 admin 修改开关被拒（权限测试）
- [ ] 简报内容不超出角色数据权限（support_agent 用例）

## 九、评测与验收（对齐 MIGAO 验收文化）

LLM 功能质量评测是立项的一部分，不是上线后的事：

- **事实一致性**（硬指标）：简报每个数字 vs SQL 结果，抽样 100% 一致才发布（校验层直接挡住）
- **覆盖率**：注入已知异常（超时工单/退款率飙升/缺货）→ 断言简报必含对应预警，可写成 `.github/cases/` 可执行用例（order_before / forbidden_text / db_verify）
- **优先级合理性**：固定输入集 + 双 AI 交叉打分（按 `migao-acceptance` 协议）
- **可执行性**：每条必办事项直达链接能打开且归属正确
- **防幻觉回归**：历史简报重放，旧会话验证不退化

## 十、风险与边界

| 风险 | 对策 |
|------|------|
| 假数字 | 分层 + 数字回填校验（红线） |
| 打扰焦虑 | 推送频率可配、可静默（后续版本）；MVP 无推送 |
| 数据泄露 | 8.2 脱敏红线 + RLS + 开关熔断（本节最高优先级） |
| 低活跃租户 | 引导式空态 |
| 信任建立 | 每条结论可展开证据链 |

## 十一、里程碑

- **M1（2 周）**：指标聚合 + 规则异常检测 + `daily_briefing` 表 + 企业开关 + 生成时刻自定义（纯确定性，先有数据底座与熔断）
- **M2（2 周）**：LLM 生成 + 脱敏层 + 校验层 + 后台首页简报卡（MVP 可用）
- **M3（后续）**：追问下钻 → 推送/小程序 → 周报/行动闭环
