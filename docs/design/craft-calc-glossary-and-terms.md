## 0. 一句话结论

```
「算料配置」页加一层**口径与术语说明**（同 tab 折叠区块 + 参数旁锚点），
但说明**不是新写一段散文** —— 它是**真值的投影**：
  参数值 ← 配置读面（页面已加载的草稿）   常量 ← frontend/admin-web/src/lib/craft-auto-features.ts（已有跨源守卫）
  算例   ← detectAutoFeatures() 的真实输出（与下单页同一份文案）
说明里**一个手写数字都没有**；写死的只剩「定义与判据句式」，集中在
frontend/admin-web/src/lib/craft-calc-glossary.ts 并逐条读源守卫。
```

**为什么这不是"加几段文案"**：页面上的既有说明**已经有一处是错的**（`side_margin` 被写成「上下卷边」，
引擎里它是**宽方向左右覆盖余量**），而且同一个错**在三处**各写了一遍（页面 hint / 契约类型注释 /
引擎配置字典那行注释）—— 照现有形态继续加文案，只会加出第二、第三份口径（issue #4940 的形态）。

> 🔴 **2026-09-21 收口（用户裁定，issue #5030）**：`side_margin` 这个键**整体退场** ——
> 订单宽高 = **窗户宽高**（净窗宽 / 净窗高）⇒ 成品宽 = 净窗宽 ⇒ **宽方向没有余量**。
> ⇒ #4940 的「页面文案与引擎口径相反」不再是靠改文案收口，而是**该键连同概念一起删除**
> （引擎常量 / 配置键 / DB 列 / 页面 / 契约类型六处同删，见 `docs/wiki/CONTRACT-LEDGER.md` 的算料配置键行）。

## 3. 设计主张（三条）

1. **说明 = 真值的投影，不是第二份口径**。能取真值就取，写死的只有「定义与判据句式」。
2. **参数说明与术语说明分开写**。参数回答「我这家的口径是多少」；术语回答「系统怎么判、拿哪些参数判」。
   今天的混乱正是两者搅在一起（`side_margin` 的 hint 写的是**另一个量**；该键已按 issue #5030 退场，
   现存的参数说明只剩 `hem_margin` 这类**单一语义**的键）。
3. **术语按「谁产生 / 影响什么」分组**（用户最需要的认知支架）：

| 组 | 成员 | 谁产生 | 影响什么 |
|---|---|---|---|
| 自动推算 | 超高 / 超宽 / 倒幅 | 系统按**尺寸 vs 门幅**或**加工类型**推导 | **加工费组合键**（超宽另经**分幅**改米数；超高会触发几何回落 ⇒ 也改米数） |
| 手选 | 拼接 / 接高 | 商家或顾客勾选，**系统不推算** | 加工费组合键 + 工序（**当前**加工项特征不触发工序，见 #4569） |
| 近义词族 | 正幅 / 定型 / 拼色 / 拼N次 / 对缝 | 各不相同（款式 / 选项 / 加工项 / 余量口径） | 各自影响不同，**不在同一层** |

## 5. 内容规格

### 5.1 参数文案（单一真值 = `frontend/admin-web/src/lib/craft-calc-glossary.ts` 的 `CALC_PARAM_COPY`）

- 覆盖**引擎全部配置键**（不止六个标量键：`tiers` / `default_formula` / `per_fold_mixed_times` 也要有说明）；
- 页面**不再持有**第二份文案：`CALC_SCALAR_FIELDS` 由 `CALC_SCALAR_KEYS.map(...)` 派生；
- 文案里**不得出现数字**（数值由真值渲染）。

### 5.2 术语文案（`AUTO_FEATURE_TERMS` / `MANUAL_FEATURE_TERMS` / `TERM_FAMILY`）

每条给：**是什么** / **系统怎么判**（符号式）/ **影响什么** / **边界与前提**（照实登记）。

必须写进边界的四条：

1. 超高/超宽的判据是**行业推理、非 ERP 实证** ⇒ 系统标注「推算」；
2. **门幅取自该商品**（没有缺省门幅：商品没录门幅 ⇒ 系统不判，不拿一个假门幅去判价）—— issue #4877；
3. 缺褶倍 ⇒ 不判超宽，但下单页显式说明「这里本该判」（不静默）；
4. 「双眼皮接高」含义**待查明**（客户亦不明）⇒ **不凭字面推**。

### 5.3 算例（**不自己拼文案**）

`buildAutoFeatureExamples(config)` 逐条调 `detectAutoFeatures`，取它给出的 `reason`（与下单页
「为什么判它超宽」是同一份实现）。举例的几何与门幅是**示例输入**（模块里显式标注：门幅**随商品而变**，
不是缺省门幅），算例里的米数由真函数算出。

## 8. 照实登记（边界与未做，不粉饰）

1. **引擎试算门幅 ≠ SKU 门幅**（分叉 #4652）：说明里只声明「本页/判定按该商品门幅」，
   **不声称**引擎实际按哪个门幅算。
2. **商家改参数只影响 web 路径**：agent 仍用默认值（`docs/design/craft-calc-and-fabric-routing.md` §7.3 已登记的偏差）——
   说明区块**未**声称「米宝也按这份配置算」。
3. **拼接/接高的「不触发工序」是当下口径**（#4569 未裁定）；本单只把它**说出来**，不改行为。
4. **`hem_margin` 目前不可配**（#4976 落地前）：说明区块讲的是**概念**（上下卷边），
   参数当前值表由配置键派生 ⇒ #4976 加键后会自动多一行，且判据 1 会先红逼着补文案。
5. **真实 LLM 评测未跑**：本改动纯 web 文案与展示、不碰 agent 行为（`migao-dev-flow` §13.2 映射表零 LLM 影响）；
   按 #4262 用户裁定不自动派发。
6. **未改任何算料数值**：包 1 只改文案与注释（回归不变量）；`verify-all.sh` 的既有算料测试逐值未动。
