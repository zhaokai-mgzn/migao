## 0. 一句话结论

**ERP 的「加工项」= 组合价目（特征集合 → 元/米），不是「单价 × 数量求和」。**
因此本方案把计价切成两层账：

```
对客加工费(每订单行) = 组合价(元/米) × 加工费米数
                     + Σ 选中特殊选项( 单价(元/套) × 套数 )       套数 = 1（1 套 = 1 订单行）
订单总价             = Σ 用料行金额(面料 / 配布边 / 纱帘) + Σ 加工费
```

## 4. 冻结契约（三个并行包的接口）

### 4.1 `production_route_rules.customer_unit_price`（V77 新增列）

| 项 | 值 |
|---|---|
| 列名 | `customer_unit_price NUMERIC(12,2)` |
| 语义 | 该**特殊选项**（`trigger_kind='option'` 行）对**顾客**的**元/套**单价 |
| `NULL` | **未定价**（≠ 0）⇒ 取价侧必须显式可见，**不得静默按 0 收** |
| 账别 | **对客售价账（L3②）**；计件路径（`ProductionService` / `piecework`）**绝不读本列** |
| 为什么带 `customer_` 前缀 | 让「两套账不互读」在 **grep 层可判**（表内同时存在车间路由语义与对客价语义） |
| 非 `option` 行 | 一律 `NULL`（工艺变体不按套收费） |
| D5 | `routing.py::ROUTE_RULES` **不改**（agent 豁免）⇒ 三源收敛守卫对**本列显式豁免登记** |

### 4.2 取价公式（`ProcessingFeeCalculator` 唯一实现）

```
fee(行) = comboUnitPrice(元/米) × processingMeters        // 既有 #4406 口径，不变
        + Σ_{opt ∈ 选中特殊选项} customerUnitPrice(opt) × 1  // 新增（R5 + R8）
```

- `processingMeters` 键族不变（`processingMeters` / `fabric_meters`）；缺米数 ⇒ `unpriced`（不猜）。
- 组合未命中 ⇒ 整体 `fee_source='unpriced'`、金额 = 0、**不回落** Σ 加工项（既有纪律）。
- 组合命中 ∧ 某选项未定价 ⇒ `fee_source` 仍 `matched`（组合那半有效），
  **该选项在 `special_options[]` 里 `priced:false` + 计 0**，并给**可行动 hint**（指向定价入口）。
  ⇒ 「未定价」有两层，**都必须在 detail 里可判**，不许静默。

### 4.3 `processingFeeDetail` 契约（web 消费，**新增键只加不改**）

```jsonc
{
  // ── 既有键（#4406/#4444，语义与键名一律不动）──
  "composition_key": "定型+打孔",
  "items": ["定型", "打孔"],
  "unit_price": 8.00,
  "price_source": "configured",
  "meters": 13.3,
  "meters_source": "processingMeters",
  "fee_source": "matched",          // matched | unpriced | manual（枚举不变）
  "amount": 106.40,                 // = 组合那半（元）
  "hint": null,

  // ── 新增（R5）──
  "special_options": [              // 逐项可审计；空数组 = 没选
    { "name": "加铅块", "unit_price": 6.00, "sets": 1, "amount": 6.00, "priced": true }
  ],
  "special_options_total": 6.00     // = Σ amount
}
```

- **行金额 `processingFee` = `amount` + `special_options_total`**（唯一进订单金额的数）。
- `special_options[]` 的顺序 = **选项名 Unicode 码点升序**（确定性；与 `compositionKey` 同族纪律，
  否则同一张单两次生成得到不同明细）。
- 未定价选项：`unit_price: null`、`priced: false`、`amount: 0`。

## 5. 术语与自动识别（D6）

### 5.1 倒幅 / 正幅（用户已确认，落成**推导**）

| 术语 | 含义 | 推导 |
|---|---|---|
| **正幅** | 定高买宽：布门幅 = 帘**高**方向，花型**正着**用 | `cuttingMode == 定高买宽` |
| **倒幅** | 定宽买高：布旋转 90°，门幅变成**宽**度方向，花型**倒了** | `cuttingMode == 定宽买高` |

⇒ **由 `cuttingMode` 唯一推导，不设手选项**（设手选项 = 制造与 `cuttingMode` 冲突的第二份口径）。

### 5.2 超高 / 超宽（**与门幅比较，自动识别**）

**推理证据链**（都来自 §1 读准的行）：

1. **定价对称**：`韩折+超高` 9.00 = `韩折+超宽` 9.00；`韩折+超高+定型` 10.00 = `韩折+超宽+定型` 10.00
   ⇒ 同一类加价的**两个维度**；
2. `韩折+超高+**接高**+定型` **同时存在** ⇒ **超高 ≠ 需要接高**（否则「接高」冗余）
   ⇒ 超高是**尺寸超限的加价维度**，「接高」是**具体工序**；
3. `韩折+**超宽+超高**+定型` **同时存在** ⇒ 二者**不互斥**（不是「定高买宽 / 定宽买高」二选一）。

**自动识别规则（冻结）**：

```
门幅 G   = SKU.doorWidth（缺省 2.8 米；窄幅布 1.4）
卷边常量 = 0.3 米（**复用** curtain_calc 既有常量，不新造第二个数）

超高 = (成品高 + 0.3) > G
超宽 = (成品宽 + 0.3) > G
```

- 两者**独立**，可同时为真（ERP `韩折+超宽+超高+定型` 佐证）；
- 阈值 `G` 与 `0.3` 按真值源 §2【默】「经验默认值，需商家可配置」处理：**给默认值 + 商家可配**；
- ⚠️ **照实登记**：本条是**推理，非实证**（未从 ERP 供应商处取得判据）。
  按 #4261 的做法标注 `source='推算'` + 可配，**不假装定论**。

### 5.3 特征集合的构成（进组合键的输入）

```
特征集合 = 手选特征（来自 L2 加工项目录）
         ∪ 自动特征（超高 / 超宽 / 倒幅，按 §5.1~5.2 推导）
         ∪ 工艺特征（韩褶 / 打孔 / 四爪钩 / 穿杆 / 平幔，来自工艺规格 `craft`）
         ∪ 定型（来自 `isShaped`）
⇒ composition_key = 归一化(特征集合)   // TreeSet 升序 + '+' 连接（**复用既有唯一实现**）
```

## 6. 加工项 ∩ 特殊选项 的边界（R11）

**不做分类重构**，只落一条**配置护栏**：

- 写面校验：组合价目的特征名 ∩ 特殊选项名 = **∅**；撞 ⇒ HTTP 422 + `error.details` 逐条理由；
- 一条红证：构造重叠 ⇒ 必须被拒（不会红的断言 = 空断言）；
- **如实登记的边界**：ERP 组合名有 `花边/扣环/接高/拼接/双眼皮`，19 项特殊选项有
  `加花边/扣环/接高/双眼皮接高/拼N次` —— **名字不同、概念相邻**。按用户口径实际业务只配一侧；
  本方案**不静默假设**，把该相邻性写进本文档边界 + 缺口报表可见。
