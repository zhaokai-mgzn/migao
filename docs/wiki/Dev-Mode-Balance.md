# 研发模式的三维平衡：墙钟 · 质量 · token

> 目的：把「本机怎么用、CI 怎么用、会话怎么编排」钉成一套**可判据化**的口径，
> 而不是靠每个会话临场凭感觉。
> 本页是**设计蓝本 + 实测基线**，行为规则的可执行载体仍是 `migao-dev-flow` 技能与三把工具。
> 建立于 2026-10-02（issue #6012 / #6015 / #6020 的当日读数之上）。

---

## 1. 目标函数与红线

三个目标**不是同一个旋钮**，各自有独立的杠杆：

| 维度 | 主要杠杆 | 今天的实例 |
|---|---|---|
| **墙钟（提效）** | **份数**（几份全量）+ **归属面**（谁该跑哪些判据） | 批次一次全量（#6012）；CI 面分离（#6015） |
| **质量** | **判据强度**（实例判据 + 类级元守卫 + 注入式红证）+ **独立验收** | 同源承诺必须被判据承担（#5007①，今天 CI 真抓到） |
| **token 成本** | **往返数**（每次工具调用 = 一轮，与命令快慢无关）+ **上下文卫生** | 批量读/批量改/不轮询（`migao-dev-flow` §21） |

**六条红线（永不为了任何一维砍掉）**：

1. 判据强度只许升（门禁只简化实现，不简化断言）；
2. 「**没跑**」必须长得像「没跑」（三态 `0/1/3`、打印未跑条数、不许静默绿）；
3. 安全护栏与既有架构契约永不砍（`docs/wiki/Code-Minimalism.md`）；
4. **唯一性资源独占**（端口 / 共享云 dev 资源 / 加载点 / 发布腿）；
5. 结论必须**可复算**（现取读数 + 可复制命令），不许拿挂钟时长当成本判据；
6. **真值取 `origin/main`**（`git show origin/main:<path>`），不读工作树 —— 2026-10-02 我本人在这里踩过一次（预设搬迁时 rsync 取了主工作区工作树，搬过去的是 1.100.0 而真值是 1.102.0）。

## 2. 三个执行域

```
会话（模型侧）   推理 / 编辑 / 编排      多会话并行（几乎不吃本机 CPU）
   │
本机（M1 8核 16GB）  决策机：定点判据 + 一批一次全量
   │                分档槽位：1 重活 + 1 服务 + 1 JVM + 3 定点 + ∞ 网络 + 1 运维独占
   │
CI（GitHub）     验证农场：每 PR 并行、按面无变更即跳过、合并后 main 侧兜底
```

原则一句话：**贵的地方（token）只放决策；慢的地方（全量）放并行免费处；唯一的东西独占。**

|---|---|---|---|---|---|

## 5. token 成本专项（最容易被忽视的一维）

**计费单位是往返**：每次工具调用 = 一轮模型往返（实测 ~8s/步，**与命令快慢无关**）。
实证（#4419）：墙钟 46.3 min / 279 步，而前台工具执行合计只有 8.1 min、单个最慢命令 16.6 s
⇒ **token 花在「轮次」上，不花在「命令耗时」上**。同理，#4455 实测 7 次 `sleep` 轮询 = 684 s = 11.4 min = 7 轮。

**十条纪律**（前六条可机械自检）：

1. **读要成批** —— 一条 bash 里 `grep`/`sed`/`ls` 组合把要改的文件一次看完；禁止 `read→edit→read→edit`。
2. **改要成批** —— 同一文件多处改动放同一步；>3 处或整体重写用一次 `write`。
3. **查要合并** —— 多条独立查询合成一条命令。
4. **输出先过滤再进上下文** —— `--jq` / `tail -n` / `grep -E`；**严禁**把 CI 全量日志倒进上下文（今天有一次 `gh run view --log-failed` 全量即为反例）。
5. **验证不来回** —— 先窄跑定位，再一次全量。
6. **等待不轮询** —— 用后台 job / `gh pr checks --watch` 一次阻塞，禁止 `sleep N` 轮询。
7. **探索性阅读外包** —— 宽面阅读交给 subagent（它的上下文不占主会话）。
8. **把已核实事实落 durable 载体**（台账 / CHANGELOG / PR body / issue），别每会话重推。
9. **子任务提示词自带验收口径**（判据文件 + 不许跑什么），减少澄清往返。
10. **预算闸门**：单包超过阈值步数仍无绿 ⇒ 停下来回报（当日最长会话 713 步 / 10.2 h 即是反面教材）。

## 6. 质量与成本的反向张力（照实登记）

**判据本身也会长成债**：`tests/unit_ci_workflows` 现取 **358 个文件 / 6160 条 / 7m35s**。
它是质量的载体，但每一条都在**每个相关 PR 上**收一遍钱。所以：

- 判据要**按射程归属**（谁约束谁跑）：这是 #6015 的口径；
- 判据要**可判定**：三态里 `3`（不可判定）必须非零，不许被读成通过；
- 判据要**有承担者**：注释里的承诺（同源 / 一致 / 必须）必须登记 `criterion` 或 `unfixed`；
- 判据要**能红**：不会红的断言 = 空断言（红证必须真跑出红）。

## 9. 边界与未固化项（照实登记）

- 「分档容量」是**策略常量**，不是物理上限：M1/8 核/16 GB 上真正装得下几份**全量**至今**没有内存读数**（本轮裁定：不需要它也能设计，靠安全阀自适应）；
- 批次大小与归因分辨率的权衡（`≤4-6 包`）是**经验建议**，未固化判据；
- 「溢出到 CI」的代价（多一次推送往返）没有被量化进台账；
- 本页**不是**行为规则的可执行载体：规则在 `migao-dev-flow`（预设仓）与三把工具里，本页只提供基线与设计意图；
- 判据的**存量瘦身**（哪些判据可以合并/下沉为确定性检查）尚未开工，只登记了方向；
- 「批次**会话**」按 worktree 去重是**本页口径、尚未落码**（`stats` 报的 `batch_integration=` 仍是**行数**），见 §10.3；
- 锁台账（#6097）**起点 = 2026-10-03 07:49 +08**（该包落地后才有记录）⇒ 更早的批次**不计入**任何读数。

## 10.1 子包禁全量 **已机制化**（2026-10-03，issue #6084）

§10 里「子包禁全量机制化」那一格的**承接包**，本页只记**结论与读数口径**（机制正文在
`docs/wiki/Development.md` 的「子包 worktree **不许**直跑全量」节，可执行载体在 `verify-all.sh`）。

**入口判别表（四态，各自「会不会持锁 + 跑整目录」）**：

| 角色 | 判定依据（现取的事实） | 处置 | 持锁 + 跑整目录？ |
|---|---|---|---|
| 主检出（primary worktree） | `--absolute-git-dir` == `--git-common-dir` | 允许 | **会**（人工 / 批次的一次性全量在这里跑） |
| 批次集成 worktree | 上述不等 + `--git-path` 处**有标记** | 允许 | **会**（`batch-gate.sh` 留的标记） |
| 子包 worktree | 上述不等 + **没有**标记 | **拒绝**（`exit 5`） | **不会**（拒绝先于 `macquire` 与档位分发） |
| CI（`CI` 为真） | 环境标记 | 不受影响 | **会**（托管 runner 不占本机资源） |

**这一格的读数 = 角色判定台账**（报的是「角色被拒 / 被放行」的次数，**不是**批次的次数）：

```bash
./scripts/package-heavy-entry-ledger.sh count     # refused=<n> / override=<n>（两类分开）
```

- 路径 `tests/unit_ci_workflows/package_heavy_entry_ledger.jsonl`（**只追加**；首行 = schema 头）；
- 现取 **4 条**（`refused=3` / `override=1`），**全部** `at` 指向守卫自己的开发 worktree
  （`ci-package-heavy-entry-ban`）⇒ 它们是**本机制的自测记录**，**不构成「批次次数」**（见 §10.3）；
- **幂等**：键 = `MIGAO_ROLE_LEDGER_ID`（同一次调用不重复计数 —— 判据
  `test_package_heavy_entry_ban.py` 有「同 id 记两笔 ⇒ 账上只一笔」的可判读数）；
- **分两类报**：`refused`（机制拦下的浪费）vs `override`（人类显式 `--allow-package-heavy` 放行）
  —— 混成一类就两个都读不出来；
- **不许静默**：拒绝必记账（台账写不进去时打 `::warning::`，但**不改判定** —— 记账失败不得把
  拒绝变成放行）。

## 10.2 两条 CI 机制事实（2026-10-02 体检实测，别踩）

1. **GitHub 对「被 job 级 `if` 跳过」的 job 不上报该 context** ⇒ required 的腿**永远不能**加 job 级面门控：
   非相关 PR 会**永久 BLOCKED 且没有任何红信号**（#5101 / #4786 同族）。required 只能靠**步骤级** gating。
2. **依赖被门控 job 的下游 job 会被一并跳过**（实测：`label-needs-changes` / `clear-needs-changes` 原 `needs` 含
   `e2e-quality-gate` ⇒ 该腿一被 job 级跳过，这两条也跳过 ⇒ 僵尸标签 `review/needs-changes` **永不脱落且无红信号**）⇒ 下游收口必须补 `always()`。
   推论：**非 required 腿被 job 级跳过之后，在本 PR 页面上根本不出现** —— 「不出现」既不等于「跑过」，也不等于「跳过」，
   所以「未跑」只能由 **detect job 主动播报**（这正是本页第 4 节那条「没跑必须长得像没跑」的落地形态）。

## 10.3 「批次粒度」重启条件：**读数口径钉死**（2026-10-03，issue #6047）

§10 那条 ⏸ 的重启条件**原文是「批次台账 ≥5 次记录」**，而「记录」在本仓有**两个互不相同**的读数出处
—— 现取分别是 **4** 与 **14**，且**两者都不等于「批次的次数」**：
