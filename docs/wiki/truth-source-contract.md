## 0. 为什么需要一份"契约"而不是又一条纪律

`migao-dev-flow` §18.8 的反模式清单已经把「靠自觉」列全了。本文要解决的是**它后面那半步**：
**把自觉换成可判定的东西**。判据的设计准则只有一条 ——

> **每条护栏都必须带一个"能红的夹具"，且它的红必须指向正确的行动。**
> 永远不红的判据是**空断言**；永远红或永远被基线豁免的判据是**装饰**；报错指向错误方向的判据
> 会挡住无关的 PR（`migao-acceptance`「断言形态：四种写法，两种『修好即红』」）。

## 1. 四条不变量（判定方式 + 违反后的处置）

每条给出：**含义 / 判定方式（机器可判的谓词）/ 违反后的处置 / 落码位置**。
`drift_audit.py` 的判据 ID 与本文一一对应（`--list-checks` 可机器读出全部判据及其判定方式与处置）。

### I1 版本可引

**含义**：任何被读的"真相"（源码 / 技能 / case 真值 / 种子 / 账本 / 部署环境）都有**版本标识**；
**任何结论必须携带它读的版本**。机制 = SSOT + 派生视图重生成 + **fencing**：
结论绑定 `(sha, cases_fingerprint, policy_version, 环境指纹)`，**版本一动则结论失效**。

| # | 判定方式 | 违反后的处置 | 落码 |
|---|---|---|---|
| I1-a | 逐技能比 `origin/main` 与工作树的 `.agent-presets/migao/skills/*/SKILL.md` 的 `version:`：**下降 ⇒ 红**；**同版本但内容不同 ⇒ 红**（那是分叉）；上升/相同且内容一致 ⇒ 绿 | `git fetch origin main && git rebase origin/main` 后再提交；**不要** `git add -A`（worktree 的 `.agent-presets/` 是创建时的快照，会把旧预设带上去） | `preset-monotonic` |
| I1-b | 生成物 `eval_cases.py` / `mibao-verification-cases.md` 重跑 `.github/render_cases.py` 后**逐字节相等**；且用例库里的 `pre_clean` 字段在渲染结果里**存在** | 以 `.github/cases/` 为唯一源重渲染并提交生成物；**不要手改生成物** | `generated-freshness` |
| I1-c | 受管引用面上每个 `path:NNN`：① 路径能解析（否则**悬空**）；② 行号 ≤ 目标文件在 `base` 上的行数（否则**越界**）；③ 带 `@<sha>` 限定（否则**裸行号**）；带文件名的裸 `第 N 行` 同理 | 改成**符号/文本锚点**（首选）或 `第 N 行` + `@<sha>`（限定值）；越界引用删掉行号只留符号。见 dev-flow §18.1 / §16.7 | `ref-freshness` |
| I1-d | 派生文档**自称**是某权威源的副本时，它声明的版本必须等于权威源当前 `version:`；声明的权威源路径必须存在；副本不得有权威源没有的章节 | 见 §4「同步副本」——**兑现或撤回**，二选一 | `sync-copy` |
| I1-e | 报告的 `(base, cases_fingerprint, policy_version)` 三元组随每次审计落盘（JSON 报告头部） | 运行期护栏把它写进 `run_key`（见 §3.2） | `drift_audit.py` 报告头 |

### I2 身份不可变

**含义**：被测对象用**不可变标识**（`order_no` / `phone` / `id` / **用例自建唯一名**）；
**名字 / 序号 / 位置只允许出现在「用户输入」里**，**不得**用于定位被测对象
（定位 = `pre_clean` / `db_verify` / `precondition` / `post_session` / `output_verify` / `amount_verify` /
`namespaces` / 回合指令里的结构化选择器）。

**判定方式**：统计上述定位位置里用可变键（`*keyword` / `*name` / `*_index` / `tag_name` /
`auto_select` / 序数值）定位对象的**条数**，输出**分量与总量**并与基线比较。

⚠️ **口径（不写清就会大面积误伤）**：名字 / 序号出现在 `user_inputs` 的**字符串项**里是**合理**的
—— 那是被测行为的一部分（用户就是会说「第一个」「遮光窗帘」）。判据**只**把
**(a) 结构化定位键**（`product_keyword` / `customer_index` / `auto_select: true` …）与
**(b) `user_inputs` 里的 dict 项**（结构化回合指令）计入。

**违反后的处置**：改用不可变标识 —— 绑定 `order_no` / `phone` / `id`，或用例自建唯一名（带 run 指纹
或时间戳后缀）。实证：`CU-003` 的 `customer_index: 0` 在 `created_at DESC` 下**点中别人中途造的那个客户**
（重名 upsert，`#3832`）；`db_verify[product_by_name]` **只按 keyword 取首条**会被同名种子商品顶替
（`PR-019`）；`auto_select` 在无卡时退化成发**字面量**「第一个」（`#2991` / `#3568`）。

**落码**：`mutable-locator`（本审计，输出分量与总量 + 基线 burn-down）。
**口径分工**：**逐条用例**的判定属 `.github/case_trust_gate.py` 的 E 规则（issue **#3846**）；
本审计只做**面级清点与 burn-down**。两者必须一致 —— **若两处读数不一致，以能给出更窄口径者为准并修另一处**
（这是本契约自己的"多处口径"禁令）。

### I3 世界自建

**含义**：用例自带 setup + teardown 或**显式复位**，不依赖"别人留下的世界"；并发靠**显式资源声明**
（namespace 锁）；辅以**前置自断言** —— 首轮断言**自己的前置**，不成立走 **fail-closed**，
**不得**退化成"agent 表现不好"的红。

| # | 判定方式 | 违反后的处置 | 落码 |
|---|---|---|---|
| I3-a | 用例首轮断言自己的前置（订单数 / 客户数 / 目标对象存在 / 库内无同名残留），前置不成立 = **fail-closed** 并把观测值打进失败信息 | 与 dev-flow §18.4 同款：`前置不成立：customers=2（期望 1）`，**不得**继续跑成"agent 不干活"的红 | **未实装**（运行器侧，见 §6） |
| I3-b | 写用例必须声明 `namespaces`（并发不被他人改世界） | 补 `namespaces` | **只报告不阻塞**（`未实装`，判据面不成立，见 §6） |

### I4 时效可验

**含义**：每个派生视图 / 副本 / 周期性任务都有**机器可判的"是否新鲜 / 是否活着"**判据（心跳）。

| # | 判定方式 | 违反后的处置 | 落码 |
|---|---|---|---|
| I4-a | **活锚**（`~/.dsh/.agent-presets/migao`，软链）逐技能与仓库比 `version:` + **逐字节 sha256**；活锚检出落后 `base` **且落后区间动过 `.agent-presets/migao/**` ⇒ 红**（**内容级**判定，不是提交数 —— 落后 1 个提交但预设未变 ⇒ 规则仍是最新，判红就是噪音红）；活锚 `.agent-presets/` 下**有未提交改动 ⇒ 红**（内容无法用 sha 引证）；活锚**不存在 ⇒ 未知**（不判通过） | 见 §5「活锚拓扑」；对活锚所在检出 `git fetch origin main && git merge --ff-only origin/main`（**不要手抄文件**，手抄就是新一层快照） | `skill-anchor` |
| I4-b | 凡声明 `schedule:` 的 workflow（含**被注释停用**的）：核"最后一次**成功**运行"与 cron 周期推出的阈值；**零成功 / 从未跑过 / 超阈值 / 调度被注释停用 ⇒ 红**；`gh` 不可达 ⇒ **未知**（不假装通过） | 当**缺陷开单**，不得读成"它一直红/它不重要"；修稳定再恢复 `schedule:` | `heartbeat` |

## 2. 三个执行点（缺一层就等于没有）

| 执行点 | 何时 | 判据 | 本包状态 |
|---|---|---|---|
| **写入门禁** | PR 时（`.github/workflows/drift-audit.yml` 的 `audit` job） | I1-a~e、I2、I4-b；引用须对 `origin/main` 命中、不可变引用、生成物重生成 diff、副本版本戳、技能活锚新鲜度 | ✅ 已落码，`--check` fail-closed |
| **运行期护栏** | 评测 / 验证时 | 记录并绑定环境指纹；前置断言 **fail-closed** | ⛔ **不由本包落地**（在 `tests/agent_eval/local_runner.py`，见 §3.2） |
| **持续账本与告警** | 每日（`schedule` job）+ `workflow_dispatch` | 同写入门禁，外加 `--strict-stale --fail-on-unknown`；**"陈旧 / 漂移"本身是可红的告警**，不是沉默 | ✅ 已落码 |

### 3.1 为什么必须三层都有

- 只有写入门禁 ⇒ 运行期漂移（世界在两次读取之间变了）无人管；
- 只有运行期护栏 ⇒ 陈旧引用 / 副本分叉会在主干累积，直到某天集中返工；
- 只有账本与告警 ⇒ 没有阻断点。

### 3.2 运行期应绑定什么（留给运行器那一层的接口）

`drift_audit.py` 已产出并落盘三项，运行器应把它们**原样写进 `run_key`**（本审计只提供口径，不碰 runner）：

```
base                  # git rev-parse origin/main（结论锚定的 SHA）
cases_fingerprint     # .github/cases/*.yml 的有序 sha256（用例集指纹）
policy_version        # 判据口径版本（口径一改即失效）
环境指纹               # 部署环境标识（由运行器负责，本审计不判定）
```

**规则**：四项任一与结论生成时不同 ⇒ 该结论**失效**，不得引用（同族于 dev-flow §16.7
「每个计数必须锚定 SHA」与 §17.4「判定跑在飞期间冻结合并」）。

**前置自断言**（I3-a）：本契约要求"前置不成立 ⇒ fail-closed 并把观测值打进失败信息"。
**本包只写契约与判据，不碰 runner** —— 落地在运行器那一层（issue #3846 的 F 规则）。

## 4. 同步副本：**兑现**或**撤回**（二选一，不许含糊）

**现状（实测，锚定 `origin/main@d0724892`）**：`docs/wiki/DEV-FLOW.md` 第 3 行**自称**
"DSH 技能 `migao-dev-flow`（**权威源：`.agent-presets/migao/skills/migao-dev-flow/SKILL.md`**）的仓库同步副本"，
而实测：

| 项 | 读数 |
|---|---|
| 权威源行数 | **971**（`SKILL.md` 去 frontmatter） |
| 副本行数 | **230** |
| 副本自报版本 | **v1.3（2026-09-04）** |
| 权威源版本 | **1.28.0** |
| 副本含 §17.4 / §18 吗 | **不含** |
| 共有章节归一化后仍不同 | **5 / 8**（§2 / §3 / §4 / §6 / §8） |

⇒ 它**不是**逐字镜像，且**每一次技能改动都在加深分叉**（§18 的"分叉"是持续量）。

**判据（已落码，`sync-copy`）**：版本戳一致性**必须**成立 —— **现状即真实红例**
（页面声明 v1.3 / 权威源 1.28.0）。此外：声明的权威源路径必须存在；副本不得有权威源没有的章节；
共有章节分歧条数与基线比较（**只许缩短**）。

**处置（二选一，落地留给后续小单，见 §6「未实装」）**：

1. **兑现（首选）**：把该页**由权威源生成**（脚本渲染，像 `eval_cases.py` 那样）——
   于是"重生成后 `diff == 0`"成为**合法**判据。
   最最小实现：`scripts/render_dev_flow.py` 取 `SKILL.md` 去 frontmatter + 加 4 行页头
   （权威源路径 / `@<sha>` / 生成命令 / "本页由脚本生成，勿手改"），输出到 `docs/wiki/DEV-FLOW.md`；
   在 `drift_audit.py` 的 `sync-copy` 里加"重生成 diff == 0"一格（与 I1-b 同款）。
2. **撤回**：若坚持人工节选，就**删掉"同步副本"的 claim**，页头改写为
   「**非权威、可能滞后；流程口径以技能为准**（`git show origin/main:.agent-presets/migao/skills/migao-dev-flow/SKILL.md`）」，
   并**保留**版本戳检查（声明版本仍须等于权威源，或干脆不写版本）。

**为什么不由本包落地**：`docs/wiki/DEV-FLOW.md` 正文正被别的包改（本包开工时主工作区里它已是
`M` 状态）⇒ 顺手重写会与在飞改动相撞（dev-flow §17.3「多个 worker 改同一个文件」）。

### 4.1 反面教材：**基于错误的真相模型写出来的护栏 = 空判据**

本契约的**委托 brief 里有一条错判据**（原文）：
> 「同步副本 diff：`docs/wiki/DEV-FLOW.md` ↔ `.agent-presets/**/SKILL.md`（现零校验，可静默分叉）」

字面实现就是"**两者 diff 必须为 0**"。而实测：971 行 vs 230 行、**diff 949 行** ⇒ 这条护栏
**永远不可能绿**，只能被塞进基线豁免 ⇒ **一条"永远红或永远被豁免"的空判据**（`migao-acceptance`
「断言形态」：真值主张 = 自毁式；登记表 = 只有报错指向正确行动才合格）。

**这个错误本身就是 I1/I4 的现场例证**：**连护栏的作者都在读一个陈旧的真相模型**
（把"人工节选"误当成"逐字镜像"）。修正方式与任何 I1 违例一样 —— **实测优先于 brief**：
先量 971 / 230 / v1.3 / 1.28.0，再定判据。
⇒ **本文档与 `drift_audit.py` 里所有数字都带 `@<sha>` 或实测命令**，不写"应该是"。

## 5. 活锚拓扑：**专用检出**是正解，**主工作区**是反模式

**实测（锚定 `origin/main@d0724892`）**：活锚 `~/.dsh/.agent-presets/migao` 是指向
**独立检出** `/Users/guangzhen.zk/ai native/migao-preset-live` 的软链（`readlink -f` 可验）。

| 拓扑 | 形态 | 风险 | 判定 |
|---|---|---|---|
| **专用检出 / 只读镜像**（`#4026` 起为实际形态） | `ln -sfn <专职只读镜像>/.agent-presets/migao ~/.dsh/.agent-presets/migao` | 需手动/时机性 ff，**会漂移但可断言**（`#4026` 已补可执行判据 + 自愈：`./scripts/preset-anchor-check.sh` / `preset-anchor-refresh.sh`） | ✅ **正解** |
| **主工作区**（**原** `AGENTS.md` 教法，`#4026` 已改掉） | `ln -sfn "$PWD/.agent-presets/migao" …` | 主工作区常年**脏 + 落后**（实测 `HEAD=aa64bb98` 落后 `origin/main` **136 个提交**且脏）⇒ 照做 = **活锚指向陈旧树**，且 `AGENTS.md` 那句"合并/拉取后自动生效"**变成"永远按几天前的规则干活"** | ❌ **反模式**（issue **#3849**；已由 **#4026** 在指令层修正） |

**现状（`#4026` 落码后，2026-09-17）**：本机活锚 = `$HOME/migao-preset-anchor`（**独立克隆**、
`checkout --detach origin/main`；不是 worktree、不是主工作区）。`AGENTS.md`「开发环境准备」与
`.agent-presets/migao/README.md`「接线」已按此拓扑改写，并给出「自检（红就停）+ 自愈刷新」两条命令；
`scripts/dev-worktree.sh add/rebase` 会在与主干同步的时机**顺带刷新镜像**（best-effort）。
上面的表保留为**反模式记录**（历史 + 为什么危险）。

**反模式为什么危险**：它**位于指令层**（技能是"改任何代码前必须加载"的东西）⇒ 按会话数放大；
且**"照文档做就会错"**（不是疏忽），越新的人 / 越新的机器越容易踩；且**静默**。

**本包的处置**：I4-a 把"活锚新鲜度"从人工纪律升级为**可 fail-closed 的检查**（落后提交数 +
内容级 sha256 diff + 未提交改动检测），在 `--check` 下**红**。
`AGENTS.md` 正文的改法（含换链前的落后/脏断言命令）写在 issue **#3849** 的评论里，**本包不改它**
（越界）。建议措辞：

```bash
# 换链前必须满足（不满足 → 不许换链，fail-closed）
R=<候选检出>; git -C "$R" fetch origin main
git -C "$R" rev-list --left-right --count HEAD...origin/main   # 输出必须为 "0<TAB>N"
git -C "$R" status --porcelain                                 # 必须为空
```

## 6. 未实装登记（**如实登记，不用恒真判断凑数**）

`drift_audit.py --list-checks` 的 `unimplemented` 字段是**单一源**，本文与之同步：

| id | 不变量 | 为什么没做成机器判据 | 缺什么 |

## 7. 反退化规则（meta）：**护栏自身纳入 L0**

1. **判据集合不得为空**；每条判据必须写清**判定方式**与**违反后的处置**（`regression-guard` 判据本身）；
2. **每条判据的判定面不得为 0**（空集恒真 = 空断言）；
3. **每条护栏必须带"能红的夹具"**，且夹具用**真实历史缺陷**：
   `tests/unit_ci_workflows/test_drift_audit_contract.py` 的 `REDPROOF` 表逐判据给出
   "打到漂移态必红 / 修后绿"的实证；
4. **基线清单不得包含"已不再漂移"的项**（否则红 —— 见 §8），
   且**基线不得成为可无限增长的豁免表**（见 §8）。

**"护栏失效 ⇒ 红"的实现**：`test_drift_audit_contract.py` 遍历 `--list-checks` 的全部判据 ID，
断言每个 ID 都在 `REDPROOF` 里有一个**实测变红**的夹具；新增判据而不补夹具 ⇒ **红**。

## 8. 基线策略（防僵化：**只许缩短**）

所有"当前已存在的漂移"进**显式基线清单** `scripts/drift_audit_baseline.json`。
**判据本体不在本脚本**：陈旧/被删/预算一律调 `.github/case_trust_gate.py` 的
`reconcile_baseline` / `burn_down_verdict`（import 复用，#4045 —— 两处各写一套就必然漂移，
本单的起因正是那句"沿用 case-trust 口径"的注释与实现已分叉）。

**条目 key 设计**：`<文件或分量>|<判据内部标识>` —— **不含行号**。否则改一行就换 key，
"只许缩短"会退化成随机红（这是本契约自己必须躲开的陷阱）。

**三层判定（缺任一层都会留下「永久豁免」）**：

| 层 | 情形 | `--check` 处置 |
|---|---|---|
| ① 逐条（diff 命中） | **新增漂移，且落在本 PR 改动面**（出现新 key / 计数上升，文件型 key 在本 PR 改动的文件里） | ❌ **非零退出（fail-closed）** |
| ① 逐条（diff 命中） | **新增漂移，但在本 PR 改动面之外**（多半来自**并行包刚合并进 main** 的文件） | ⚠️ 打印，**不阻塞本 PR**；`--strict-stale`（定时腿）下 ❌ 红 |
| ② **全量对账**（#4045，**不限 diff 命中**） | **基线条目归零但未删**（记了却不再漂移） | ❌ **阻塞**（豁免一条不存在的漂移 = 未来的假真值） |
| ② **全量对账** | **`origin/main` 记着、现在仍漂移，却被本 PR 删掉** | ❌ **阻塞**（删条目 = 偷偷缩短） |
| ② 报告口径 | **存量漂移**（计数不变） | 🟡 打印但放行 |
| ② 报告口径 | **可销账**（计数下降但仍 > 0） | 🧹 打印 + 提示 `--regen-baseline` |
| ③ **burn-down 预算** | 本 PR **动了判据面**（基线文件本身 / 引入新的存量条目）却**净消减 < `per_pr_min`**（默认 1） | ❌ **阻塞**（生效配置读 `--base` 那一份，本 PR 改不动本次判定） |

**为什么"面外新增"在 PR 门禁上只告警**：把并行包刚合并的漂移算到本 PR 头上 = 报错指向
错误的对象、并挡住无关的 PR（`migao-acceptance`「假红」）。**实证**：本包自己的 CI 第一次跑
（run `34914147884`）就被 `docs/testing/demo-readiness.md` 的 3 处裸行号判红 —— 那是**另一个包
刚合并进 main** 的内容。故 `--check` 只对**本 PR 改动面**的新增漂移 fail-closed；
面外那部分交给**定时腿**（它才是"债务盘点"的地方）。

**为什么"归零未删"从"只告警"改为"一律阻塞"**（#4045 翻转，与 `#4031` 在 case-trust 上的翻转同款）：
旧的退让（"别把修好的人卡在别人的基线文件上"，#3846）代价更大 —— 它正是**永久豁免**的来源：
只要没人再碰那个文件，条目就永远躺着。**实证**：基线里 `…|local_runner.py#3899|bare` 在引用它的
测试改掉（`9b12e1d7`）之后仍在清单里，而 `--check` 全绿（该文件不在任何后续 PR 的 diff 里）。
修法是机械的：`--regen-baseline`（重生成时把已不再漂移的条目一并删掉）。

**`unverifiable`（没跑 ≠ 不漂移）**：判据**本轮没能重算**时（`--offline` 下的 `heartbeat`、
判定面为空的判据），它的旧条目记 `⏭️` 而**不判陈旧** —— 否则"网络不可达"会被读成
"那些漂移都没了"，凭空判红。

**环境相关漂移永不进基线**：活锚落后 / 活锚脏 / 活锚缺技能，一律 `env` 作用域 ⇒
**不可放行、不可豁免**（它是"你本机读的快照比别人旧"的现场证据；一旦写进基线就是永久豁免，
而落后数还在变，基线里那个 `1` 会变成假真值）。CI runner 上活锚不存在 ⇒ 该项记「未知」，
所以它不会在 CI 上假装通过。同理 `|empty-surface`（判定面为空 = 护栏恒真）标 `always=True`：
**永不进基线**，否则「我的护栏曾经空跑」会变成永久豁免。

**重生成必须带理由**：`--regen-baseline` 不带 `--reason` ⇒ `exit 2`；
理由、`anchor_sha`、`cases_fingerprint` 都写进基线 JSON（PR 里要说明为什么）。

## 9. 怎么用（一条命令、一个报告）

```bash
# 人读报告（永远 exit 0）
python3 scripts/drift_audit.py

# PR 门禁：新增漂移 ⇒ exit 1；存量放行
python3 scripts/drift_audit.py --check --json /tmp/drift.json

# 定时审计：陈旧基线条目也红 + 网络不可达也红
python3 scripts/drift_audit.py --check --strict-stale --fail-on-unknown

# 只看某一项 / 打印判据集合（机器可读）
python3 scripts/drift_audit.py --only heartbeat,mutable-locator
python3 scripts/drift_audit.py --list-checks

# 重生成基线（必须写理由）
python3 scripts/drift_audit.py --regen-baseline --reason "PR #xxxx：销账 xxx"
```

**退出码**：`0` 无新增漂移 / `1` 新增漂移（或 `--strict-stale` 下的陈旧条目 / 判据崩溃）/
`2` 用法错误（如 `--regen-baseline` 缺 `--reason`）。

**误红了怎么办（先怀疑夹具，再怀疑判据）**：测试里的**红证夹具**按定义就是一个"失效的引用"
（形如 `<不存在的路径>.py:<行号>`）—— 它必然被引用新鲜度扫到。处方**不是**放宽判据，而是在该
`tests/**` 文件里加一行显式声明：

```python
# drift-audit: refs-are-fixtures
```

审计见到该标记就跳过该文件的引用字面量（**只对 `tests/**` 生效**；文档/workflow 里加它无效）。
另一条同样有效的写法是**把字面量拼出来**（把路径与 `:<行号>` 分两段字符串拼接），源码不含该模式。
两条都**不削弱判据**：对文档与 workflow 的扫描照旧。

**审计的离线可复现性**：`--offline` 令网络判据记「未知」；`--now` / `--gh-fixture` /
`--live-anchor` / `--repo` / `--base` 供 L0 夹具在**临时仓库**里复现漂移态（夹具不依赖本机状态）。
