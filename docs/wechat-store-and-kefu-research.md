# 微信生态「商家开店 + AI 客服」通道调研（2026-11-05）

> **这是什么**：原设想「给每个商户一个独立小程序」判定走不通后，对**微信官方通道**做的一手资料调研 ——
> 商家能不能在微信里低成本「开店」，我们的 AI 能不能在微信里接待客户，走通「咨询 → 下单 → 支付 → 查单 → 售后」。
>
> **证据强度约定**：§三 的能力 / 门槛 / 资金路径**均取自微信开放文档与微信小店官方规则页**（2026-11-05 抓取，链接见附录）；
> **二手来源与未核实项一律不进结论**，集中列在 §八（每条附「怎么验」）。
>
> **结论先行**：**有方案，而且不需要商户自建小程序。**
> 走「**微信小店（交易面）+ 微信客服（对话面）+ 1 个平台自营小程序（导购面）**」三件套：
> 商户零开发、零代码审核、零 ICP 备案，**资金直达商户自己的微信支付商户号**，平台不碰钱。

---

## 一、结论（一张表看完）

| 面 | 通道 | 谁开、要什么 | 替代了原方案的哪一块 |
|---|---|---|---|
| **交易** | **微信小店** | 商户自己开：营业执照（企业店 / 个体工商户店）+ 法人/经营者身份证 | 商户小程序、商户自己申请支付商户号、我们的「服务商 + 特约商户」支付工程 |
| **对话** | **微信客服**（企业微信） | 商户注册企业微信 → 开通微信客服 → 扫码把客服账号授权给我们 | C 端小程序里的聊天页；用户**不加好友、不装小程序**，在微信里直接聊 |
| **导购 / 详情** | **1 个平台自营小程序**（我们自己的 appid） | 我们自己（一次审核） | N 个商户 appid + N 套出包/上传/审核/升级漏斗 |
| 分发 / 收费（可选） | **微信小店服务市场（ISV）** | 我们：第三方平台 + 权限集 + 全网发布 + 服务上架 | 逐户商务谈判与授权；商户在服务市场购买即**静默授权** |

一句话：**商户只需开「一个微信小店 + 一个微信客服」，剩下全是我们的一套系统。**

## 二、原链路为什么走不通（先把账算清）

原设计见 [tenant-miniapp-launch-and-payment.md](design/tenant-miniapp-launch-and-payment.md)（模式 A 半自动发布 / 模式 B 第三方平台代开发）。

### 2.1 商户侧成本（每开一家都要重来一遍）

| # | 事项 | 周期 / 成本 | 卡点 |
|---|---|---|---|
| 1 | 注册企业小程序 + 微信认证 | 1-3 天 + **300 元/年** | 需要企业主体、对公账户、管理员扫码 |
| 2 | ICP 备案 | **1-2 周** | 2023.9 起强制，纯等待 |
| 3 | 选服务类目 + 资质匹配 | 不确定 | 营业执照经营范围必须匹配，审核会打回 |
| 4 | 配置代码上传密钥 | 10 分钟 | **密钥仅显示一次**，商户容易丢；丢了要重置 |
| 5 | 每次发版：上传 → 提交审核 → 发布 | 每次 1-7 天 | 商户要理解「升级包/紧急度/放弃升级」 |
| 6 | 申请微信支付商户号 / 进件 | 3-7 天 | 需要 APIv3 密钥、证书、回调域名 |
| 7 | 配置 request 合法域名 | 10 分钟 | 填错 → 线上白屏 |
| 8 | 隐私协议 / 用户隐私保护指引 | 半天 | 模板要按商户改 |

### 2.2 平台侧成本（N 家 = N 倍的运营面）

按租户出包（P1/P3）、双通道配置（P2）、升级包与版本矩阵（P4）、SOP 手册（P5）、订单卡片（P6）、「小程序发布」页（P7）、旧包兼容窗口 —— 这七项**全部是为了「商户自己拥有一个 appid」这个前提服务的**。

### 2.3 结构性原因（换发布方式也救不了）

1. **主体、appid、审核权、发布权都在商户** —— 平台只能「代传包」，**不能替商户过审**。商户越多，N 套发布流程、N 份审核风险。
2. **升级是 pull 模式**（商户点「立即升级」才上传）—— 升级漏斗、滞后催办、旧版兼容是**长期**运营成本，不是一次性工程。
3. **支付要另外做一套「服务商 + 特约商户」**（原文档 §4 的 D2）—— 本质是「平台替商户发起收款」，而**微信小店已经把这套做完了**（见 §3.1）。
4. 原文档 §3.5 的「模式 B：第三方平台代开发」**只换了发布方式，没换 ownership 模型** —— 仍然是「每个商户一个小程序」。

> 本调研的结论是：**换 ownership 模型**（商户不再拥有小程序），而不是换发布方式。

## 三、官方通道事实（一手）

### 3.1 微信小店 —— 交易面

**是什么**：腾讯以微信为技术基础，向商家提供的**商品信息展示 + 商品交易**技术服务，是视频号小店的升级版；
官方明确「支持店铺及商品信息在**公众号（订阅号、服务号）、视频号（直播、短视频）、小程序、搜一搜**等多个微信场景内流转」。
（[微信小店介绍](https://developers.weixin.qq.com/doc/store/shop/)）

**谁能开**（[《微信小店入驻规则》20240826，2025-08-11 修订](https://store.weixin.qq.com/chengzhang/webdoc/wiki/7984/ffa4f53de1b8d289/growth_center_rule_for_store)）：

| 项 | 要求 |
|---|---|
| 店铺类型 | **企业店** / **个体工商户店**（规则未列个人店） |
| 主体限制 | 中国大陆合法注册实体；**同一营业执照最多开 30 家店铺** |
| 资质 | 营业执照（所售商品在经营范围内）+ 法人/经营者身份证；品牌认证可选 |
| 小程序 | **不需要** |
| ICP 备案 | 规则未要求（小店不是商户自建站点；以入驻页为准） |

**支付与结算**（[腾讯客服 FAQ：微信小店商品结算周期](https://kf.qq.com/faq/231129uaqauA2311297ZjiMZ.html)）：

- 商户接入小店后，**通过财付通自动开通一个新的微信支付商户号** —— 商户不需要自己去申请、也不需要把 APIv3 密钥交给我们。
- 用户支付成功 → 待结算资金；**商品确认收货后 + 7 天** 转入可提现资金（定制家具等类目另有履约型规则）。
- 技术服务费 = **费率 × 结算基数**，与商品售后期结束时一并结算，**从每笔订单货款里直接扣**
  （[《微信小店商家技术服务费管理规则》2025-02-25](https://store.weixin.qq.com/chengzhang/webdoc/wiki/1270/c1f8fa40d604582a/growth_center_rule_for_store)）。
- 资金路径：`用户付款 → 微信支付 → 商户自己的商户号 → 商户结算账户`。**平台不经手、不沉淀资金 ⇒ 无二清问题。**

**API 能力面**（[微信小店 API 接口目录](https://developers.weixin.qq.com/doc/store/shop/API/)）：
商品与类目、库存、**订单（含改价 / 改地址 / 发货 / 解密收货信息）**、售后、纠纷、物流与电子面单、资金结算与对账、营销与会员、**商家客服（sendmsg）**、小店礼物、优选联盟。

**两种接入模式**（[开发须知，2026-04-29 更新](https://developers.weixin.qq.com/doc/store/shop/dev_before/guide.html)）：

| 模式 | 适用 | 鉴权 |
|---|---|---|
| 商家自研 | 商家自建系统管自己的店 | 小店自己的 `access_token`（小店后台 → 服务市场 → 经营工具 → 自研） |
| **第三方服务商（ISV）** | **SaaS 为多个商家提供统一服务** | 商家授权后，用 `authorizer_access_token` 代商家调用 |

> **ISV 是官方为「一个 SaaS 服务多个商家」设计的模式** —— 正是 MIGAO 的形态。

### 3.2 小程序连接小店 —— 一个平台小程序服务 N 个商户

来源：[《微信小店「小程序连接小店」功能指引》2025-01-22](https://store.weixin.qq.com/chengzhang/webdoc/wiki/7296/99bdb51e4787f776/growth_center_manual_for_store)、
[开发指南](https://developers.weixin.qq.com/doc/store/shop/guide/connect/miniprogram.html)、
[官方 API 目录](https://developers.weixin.qq.com/doc/store/shop/API/)。

| 能力 | 组件 / 接口 | 要不要「关联关系」 | 关键事实 |
|---|---|---|---|
| 小程序内嵌**小店商品卡** | `<store-product>`（组件 3.5.5+；默认样式 3.7.1+） | **不要** | 官方原文：「**默认商品展示：不限制小程序和小店的关系，均可以进行跳转**」；传 `appid`=小店 appid + `product-id` 即可；点击**半屏拉起小店下单页** |
| 小程序内嵌**店铺首页** | `<store-home>`（3.5.5+） | **不要** | 「不限制小程序和小店的关系，均可以进行跳转」 |
| 小程序内嵌**优惠券** | `<store-coupon>`（3.8.3+） | **不要** | 「所有小店的优惠券均可在任意小程序调用」 |
| **订单详情页** | `wx.openStoreOrderDetail` | **不要** | 不限制关系，但会校验：①订单来自该小程序 ②属于该用户 ③属于目标小店 |
| 礼物组件 | `<store-gift>`（3.8.10+） | **要** | 需商家对指定小程序创建礼物活动 |
| **订单数据互通** | 订单通知 + 获取合作店铺订单 + 获取合作账号微信小店列表 | **要** | 小店发起邀请 → 小程序接受（`status=1`）后生效 |
| 定制商品 | 上传资料 → `media_id` → 塞进商品卡 → 下单 → 商家下载文件履约 | **不要** | 「个性化印刷、定制刻字、3D 打印」场景；**窗帘量尺定制正对口** |
| 带货跟佣 | 商品卡 `product-promotion-link` | **不要** | 可走优选联盟，按成交拿佣金（商业化可选项） |

**这一条是全局关键**：商品卡/店铺卡/优惠券/订单详情**都不要求关联关系** ⇒
**我们一个平台小程序，可以直接展示任意一家商户小店的商品并跳转其原生下单页**，商户侧零配置。
只有「订单数据回传/订单查询」需要建立「合作账号」关联（小店发邀请 → 我们的小程序接受）。

实现细节（容易踩）：
- 订单通知里的 `order_id` **不是小店订单 id**，只用于渠道小程序回查；回调事件名有新老两种（`cooperation_shop_order` / `related_shop_order_submission`），带 `shop_appid`。
- **UnionID 打通有额度**：官方「UnionID 机制」写明「一个开放平台账号最多可绑定 **20 个小店**」⇒ 商户数超过 20 时，跨应用识别用户需要规划多个开放平台账号（或不做跨店识别）。

> 未核实：一个小程序能接受多少家小店的关联邀请（文档未写上限）—— 见 §八 Q2。

### 3.3 微信客服 —— 对话面（把 AI 放进微信聊天）

来源：[微信客服 · 接收消息和事件](https://developer.work.weixin.qq.com/document/path/94670)、
[微信客服 · 发送消息](https://developer.work.weixin.qq.com/document/path/94677)。

- **客户侧体验**：从公众号菜单 / 小程序 / 视频号 / 网页 / 搜一搜 / 线下二维码进入「客服会话」，**不用加好友、不用装 App**，就在微信里聊。
- **技术形态**：回调事件 `kf_msg_or_event`（带 `Token` + `OpenKfId`）→ `sync_msg` 拉取最近 3 天消息 → `send_msg` 回复。
- **权限（关键）**：第三方应用需要「**微信客服 → 管理账号、分配会话和收发消息**」权限；
  自建应用 / 第三方应用 / 代开发自建应用三种形态都支持 ⇒ **可以做成服务市场上的第三方应用，批量授权**。
- **回复窗口**：「仅当微信客户在**主动发送消息**给客服后的 **48 小时**内，企业可发送消息给客户，最多 **5 条**；若用户继续发送消息，企业可再次下发」。
  ⇒ AI 只能**被动响应**，不能主动骚扰（合规上反而是好事，也决定了「主动营销」要有别的通道）。
- **消息类型**：文本 / 图片 / 语音 / 视频 / 文件 / 图文链接 / **小程序卡片** / 菜单消息 / 地理位置 / 获客链接。
  ⇒ 可以把「商品详情页 / 订单页」做成**小程序卡片**发进会话，实现「聊着聊着直接点单」。

### 3.4 微信小店服务市场 —— 分发与收费面（可选）

来源：[《微信小店服务市场接入指引》](https://developers.weixin.qq.com/doc/oplatform/partner/service_market/provider_guideline/enter_guideline/sph_enter_guideline.html)。

- 服务商资质路径：**第三方平台（开放平台）+ 申请权限集 + 全网发布** → 登录微信服务商平台 → 配置客服与收款账户 → 上架服务。
- 服务上架**必须提供 7 天免费版本**；支持「测试服务」调试；「服务 Url」为使用入口（支持移动端跳转指定小程序）。
- **授权是静默的**：商户在服务市场购买后，平台按服务类型把对应权限集**静默授权给第三方平台**，服务商据此换 `authorizer_refresh_token` / `authorizer_access_token`。
- 权限集按服务类型组合，例如：商品服务 / 订单服务 = **129、130、131、132**；ERP 再加 138、141；会员工具加 167、185&186。

> 含义：MIGAO 可以作为「**微信小店经营工具**」上架服务市场，商户在微信里点几下就完成「购买 + 授权」，
> 我们既拿到 API 权限，也拿到收款通道 —— 这是比「逐户签合同 + 收密钥」更轻的分发方式。
> 但它有一次性投入（第三方平台 + 权限集 + 全网发布 + 7 天免费版 + 服务运营），**属于第二阶段**。

### 3.5 概念澄清（别混）

| 名词 | 是什么 | 和我们的关系 |
|---|---|---|
| **微信小店** | 腾讯官方交易产品 | ✅ 本方案交易面 |
| **微信客服** | 企业微信的客服产品（客户在微信里聊） | ✅ 本方案对话面 |
| **小店「商家客服」** | 微信小店后台自带的客服工作台 / 客服 API | ⚠️ 是另一个东西；API **不支持第三方服务商调用**，只能商家自研（见 §八 Q5） |
| **微店（weidian.com）** | **第三方**电商平台（非腾讯官方） | ❌ 不是本方案；仅可作为「商户已有店」的外部链接 |
| **微信小商店** | 早期面向小商家的开店工具 | ⚠️ 旧形态；官方迁移说明：**视频号小店已迁移到微信小店**（[迁移说明](https://developers.weixin.qq.com/doc/channels/migration.html)，2026-07-05 更新），新开店按微信小店走 |
| **个人微信** | 商户现在加好友聊天的那个 | ❌ **没有官方 API**；Hook/协议外挂违反平台规则，有封号风险 |

## 四、路径对比

| 路径 | 商户要做 | 平台要做 | 资金 | 客户体验 | 结论 |
|---|---|---|---|---|---|
| **A. 每商户一独立小程序**（原设想） | 注册+认证+备案+类目+密钥+每次发版审核+开支付号 | 出包/密钥/版本矩阵/兼容 | 平台或商户支付号（服务商进件） | 最好的品牌独立感 | ❌ 淘汰为「旗舰版增值项」 |
| **B. 平台小程序 + 微信小店**（推荐） | **开小店**（营业执照，1-3 天） | 1 个自营小程序 + 商品卡/订单页 | 小店直收，平台不碰钱 | 微信内、原生下单 | ✅ **默认链路** |
| **C. 微信客服 + 小店**（推荐，与 B 并行） | **开通微信客服**（企业微信基础能力，开通条件见 §八 Q3）+ 授权 | 回调 + LLM + send_msg | 同上 | 不用加好友、聊天即服务 | ✅ **对话主入口** |
| D. 公众号（服务号）+ 小店 | 认证服务号（300/年）+ 菜单/客服消息 | 客服消息 API + 网页授权 | JSAPI 支付或小店 | 公众号内聊天 | ⚠️ 备选（服务号审核也在商户侧） |
| E. 微信小店服务市场 ISV | 在服务市场购买 | 第三方平台+权限集+全网发布+上架 | 服务市场收款 | 工具入口 | ✅ 第二阶段分发 |
| F. 企业微信外部联系人 | 企微 + 客户加企微好友 | 客户联系 API | 线下/小店 | 更像"加好友" | ⚠️ 备选（迁移成本高） |
| G. 个人微信机器人 | — | Hook/协议 | — | 最贴近现状 | ❌ **违规、封号、不可做** |

```

  │  ①从公众号菜单 / 二维码 / 搜一搜 / 视频号 / 小程序 进入
  ▼
┌──────────────────────────────┐
│ 微信客服会话（微信原生窗口）      │  ← 商户自己的微信客服账号（授权给我们）
│  用户：这窗帘多高、能定制吗？      │
│  AI：……（kf 回调 → LLM → send_msg）│
│  发「商品卡/订单卡」小程序卡片     │
└──────────────┬───────────────┘
               │ ②点卡片
               ▼
┌──────────────────────────────┐
│ 平台自营小程序（1 个 appid）      │
│  <store-product> 商品卡           │
│  <store-home> 店铺卡              │
│  wx.openStoreOrderDetail         │
│  + 定制表单（量尺/面料/工艺）→ media_id │
└──────────────┬───────────────┘
               │ ③半屏拉起原生下单
               ▼
┌──────────────────────────────┐
│ 微信小店（商户自己的店）          │
│  微信支付（商户自己的商户号）      │
│  订单/售后/物流/结算             │
└──────────────────────────────┘
               │ ④订单通知 / 合作店铺订单
               ▼
        MIGAO 后端（多租户）
```

### 5.1 商户开通 SOP（目标：30 分钟内可上线）

| 步 | 商户做什么 | 平台做什么 |
|---|---|---|
| 1 | 注册/登录微信小店，提交营业执照 + 法人身份证，选类目（「家纺」等），缴保证金 | 提供图文 SOP + 类目建议 |
| 2 | 上架商品（可先用我们的商品导出/Excel 导入生成小店商品草稿） | 商品字段映射、批量上架（后续用 ISV 权限集） |
| 3 | 注册企业微信 → 开通微信客服 → 扫码授权我们的第三方应用 | 授权回调、租户绑定、客服账号映射 |
| 4 | （可选）邀请我们的平台小程序建立「合作账号」关联 | 接受邀请 → 开始收订单通知 |

### 5.2 阶段

| 阶段 | 内容 | 产出判据 |
|---|---|---|
| **M0（2 周内可验证）** | 1-2 家商户：开小店 + 平台小程序挂商品卡 + 微信客服接 AI；人工走通「咨询→点卡→下单→支付→查单」 | 真实订单 1 单，全链路截图/日志 |
| **M1** | 合作账号关联 → 订单通知 + 合作店铺订单；米宝 `customer_order_query` 改读小店订单 | AI 能回答「我昨天那单到哪了」且订单号来自小店 |
| **M2** | ISV：第三方平台 + 权限集 129/130/131/132 + 服务市场上架 | 商户在服务市场购买后，我们拿到 `authorizer_access_token` |
| **M3** | 定制链路：量尺/加工参数 → `media_id` 商品卡 → 商家下载文件履约 | 1 张定制单走通 |
| **M4（可选）** | 优选联盟跟佣（成交归因、佣金结算） | 佣金到账对账 |

## 九、风险与合规

| 风险 | 说明 | 应对 |
|---|---|---|
| **个人微信自动化** | 商户现在大量在个人微信里加好友聊；个人微信**无官方 API**，Hook/协议外挂违反规则、封号风险高 | 明确不做；把客户迁到**微信客服**（发二维码/公众号菜单/短信引导） |
| **二清** | 平台统一收款再分账是红线 | 小店直收（钱进商户自己的商户号），平台**不经手资金** |
| **小程序审核** | 平台小程序承载多商户商品，可能被要求电商类目 | Q1 先验证；若被卡，退化为「H5 + 小店 H5 链接」或「商户自建小程序（旗舰版）」 |
| **依赖微信政策** | 小店/客服/组件迭代快（文档 2025-12、2026-04 都有变更） | 通道适配层隔离；关键接口版本变化纳入季度巡检 |
| **对话 48h / 5 条** | 微信客服不能主动触达 | 主动营销另走公众号模板/订阅消息或企微群发；AI 定位为「被动接待」 |
| **数据与隐私** | 打通 openid/unionid 需开放平台绑定；跨应用识别依赖 unionid | 按官方「UnionID 机制」绑定；隐私协议列明收集项 |
| **小店客服 API 切换不可逆** | 切到 API 模式后，工作台欢迎语/自动回复失效，未接好会丢咨询 | 先测试店验证；正式店切换前灰度 |

## 十、米宝接入微信小店的三种完整链路（2026-11-05 补）

### 10.1 先回答一句：**微信小店没有「AI 插件位」**

- 小店页面里**没有**可注入第三方 agent 的槽位/组件；唯一的「店内对话通道」是**小店商家客服**，
  而它的 API **只对商家自研开放、不支持第三方服务商**（§3.1 / [商家客服文档](https://developers.weixin.qq.com/doc/store/shop/guide/connect/kf.html)）。
- 因此「把米宝对接到微信小店」只可能是下面两种含义之一：
  1. **米宝在店内客服窗口里接待客户**（链路 1）——客户在小店商品页点「客服」就和米宝聊；
  2. **米宝在店外接待、交易走小店**（链路 2 / 3）——米宝在微信客服或我们的小程序里聊，点商品卡进小店原生下单。

### 10.2 三条链路对比

| | 链路 1：店内客服直连 | **链路 2：微信客服 + 小店（推荐）** | 链路 3：平台小程序内嵌 |
|---|---|---|---|
| 客户在哪遇到米宝 | **小店商品页/订单页的「客服」** | 微信客服会话（扫码/公众号菜单/小程序跳转） | 我们的小程序聊天页 |
| 商户前置 | 小店自研 AppID/Secret + 配消息推送 + **超管扫码切 API 模式（不可逆）** | 开通微信客服 + 授权（MVP：自建应用 corpId/secret；规模化：第三方应用） | 无（我们的小程序） |
| 收消息 | 事件 `commkf_send_msg_to_kf` | 事件 `kf_msg_or_event` → `sync_msg` | 我们自己的 SSE |
| 发消息 | `channels/ec/commkf/sendmsg` | `kf/send_msg` | SSE 流式 |
| 语音 | ✅ 回调带**转写文本** `voice.translated_msg` | ❌ 只给 `media_id`，**需自建 ASR** | 自有 |
| 商品卡/订单卡 | ✅ 收发都支持 | ✅ 发小程序卡片（点开进商品页） | ✅ |
| 48h / 5 条 | ✅ 同样受限 | ✅ 同样受限 | ❌ 不受限 |
| 能否批量复制 | ❌ 不支持 ISV，**每户手工配置 + 切换** | ✅ 第三方应用一次授权 | ✅ |
| 硬约束 | 切换后工作台欢迎语/自动回复失效，未接好会丢咨询 | 客户要一次入口跳转 | 多一跳 + 小程序审核（Q1） |
| 结论 | **标杆/旗舰版**（1-2 家） | **默认链路** | 作为链路 2 的详情/长对话承载页 |

### 10.3 推荐组合

- **默认走链路 2**：可批量、商户零代码、钱进小店；
- **链路 1 只做 1 家标杆**：验证「店内客服 → 米宝」的转化是否显著优于链路 2，再决定是否给旗舰版；
- **链路 3 不单独做入口**：把它当作商品详情页 + 长对话兜底（微信客服 5 条预算用完后，引导客户点小程序卡片继续聊）。

### 10.4 链路 2 的完整 runbook（一次真实会话）

**A. 商户侧前置（约 30 分钟，一次性）**

| # | 谁做 | 动作 | 失败点 |
|---|---|---|---|
| 1 | 商户 | 开微信小店（营业执照 + 法人身份证 + 类目「家纺」+ 保证金），上架商品 | 类目与经营范围不匹配被打回 |
| 2 | 商户 | 注册企业微信 → 开通「微信客服」→ 建客服账号 → 取**客服链接** | 主体未认证时功能受限（Q3） |
| 3 | 商户 | 建「自建应用」（MVP）并给我们 `corpId` + `secret` + `agentId`；或授权我们的第三方应用（规模化） | 应用不在「微信客服-可调用接口的应用」里 ⇒ 48001 |
| 4 | 商户 | （可选）邀请我们的小程序为「合作账号」 | 邀请超时/拒绝 |

**B. 平台侧模块（6 个）**

| # | 模块 | 要做的事 |
|---|---|---|
| 1 | 回调网关 | 校验 `msg_signature/timestamp/nonce` + AES 解密 → 入队；**幂等**（按事件去重） |
| 2 | 拉取器 | `kf/sync_msg`，`cursor` **入库持久化**（官方明确要求，丢了要重拉 3 天） |
| 3 | 租户映射 | `open_kfid → tenant_id`；`external_userid → C 端用户`（按租户隔离，复用现有 `user_identities`） |
| 4 | 米宝 | 复用 LangGraph：意图路由 → 工具（商品/订单/物流/定制报价）→ 生成回复 |
| 5 | 发送器 | `kf/send_msg`：文本合并（**每条回复只发 1-2 条**，5 条预算很紧）+ 小程序卡片 |
| 6 | 订单同步 | 合作账号 `cooperation_shop_order` / ISV 订单接口 → 落 `orders`/映射表 → 供查单 |

**C. 时序（8 步）**

```
1. 客户扫码 → 微信客服会话 → 发「这款窗帘能做 3 米吗，多少钱」
2. 企微回调 kf_msg_or_event → 网关验签解密 → 入队
3. 拉取器 sync_msg(cursor) → 拿到文本 + external_userid + open_kfid
4. 映射租户 → 米宝：意图=咨询 → 商品检索（小店/自有）→ 报价
5. send_msg：1 条文本 + 1 条小程序卡片（预算 2/5）
6. 客户点卡片 → 平台小程序商品页 → <store-product> 半屏 → 小店原生下单支付
7. 小店订单通知 → 我们落库（order_id / shop_appid / openid）
8. 客户回会话问「什么时候发货」→ 米宝查小店订单+物流 → 回复
```

**D. 验收判据（缺一不算走通）**

1. 真实客户（非内部账号）完成 1 单，订单号可在小店后台对上；
2. 米宝首响 < 10s，48h 内**不超 5 条**、无重复回复（幂等验证：重复投递同一事件只回一次）；
3. 订单通知 → 落库 < 30s，AI 查单结果与店铺后台一致；
4. 语音/图片消息不丢：语音走 ASR、图片走 Vision，均能给出可读回复；
5. 断线可恢复：`cursor` 丢失后重拉 3 天内消息不重复、不丢关键会话。

### 10.5 会卡住「完整」的四个缺口

| 缺口 | 影响 | 处置 |
|---|---|---|
| 微信客服语音只给 `media_id`，**无转写**（小店客服反而有 `translated_msg`） | 客户发语音，米宝听不懂 | 接 ASR（可先用云厂商/本地小模型），或引导「请发文字」 |
| 图片/文件只给 `media_id` | 图片识别链路要自己下载 | 企业微信「获取临时素材」接口下载 → 走 DeepSeek Vision |
| 48h / 5 条 | 不能主动跟进、不能一次发多条 | 回复合并；长对话引导到小程序卡片 |
| 平台小程序审核类目（Q1） | 商品卡载体可能过不了审 | 先提审验证；被卡则退化 H5 + 小店 H5 链接 |
