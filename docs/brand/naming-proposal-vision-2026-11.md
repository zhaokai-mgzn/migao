# 启营：观星台改名第二轮——按公司愿景与产品力重取平台名

> 2026-11-19 ｜ 状态：提案（未改名）｜ 关联 issue #8929
>
> 用户第一轮反馈原话：「这几个名字太局限格局太小。现在抛开行业，基于我们公司愿景、产品力，重新取名字。」
>
> 第一轮提案（`docs/brand/naming-proposal-2026-11.md`）保留为「行业贴近」轮记录；本轮只回答**平台名**。

## 0. 结论

**推荐平台名：启营（品牌最贴）；备选：元营（公司品牌优先；9 / 42 类待查）。**

- **启** = 让 AI 成为能力（公司使命）；**营** = 经营 / 运营（产品主战场）。
- **启营 = 让每一家中小企业都拥有 AI 经营能力**；行业无关、平台级、可向更多行业扩展。
- **注意**：第 9 类（软件）已有「启营」商标公告，9 / 42 类是采用前的硬门槛；清不掉就转元营（先查 9 / 42 类）。
- **品牌架构**：词元通达（公司 / AI 底座）→ **启营**（平台）→ 米宝 / 黄金策（Agent）→ 布掌柜（布艺行业解决方案，可选）。
- **备选**：元营（更贴「词元」公司品牌；9 / 42 类待查）、启能（更贴「能力」使命）。
- **上一轮的「布掌柜 / 帘师傅 / 布总管」不再作为平台名**；它们是行业垂直品牌的好名字，可保留为布艺 / 窗帘解决方案品牌。

**如果今天只投一个名字：启营（先清 9 类）；清不掉就转元营（先查 9 / 42 类）。** 启营同时接住公司使命（启）与产品主战场（营），又不把公司锁在布艺行业。

## 1. 上一轮为什么「太小」

| 维度 | 上一轮（布掌柜 / 帘师傅 / 布总管） | 本轮要求 |
|---|---|---|
| 语义 | 布 / 帘 + 掌柜 / 师傅 / 总管 | 行业无关 |
| 格局 | 一家店 / 一个行业 | 每一家中小企业、跨行业 |
| 角色 | 店主 / 师傅 / 店员 | 平台 / 能力 / 标准 |
| 延展 | 扩到软装都吃力 | 布艺只是起点，可到更多行业 |
| 与公司 | 没接上「词元通达」的 AI 底座 | 能承接公司愿景与产品力 |

上一轮不是错，是**场景选错了**：它回答的是「这家窗帘店该叫谁」，不是「词元通达要把 AI 带给谁」。作为**布艺行业解决方案**的名字，布掌柜仍然很好；作为**平台名**，它把公司锁死在一个行业里。

## 2. 公司愿景与产品力

### 2.1 愿景（仓库现行文案）

- 「**让 AI 成为中小企业的经营能力。**」（官网「关于词元通达」标题）
- 「AI 不应只属于大型企业：以产品化、可配置、可审计的方式，把大模型带到真实经营现场。」（官网同节 lead）
- 「让每一家中小企业，都拥有与大企业同等的经营能力。观星台从布艺行业起步，把 AI 数智化带向更多行业，让规模不再是经营能力的边界。」（#8863 官网叙事原文；「观星台」是当时的旧名）
- 「用 AI 数智化赋能每一家中小企业。」（官网 Hero）

### 2.2 产品力（不是形容词，是能力面）

| 能力 | 事实 |
|---|---|
| 双 Agent | 米宝（顾客侧 7×24 咨询 / 算料 / 下单 / 售后）+ 黄金策（经营侧问答 / 分析 / 受控写入） |
| 全链路 | 询价算料 → 下单 → 生产（裁床 / 车位 / 后整）→ 入库 → 发货 → 售后 / 对账 |
| 八个能力域 | 客户服务、订单 / 商品、生产、质量、仓储 / 物料、财务、供应链、组织 |
| 四端同源 | 管理后台、顾客小程序、商家小程序、员工端 H5 / 终端 |
| 企业级底座 | 多租户隔离、PostgreSQL RLS、岗位权限、操作审计 |
| 可审核的 AI | 口径卡先审核再进 prompt；写操作有边界、确认卡、审计记录 |
| 行业纵深 | 算料、SKU 矩阵、批次成本、计件工资是主模型，不是外挂；但**不是天花板** |

### 2.3 命名标准

1. **行业无关**（25%）：不带布 / 帘 / 裁 / 缝 / 织。
2. **平台级**（20%）：不是店主 / 师傅 / 工具，而是能力 / 平台 / 标准。
3. **使命级**（20%）：能承载「AI 成为经营能力」「规模不再是边界」。
4. **产品级**（15%）：能接住双 Agent、全链路、可审计，不是空泛的云 / OS。
5. **大而不空**（10%）：有野心，但一听知道是干什么的。
6. **可说可记**（10%）：2-3 字，无坏谐音，能注册 / 能搜。

## 5. 推荐：启营

### 5.1 一句话

**启营——让每一家中小企业都拥有 AI 经营能力。**

### 5.2 为什么是它

1. **使命**：启 = 让 AI 成为能力；营 = 经营。名字本身就是公司使命的缩写。
2. **产品**：营 = 经营 / 运营；平台的全链路、双 Agent、四端、审计都在「营」里；启 = AI 把能力激活。
3. **格局**：行业无关；不锁死在布艺；从布艺起步，可到更多行业；比「布掌柜」大一个量级。
4. **温度**：启是正向动词，营是日常经营词；不像「元枢」那么冷，也不像「无界」那么空。
5. **差异**：不是常用词；「启赢」正向谐音；比「启能 / 智营 / 无界 / 知行」更有品牌感。
6. **架构**：词元通达（公司 / AI 底座）→ 启营（平台）→ 米宝 / 黄金策（Agent）→ 布掌柜（布艺行业解决方案，可选）。

### 5.3 品牌架构

| 层级 | 名字 | 说明 |
|---|---|---|
| 公司 / AI 底座 | 词元通达 / 词元 | 公司主体与技术品牌；「词元」= token，AI-native |
| 平台 | **启营** | 面向每一家中小企业的 AI 经营平台 |
| Agent | 米宝 | 顾客侧 7×24 服务 |
| Agent | 黄金策 | 经营侧分析与受控写入 |
| 垂直解决方案（可选） | 布掌柜 | 布艺 / 窗帘行业版；上一轮的名字在这里继续使用 |
| 旧平台名 | 观星台 | 降级为经营看板 / 数据模块名，或退役 |

### 5.4 口号

- 启营——让每一家中小企业都拥有 AI 经营能力。
- 启营——AI 时代的经营操作系统。
- 启营——把大企业的经营能力，装进每一家中小企业。
- 启营——规模不再是经营能力的边界。
- 启营——让经营，从经验走向智能。

### 5.5 风险

| 风险 | 事实 | 处置 |
|---|---|---|
| 读音 / 语义 | 「启营」不是常用词，可能被读成「起营」 | 口号 / 视觉固定读音和语义；「启赢」正向谐音可做辅助 |
| 同名公司 | 初步检索到北京启营科技工程、启营电子科技、深圳市启营化工、启营教育 | 做商标交叉检索；同名不等于同类 |
| 商标 | 第 9 类已有「启营」商标公告；第 42 类需专业检索；9 类是软件直接冲突面 | 9 / 35 / 42 类硬门槛；未清掉不对外发布 |
| 域名 | `qiying.com` / `qiyings.com` 已注册（2026-11-19） | 2 字拼音 .com 不可得；查 `.cn` / 组合域名 / 品牌 + AI |
| 小程序 / 应用市场 | 微信小程序名、应用市场名需查重 | 准备「启营 +」变体 |
| 迁移 | #6525 的改名是 665 文件量级 | 选定后单独立项、一次改干净 |

## 6. 备选：元营、启能

### 6.1 元营（公司品牌优先）

- **语义**：词元（AI / token）+ 经营；「词元 · 元营」是最顺的公司-产品关系。
- **优点**：产品指向清楚；平台级；行业无关；与公司 AI 品牌一体。
- **风险**：偏抽象，店主未必秒懂；上海元营生物科技同名；`yuanying.com` 已注册；初步只看到生物科技同名，9 / 42 类仍需专业检索。
- **适合**：如果团队希望产品名直接继承「词元」的 AI 资产，元营比启营更「公司化」。

### 6.2 启能（使命优先）

- **语义**：启 = 开启；能 = 能力；最贴「让 AI 成为经营能力」。
- **优点**：使命最直白；2 字大气；行业无关。
- **风险**：偏能力、不偏经营；启能新能源 / 启能科技 / 启能教育等同名多；差异化弱；42 类待查。
- **适合**：如果团队想把名字做成「AI 能力普惠」的品牌，而不是「经营平台」的品牌。

### 6.3 无界 / 知行 / 游刃 为什么不做首选

- **无界**：愿景最直白，但 1216 条商标记录，太泛，不接产品；做口号可以（「让规模不再是边界」），做名字不行。
- **知行**：双 Agent 的「知 / 行」很好，但商标拥挤，且不接公司愿景；做产品原则可以（「知行合一」），做名字不行。
- **游刃**：产品让经营「游刃有余」很好，但第 42 类已有商标；文学感强；不做首选。

## 8. 建议的决策路径

1. **三选一**：启营（推荐）/ 元营（公司品牌优先）/ 启能（使命优先）。
2. **查商标 + 域名 + 小程序名**：9 / 35 / 42 类；同时看 24 / 20 / 25 类冲突。
3. **用户盲测**：拿 3 个名字给 5-10 位不同行业的中小企业主，问「这是干什么的、你记得住吗、你会不会用」。
4. **选定后开改名单**：一次改完四端文案 + 文档 + 小程序名 + 域名 + APK；参照 #6525 的做法（旧名用户可见面零残留 + 新名关键落点正向存在 + CHANGELOG + UI 截图 before/after）。
5. **旧名处理**：观星台降级为经营看板 / 数据模块名，或退役；布掌柜作为布艺行业解决方案品牌保留（可选）。
