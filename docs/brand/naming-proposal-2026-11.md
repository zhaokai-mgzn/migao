# 观星台改名：候选名与取舍建议

> 2026-11-19 ｜ 状态：提案（未改名）｜ 关联 issue #8926
>
> 用户原话：「我想给观星台换个名字，观星台不贴近产品和用户。结合我们产品和行业，你觉得叫什么名字比较好。」
>
> 本文只做命名提案与取舍，不改代码、文案、域名或小程序名；选定名字后另开改名单。

## 0. 结论

**品牌最贴的是「布掌柜」，但它的第 42 类商标记录是采用前的硬门槛。**

- **对用户**：掌柜 = 店主每天挂在嘴边的角色；「布掌柜」一听就知道是布艺 / 窗帘店的掌柜，不需要解释。
- **对产品**：掌柜对整店负责——接客、算料、下单、生产、库存、财务；不是单一客服或算料工具，正好装得下平台的全链路。
- **对品牌体系**：布掌柜（平台）+ 米宝（顾客侧伙计）+ 黄金策（经营侧军师）= 一个掌柜、一个伙计、一个军师，比「观星台 + 米宝 + 黄金策」更像一家人。
- **现实面**：`buzhanggui.com` / `buzhanggui.cn` 在 2026-11-19 的 whois 查询中无记录（可注册，仍以注册商实时结果为准）；但第 24 / 25 / 42 类都有「布掌柜」商标记录，海宁还有一家同名纺织品经营部。**第 42 类（网站 / SaaS 服务）是 SaaS 平台的直接冲突面，必须由专业代理判断能否规避或共存。**
- **如果 42 类清不掉**：不要退回「观星台」式的抽象名；在同一条「店主人格」线上做第二轮（优先「帘师傅」「布总管」），或按本文 §5 的备选路径处理。

**如果今天必须只投一个方向：布掌柜（先做 42 类清除评估）。** 它的用户贴合度和产品贴合度都最高；但 42 类清不掉就不要硬上，转「帘师傅 / 布总管」。

**明确不建议**：经纬（与经纬纺机、浙大经纬直接撞）、布卡（与布卡互动撞）、布当家 / 布管家 / 布管事 / 布尺 / 布行 / 布能 / 布会 / 布知（「不…」谐音反义）、织女星（仍是星空隐喻，且 24 类与窗帘店已有同名）、一尺（太窄，像量尺工具）。

## 1. 为什么「观星台」不贴

| 维度 | 观星台 | 用户实际语言 |
|---|---|---|
| 语义 | 天文台、看星星 | 接单、算料、下单、生产、库存、对账 |
| 角色 | 一个「台」（工具 / 地点） | 掌柜、师傅、老板、店长 |
| 情绪 | 冷、远、仰望 | 忙、算不清、怕漏单、怕算错 |
| 产品 | 只暗示「看 / 观测」 | 全链路经营 + 两位 Agent |
| 记忆 | 三个字，但和布艺无关 | 说一次就能记住的行业词 |

「观星台」不是坏名字，但它回答的是「我们仰望什么」，不是「我这家窗帘店今天怎么把单接住、把料算准、把钱收回来」。

仓库里现成的 POC 一句话定位其实已经把答案写出来了：

> **观星台 = 窗帘店的 AI 接单员 + 算料师傅 + 记账员，7×24 不休息。**（`docs/deployment/poc-demo-script.md`）

这句话里没有一个词是「观星台」。新名字应该让这句话读起来像同一个人：**布掌柜 = 窗帘店的 AI 掌柜，接单、算料、记账全都管。**

## 2. 命名 Brief

| 项 | 口径 |
|---|---|
| 产品 | 布艺 / 窗帘行业的企业级 AI 经营平台；多租户 SaaS |
| 用户 | 窗帘 / 布艺店老板、店员、车间工人、终端顾客 |
| 场景 | 询价算料 → 下单 → 生产（裁床 / 车位 / 后整）→ 入库 → 发货 → 售后 / 对账 |
| AI 分工 | 米宝（C 端顾客服务）+ 黄金策（B 端经营助手） |
| 品牌人格 | 专业、温暖、可信、懂行；不是「高冷科技」，是「店里最能干的自己人」 |
| 现行资产 | 产品名「观星台」；小程序实名「词元观星台」；logo「帘成 M / C1 取景角 + AI 星芒」；域名 `migaozn.com` |
| 历史改名 | #6525（米高 → 观星台，665 文件量级）；#8881（元元 → 米宝）；#8614（品牌标） |

**命名标准（按权重）**：

1. **用户听得懂、说得出**（30%）：店主听一遍能复述，能拿去跟店员说。
2. **产品装得下全链路**（25%）：不像单一客服 / 算料 / 记账工具。
3. **有差异化、可注册**（20%）：不是纯描述词，9 / 35 / 42 类有空间。
4. **能和米宝 / 黄金策组成体系**（10%）：一个掌柜、一个伙计、一个军师。
5. **好记、好写、好搜**（10%）：三字以内、无生僻字、无坏谐音。
6. **能延展到软装 / 家居**（5%）：先吃透窗帘，再谈扩品类。

## 4. 首选：布掌柜

### 4.1 为什么是它

1. **用户语言**：掌柜是店主 / 店长每天挂在嘴边的角色。「布掌柜」不需要解释，听一遍就知道是「布艺店的掌柜」。
2. **产品范围**：掌柜不是客服、不是算料员、不是记账员，而是对整店负责的人——接客、算料、下单、生产、库存、财务，正好对应平台的全链路。
3. **品牌体系**：布掌柜（平台）+ 米宝（顾客侧伙计）+ 黄金策（经营侧军师）。一个掌柜带两个角色，比「观星台 + 米宝 + 黄金策」更像一家人；老板是东家，AI 是掌柜，角色层级清楚。
4. **情绪**：温暖、可信、懂行；不是「仰望星空」，是「柜台后面那个什么都知道的人」。
5. **视觉**：现有「帘成 M」图形可以演化成掌柜印章 / 算盘 / 帘头；「布掌柜」三字结构稳，适合做招牌、小程序头像、APK 图标。
6. **现实**：三字、无生僻字、好搜；`buzhanggui.com` / `buzhanggui.cn` 目前无记录；比「观星台」更容易被店主记住和转述。

### 4.2 风险与门槛

| 风险 | 事实 | 处置 |
|---|---|---|
| 商标 42 类 | 初步检索到「布掌柜」第 42 类（网站服务）商标记录 | **采用前必须由专业代理判断**：是否构成相同 / 近似、能否规避 / 共存 / 购买；未清掉不对外发布 |
| 商标 24 / 25 类 | 第 24 类（面料）、第 25 类（服装）有「布掌柜」商标记录；海宁有「布掌柜纺织品经营部」 | 与 SaaS 不直接同类，但同行业同名会带来混淆；做交叉检索与混淆评估 |
| 微信小程序名 | 「布掌柜」可能已被占用（顾客端 / 商家端都要查） | 微信公众平台查重；准备「布掌柜 +」变体 |
| 域名 | `.com` / `.cn` 目前无记录；`.com.cn` 未取到明确结果 | 注册商实时复核；先锁 .com + .cn |
| 品牌迁移 | #6525 的改名是 665 文件量级；四端文案、文档、小程序名、APK、域名都要动 | 选定后单独立项、一次改干净；不要边改边想 |
| 语义边界 | 「掌柜」偏门店 / 零售；未来重点转工厂 / 批发时可能不够 | 当前核心用户是窗帘 / 布艺门店，合适；扩品类时用副品牌 |

### 4.3 一句话 / 口号

- 布掌柜——布艺窗帘店的 AI 掌柜。
- 接客、算料、管店，一个布掌柜就够了。
- 你负责选布，布掌柜负责把店管明白。
- 米宝接客，黄金策参谋，布掌柜管店。

## 5. 备选：帘师傅、布总管

### 5.1 帘师傅（更可能注册的「用户贴」备选）

- **为什么**：「帘」= 窗帘（核心品类），「师傅」= 懂算料 / 工艺的人；POC 金句就是「算料师傅」。三字、无生僻字、无「不」谐音；初步网络检索未见直接同名商标（**不等于可用**）。
- **代价**：它更像「做帘子的师傅」，不像「管全店的平台」；需要用副标题 / 口号把经营面补出来（「帘师傅——窗帘店的 AI 经营平台」）；如果公司要扩到布艺批发 / 软装，「帘」会限制。
- **适合**：如果布掌柜 42 类清不掉，且团队更看重「一听就懂 + 可注册」，帘师傅是同一方向里最顺的备选。

### 5.2 布总管（更强调「全链路」的备选）

- **为什么**：「布」= 布艺，「总管」= 什么都管；比「掌柜」更强调全链路覆盖；无「不」谐音；初步只看到第 25 类商标记录，42 类待查。
- **代价**：「总管」偏书面 / 管家感，店主日常不一定这么说；需要 5-10 位店主盲测；「布总管」也可能被听成「布匹总管」，偏供应链。
- **适合**：如果团队想要一个比「掌柜」更「管理平台」、比「师傅」更「全链路」的名字，可作为第二轮候选。

### 5.3 经纶（产品语义备选，但不建议作为首选）

- **为什么**：「经」= 经线 / 经营，「纶」= 丝线 / 谋略；「满腹经纶」= 有学问、有办法。一个懂布艺经营的 AI，满腹经纶，语义极好。
- **为什么不首选**：它贴产品，不贴用户；店主不会说「我今天经纶一下」；如果用户要的是「一听就懂」，它可能重蹈「观星台」的覆辙。第 42 类还有商标记录。
- **适合**：如果团队更想要「品牌感 / 文化感」而非「店主人格」，且 42 类能清，可作为品牌升级方向；但必须做用户盲测。
