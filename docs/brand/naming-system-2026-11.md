# 一个「启营」：词元通达产品命名统一方案

> 2026-11-23 ｜ 状态：提案（未改名）｜ 关联 issue #9063
>
> 用户原话：「我们公司名称词元通达，我们的产品中产品名共出现了四个：米高智能、观星台、米宝、黄金策，这不利于用户对我们的产品建立统一标识形成用户心智口口传播。我想把名称统一一下，要求好听、响亮又立意深远，你有没有什么好的建议。」
>
> 本文回答「怎么统一」；平台名的完整取舍见同 PR 的 `naming-proposal-vision-2026-11.md`（第二轮）。

## 0. 结论

**推荐：一个产品名「启营」，两个角色「启营客服 / 启营参谋」。**

| 角色 | 名字 | 旧名 | 说明 |
|---|---|---|---|
| 平台 / 产品 | **启营** | 米高智能 / 观星台 | 用户只需要记住的一个品牌 |
| 顾客侧 Agent | **启营客服**（角色名） | 米宝 | 启营里的顾客服务角色，不再单独背品牌 |
| 经营侧 Agent | **启营参谋**（角色名） | 黄金策 | 启营里的经营参谋角色，不再单独背品牌 |
| 公司 | **词元通达**（保留） | — | 公司 / 法律主体；「词元」是 AI 技术品牌 |

- 四个名字 → **一个品牌 + 两个角色**；用户说「启营」，就知道是这套产品。
- 如果团队希望两个 Agent 保留人格化名字，走备选 **「启」家族**：**启营 / 启宝 / 启策**（见 §4.1）。
- 如果只想要公司-root 的家族，走备选 **「元」家族**：元营 / 元宝 / 元策（见 §4.2）。

**一句话：四个名字收成一个「启营」；启营管店，客服接客，参谋出策。**

## 1. 四个名字为什么不利

| 名字 | 命名逻辑 | 问题 |
|---|---|---|
| 米高智能 | 旧公司 / 产品名 + 泛描述 | 与「词元通达」不一致；「智能」是品类词，不像品牌 |
| 观星台 | 地点 / 天文台 | 不贴产品；用户听不懂「台」和自己生意的关系 |
| 米宝 | 可爱型 Agent 名 | 「米」来自旧品牌；与「黄金策」风格不搭 |
| 黄金策 | 古典 / 术数型 Agent 名 | 「黄金」= 钱，「策」= 术数 / 策略；与「米宝」不是一家人 |

四个名字 = 四种命名逻辑（旧品牌 / 地点 / 可爱 / 古典）。用户无法从名字看出它们属于同一家公司，更无法口口传播「这一个产品」。

**统一的目标不是「四个都改成一个字」，而是让用户听到「启营」就知道整套产品。** 角色名可以保留，但不再各自背品牌。

## 2. 命名标准

1. **一个品牌**：用户只需要记住一个名字。
2. **好听、响亮**：开口音 / 鼻音收尾，二到三字，连读顺口，无坏谐音。
3. **立意深远**：有经典 / 文化根，能讲出「AI 成为经营能力」的故事。
4. **角色可辨**：平台 / 顾客 / 经营三个角色，一听知道谁是谁。
5. **可延展**：未来加角色 / 行业，仍能在这一个品牌上生长。
6. **可注册**：9 / 35 / 42 类有空间；小程序 / 域名可查。

## 3. 推荐：一个「启营」

### 3.1 三个名字

| 名字 | 读音 | 字义 | 角色 | 一句话 |
|---|---|---|---|---|
| **启营** | qǐ yíng | 启 = 开启 / 启发；营 = 经营 | 平台 / 产品 | 启营——让 AI 成为每一家中小企业的经营能力 |
| 启营客服 | qǐ yíng kè fú | 启营里的顾客服务角色 | 顾客侧 | 接客、算料、下单、售后 |
| 启营参谋 | qǐ yíng cān móu | 启营里的经营参谋角色 | 经营侧 | 问答、分析、经营建议 |

> 角色名是对外**功能称呼**，不是第二个品牌；海报 / 小程序 / App 上只出现「启营」。

### 3.2 为什么好听、响亮

- **两个字**：qǐ yíng，短、好记、好打；适合口口传播、小程序名、App 名、招牌。
- **声母 + 韵母**：qǐ 是送气音，开口亮；yíng 是鼻音收尾，余音长；连读有「启—营」的起伏。
- **声调**：三声 + 二声，先抑后扬，像「启程」的语气。
- **无坏谐音**：主要风险是「起营」（拔营 / 开营），靠口号和视觉固定为「启」；正向谐音「启赢」可做辅助。
- **可喊**：两个字都开口，适合展会 / 电话 / 短视频里喊出来；比「观星台」「黄金策」短，比「米宝」稳。

### 3.3 为什么立意深远

- **启**：出自「启明星」「启航」「启程」「启发」；是「打开 / 点亮 / 开始」的动作。对应公司使命「让 AI 成为中小企业的经营能力」——AI 不是替代，而是**启**。
- **营**：经营 / 运营；平台的主战场。
- **合起来**：**启营 = 把经营打开 / 让经营被开启**；不是「又一个软件」，而是「把经营能力交到中小企业手里」。
- **与公司名**：「词元」是 AI / token 的底座，「启营」是产品品牌；「词元·启营」可作技术背书，日常只说「启营」。
- **角色故事**：**启营开店，客服接客，参谋出策。** 一句话讲完一套产品。

### 3.4 品牌架构

| 层级 | 名字 | 说明 |
|---|---|---|
| 公司 / 法律主体 | 词元通达 | 保留；合同 / 发票 / 官网主体 |
| AI / 技术品牌 | 词元 | token / AI 底座；可选背书「词元·启营」 |
| 产品 / 平台 | **启营** | 用户唯一需要记住的品牌 |
| 顾客侧角色 | 启营客服 | 原米宝；功能称呼，不单独做品牌 |
| 经营侧角色 | 启营参谋 | 原黄金策；功能称呼，不单独做品牌 |
| 退役 | 米高智能 / 观星台 / 米宝 / 黄金策 | 不再作为对外产品名；历史记录保留 |

> **不新增第五个品牌。** 第二轮提案 §5.3 曾把「布掌柜」作为布艺垂直子品牌；按本轮「统一标识」的要求收窄：布掌柜不再作为品牌，只作为布艺行业版的描述词（如「启营·布艺版」），避免又回到多品牌。

### 3.5 口号

- 启营——让 AI 成为每一家中小企业的经营能力。
- 启营——AI 时代的经营操作系统。
- 启营开店，客服接客，参谋出策。
- 一个启营，接客、算料、管店、参谋全都有。
- 启营——让规模不再是经营能力的边界。

## 4. 备选方案

### 4.1 「启」家族（人格化备选）

- **启营 / 启宝 / 启策**：共享首字「启」；平台 / 顾客 / 经营三角色。
- **优点**：三个名字一听就是一家；Agent 保留人格化；口口传播时有「启宝」「启策」两个记忆点。
- **代价**：三个品牌要分别做商标 / 小程序 / 域名；**启营第 9 类已有含「启营」的商标公告，启策第 42 类已有商标**；启宝第 3 / 5 类 / 教育同名多。三件都要清，难度明显高于单品牌。
- **适合**：如果团队认为「一个启营」太素，愿意为 Agent 人格化多付注册 / 迁移成本。

### 4.2 「元」家族（公司-root 备选）

- **元营 / 元宝 / 元策**：共享「元」，最贴公司「词元」。
- **优点**：公司-root 最顺；「元」有 origin / token 的深意。
- **代价**：「元宝」是通用货币词，商标拥挤；「元营」偏抽象；「元策」像咨询公司。三个都要清。
- **适合**：如果团队希望产品名直接继承「词元」的 AI 资产，且不介意「元宝」的货币联想。

### 4.3 其他家族（为什么不推荐）

- **知行家族**：知行 / 知宝 / 知策；文化好，但「知行」商标拥挤，且不接公司愿景。
- **明家族**：明营 / 明宝 / 明策；明亮，但「明宝」「明策」都有同名品牌 / 公司。
- **智家族**：智营 / 智宝 / 智策；直白，但太常见，不像大品牌。
- **星家族**：观星台 / 星宝 / 星策；旧平台名是问题本身，不推荐。

## 5. 评分与门槛

| 方案 | 一个品牌 | 好听 / 响亮 | 立意 | 角色可辨 | 差异 / 可注册 | 结论 |
|---|---|---|---|---|---|---|
| **单品牌「启营」** | ✅ | ✅ | ✅ | ⚠️ 角色名偏功能 | ⚠️ 启营 9 类有公告；9 / 42 待清 | **推荐（最统一）** |
| 启家族 | ⚠️ 三个名 | ✅ | ✅ | ✅ | ⚠️ 启营 9 类 + 启策 42 类 + 启宝待查 | 备选（人格化） |
| 元家族 | ⚠️ 三个名 | ✅ | ✅ | ✅ | ⚠️ 元宝通用词；三个都要清 | 备选（公司-root） |
| 旧四名 | ❌ | ⚠️ | ⚠️ | ❌ | ⚠️ | 退役 |

> 任何方案先过「品牌数量 + 无致命撞名 / 谐音」门槛，再谈分数。

## 8. 决策路径

1. **先选架构**：单品牌「启营」（推荐）/ 启家族（人格化）/ 元家族（公司-root）。
2. **再选平台名**：启营（品牌最贴）/ 元营 / 启能（见第二轮提案）；9 / 35 / 42 类检索。
3. **用户盲测**：5-10 位中小企业主；问「这是不是一个产品？你记得住吗？」。
4. **选定后开改名单**：一次改完；参照 #6525。
5. **旧名退役**：米高智能 / 观星台 / 米宝 / 黄金策不再对外；历史记录保留。
