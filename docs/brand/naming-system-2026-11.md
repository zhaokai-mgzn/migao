# 一个「明营」：词元通达产品命名统一方案

> 2026-11-23 ｜ 状态：提案（未改名）｜ 关联 issue #9068
>
> 用户原话：「我们公司名称词元通达，我们的产品中产品名共出现了四个：米高智能、观星台、米宝、黄金策，这不利于用户对我们的产品建立统一标识形成用户心智口口传播。我想把名称统一一下，要求好听、响亮又立意深远，你有没有什么好的建议。」
>
> **2026-11-23 用户反馈：「启字系列都不好，换一个。」本版把第三轮的「启」系列改为「明」系列；启系列候选保留为历史。**
>
> 平台名的完整取舍见 `naming-proposal-vision-2026-11.md`（第二轮）；该轮的「启营」候选已被本次反馈否定，平台名改用「明营」。

## 0. 结论

**推荐：一个产品名「明营」，两个角色「明营客服 / 明营参谋」。**

| 角色 | 名字 | 旧名 | 说明 |
|---|---|---|---|
| 平台 / 产品 | **明营** | 米高智能 / 观星台 | 用户只需要记住的一个品牌 |
| 顾客侧 Agent | **明营客服**（角色名） | 米宝 | 明营里的顾客服务角色，不再单独背品牌 |
| 经营侧 Agent | **明营参谋**（角色名） | 黄金策 | 明营里的经营参谋角色，不再单独背品牌 |
| 公司 | **词元通达**（保留） | — | 公司 / 法律主体；「词元」是 AI 技术品牌 |

- 四个名字 → **一个品牌 + 两个角色**；用户说「明营」，就知道是这套产品。
- 如果团队希望两个 Agent 保留人格化名字，走备选 **「明」家族**：**明营 / 明宝 / 明策**（见 §4.1）。
- 如果团队想要公司-root 的家族，走备选 **「元」家族**：元营 / 元宝 / 元策（见 §4.3）。

**一句话：四个名字收成一个「明营」；明营管店，客服接客，参谋出策。**

## 1. 四个名字为什么不利

| 名字 | 命名逻辑 | 问题 |
|---|---|---|
| 米高智能 | 旧公司 / 产品名 + 泛描述 | 与「词元通达」不一致；「智能」是品类词，不像品牌 |
| 观星台 | 地点 / 天文台 | 不贴产品；用户听不懂「台」和自己生意的关系 |
| 米宝 | 可爱型 Agent 名 | 「米」来自旧品牌；与「黄金策」风格不搭 |
| 黄金策 | 古典 / 术数型 Agent 名 | 「黄金」= 钱，「策」= 术数 / 策略；与「米宝」不是一家人 |

四个名字 = 四种命名逻辑（旧品牌 / 地点 / 可爱 / 古典）。用户无法从名字看出它们属于同一家公司，更无法口口传播「这一个产品」。

**统一的目标不是「四个都改成一个字」，而是让用户听到「明营」就知道整套产品。** 角色名可以保留，但不再各自背品牌。

## 2. 命名标准

1. **一个品牌**：用户只需要记住一个名字。
2. **好听、响亮**：开口音 / 鼻音收尾，二到三字，连读顺口，无坏谐音。
3. **立意深远**：有经典 / 文化根，能讲出「AI 成为经营能力」的故事。
4. **角色可辨**：平台 / 顾客 / 经营三个角色，一听知道谁是谁。
5. **可延展**：未来加角色 / 行业，仍能在这一个品牌上生长。
6. **可注册**：9 / 35 / 42 类有空间；小程序 / 域名可查。

## 3. 推荐：一个「明营」

### 3.1 三个名字

| 名字 | 读音 | 字义 | 角色 | 一句话 |
|---|---|---|---|---|
| **明营** | míng yíng | 明 = 清明 / 明察 / 明德；营 = 经营 | 平台 / 产品 | 明营——让每一家中小企业的经营，看得清、算得明、走得远 |
| 明营客服 | míng yíng kè fú | 明营里的顾客服务角色 | 顾客侧 | 接客、算料、下单、售后 |
| 明营参谋 | míng yíng cān móu | 明营里的经营参谋角色 | 经营侧 | 问答、分析、经营建议 |

> 角色名是对外**功能称呼**，不是第二个品牌；海报 / 小程序 / App 上只出现「明营」。

### 3.2 为什么好听、响亮

- **两个字**：míng yíng，短、好记、好打；适合口口传播、小程序名、App 名、招牌。
- **声母 + 韵母**：míng 是鼻音收尾，明亮、有余音；yíng 也是鼻音，两个字连读有「明—营」的回响。
- **声调**：二声 + 二声，平稳、笃定，不像「启」那么用力，也不像「观星台」那么飘。
- **无坏谐音**：正向谐音「明赢」（明明白白地赢）可做辅助；「明营」不是常用词，不会被读成负面词。
- **可喊**：两个字都开口，适合展会 / 电话 / 短视频里喊出来；比「观星台」「黄金策」短，比「米宝」稳。

### 3.3 为什么立意深远

- **明**：明亮、清明、明察、明德、明镜。它是「看得清」——账目清、进度清、成本清、边界清。
- **营**：经营 / 运营；平台的主战场。
- **合起来**：**明营 = 让经营看得清、算得明、走得远**。这不是「又一个软件」，而是「把经营摆到明面上」。
- **产品对应**：数据同源、可审计、口径卡先审核、AI 边界写明——这些产品事实，正好是「明」。
- **与公司名**：「词元」是 AI / token 的底座，「明营」是产品品牌；「词元·明营」可作技术背书，日常只说「明营」。
- **角色故事**：**明营管店，客服接客，参谋出策。** 一句话讲完一套产品。

### 3.4 品牌架构

| 层级 | 名字 | 说明 |
|---|---|---|
| 公司 / 法律主体 | 词元通达 | 保留；合同 / 发票 / 官网主体 |
| AI / 技术品牌 | 词元 | token / AI 底座；可选背书「词元·明营」 |
| 产品 / 平台 | **明营** | 用户唯一需要记住的品牌 |
| 顾客侧角色 | 明营客服 | 原米宝；功能称呼，不单独做品牌 |
| 经营侧角色 | 明营参谋 | 原黄金策；功能称呼，不单独做品牌 |
| 退役 | 米高智能 / 观星台 / 米宝 / 黄金策 | 不再作为对外产品名；历史记录保留 |

> **不新增第五个品牌。** 第二轮提案 §5.3 曾把「布掌柜」作为布艺垂直子品牌；按「统一标识」的要求收窄：布掌柜不再作为品牌，只作为布艺行业版的描述词（如「明营·布艺版」），避免又回到多品牌。
>
> 第三轮的「启」系列（启营 / 启宝 / 启策）已按用户 2026-11-23 反馈撤下，不再作为主推；见 §4.4。

### 3.5 口号

- 明营——让每一家中小企业的经营，看得清、算得明、走得远。
- 明营——AI 时代的透明经营平台。
- 明营管店，客服接客，参谋出策。
- 一个明营，接客、算料、管店、参谋全都有。
- 明营——让经营，从经验走向明算。
- 明营——把经营，摆到明面上。

## 4. 备选方案

### 4.1 「明」家族（人格化备选）

- **明营 / 明宝 / 明策**：共享首字「明」；平台 / 顾客 / 经营三角色。
- **优点**：三个名字一听就是一家；Agent 保留人格化；「明宝」「明策」有记忆点。
- **代价**：三个品牌要分别做商标 / 小程序 / 域名；「明宝」「明策」是常见词，商标可能拥挤；三件都要清。
- **适合**：如果团队认为「一个明营」太素，愿意为 Agent 人格化多付注册 / 迁移成本。

### 4.2 「知」家族（文化备选）

- **知行 / 知宝 / 知策**：知 = 知道 / 认知；「知行」= 知道 + 执行，正好对应 AI Agent 的「知」与「行」。
- **优点**：文化厚度最好；「知行合一」人人能懂。
- **代价**：「知行」是超级常见词，商标极拥挤；平台名「知行」很难清；知宝 / 知策也有同名。
- **适合**：如果团队把「文化感」放在「可注册」之前，可作为讨论项；不建议作为首选。

### 4.3 「元」家族（公司-root 备选）

- **元营 / 元宝 / 元策**：共享「元」，最贴公司「词元」。
- **优点**：公司-root 最顺；「元」有 origin / token 的深意。
- **代价**：「元宝」是通用货币词，商标拥挤；「元营」偏抽象；「元策」像咨询公司。三个都要清。
- **适合**：如果团队希望产品名直接继承「词元」的 AI 资产，且不介意「元宝」的货币联想。

### 4.4 「启」系列（已按用户反馈撤下）

- 第三轮曾推 **启营 / 启宝 / 启策**；用户 2026-11-23 反馈「启字系列都不好，换一个」。
- 事实：启营第 9 类已有含「启营」的商标公告；启策第 42 类已有商标；启宝第 3 / 5 类 / 教育同名。
- 结论：不再作为主推；保留为历史记录，避免后来者重复踩坑。

## 8. 决策路径

1. **先选架构**：单品牌「明营」（推荐）/ 明家族（人格化）/ 知家族（文化）/ 元家族（公司-root）。
2. **再选平台名**：明营（首选）/ 知营 / 元营；9 / 35 / 42 类检索。
3. **用户盲测**：5-10 位中小企业主；问「这是不是一个产品？你记得住吗？」。
4. **选定后开改名单**：一次改完；参照 #6525。
5. **旧名退役**：米高智能 / 观星台 / 米宝 / 黄金策不再对外；历史记录保留。
