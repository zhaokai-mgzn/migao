## 1. 术语对照（本文的**结论**，供界面与文档直接引用）

| 仓库分组（`production_operations.group_name`） | **行业正名**（本文依据） | 行业职责（逐字引文，见 §2） |
|---|---|---|
| **裁剪** | **裁床** | 复核收到的布料 → 裁剪 → **按套件打捆** → 发放给**车位** |
| **车位** | **车位** | 负责布艺产品的**缝制**；缝制中如需**中烫** ⇒ 找烫工处理**再取回继续缝** |
| **后道** | **烫工及后整**（+ **质检** + **包装**） | 「**不可缺少的辅助工序**」；**质检贯穿全过程**；**包装是最后一道工序** |
| **其他** | （无对应） | 配套软装件（绑带 / 抱枕 / 腰靠垫）—— 非本文档范围 |

> ⚠️ **「后道」是 ERP 简称**，行业正名是「**烫工及后整**」。
> ⇒ **界面第一层用行业术语**（**裁剪 / 车位 / 后整 / 质检**），**不许**用「槽位」这类**我们发明的词**
> （用户裁定，2026-09-20；见 `docs/design/ai-craft-config.md` §2.5 的口径收窄）。
> ⚠️ **车间三段** = **裁床 / 车位 / 烫工及后整** —— 它是判断「某道活是不是**工序**」的标尺：
> **不在车间三段里** ⇒ 不是工序（`配料` 即据此退场，见 §3）。

## 2. 逐字引文（只摘与术语定义相关的段落）

> 标注约定：引号内为**逐字引文**；「…」为**原文省略号**；方括号 `［］` 内为**本仓库的说明**，非引文。

### 2.1 裁床（裁剪）

- 「**裁床**…**复核收到的布料**，确认无误后方能进行**裁剪**」
  ⇒ ［说明］裁床的职责 = **复核布料 → 裁剪**；**卖布（按米）在车间就是裁床按米裁**。
- 「…**按套件打捆**…**发放给车位**缝制」
  ⇒ ［说明］裁剪的**输出形态** = **按套件打捆**；裁剪的**下游** = **车位缝制**。
- 「**专职收发人员**将领用的物料，应按加工单所列套件进行**物料分配**…**分发给裁床**」
  ⇒ ［说明］「**物料分配**」是**收发人员**的活，**不在车间三段里** ⇒ **不是工序**
  （这是 `配料` 退场的依据，见 §3）。

### 2.2 车位（缝制）

- 「**车间车位**负责布艺产品的**缝制**」
- 「［缝制中］如需**中烫** ⇒ 找**烫工**处理**再取回继续缝**」
  ⇒ ［说明］车位与烫工之间存在**工序间往返**（中烫）；这是「车位 / 烫工」**两道不同活**的证据。

### 2.3 烫工及后整 + 质检 + 包装

- 「**不可缺少的辅助工序**」［指烫工及后整］
- 「**质检贯穿全过程**」
- 「**包装是最后一道工序**」
  ⇒ ［说明］⇒ **质检不是一个固定位置**（它是**检验点**，可出现在多个位置）；
  **包装是终点**。两条都直接影响工序顺序的建模。

## 4. 由本文得出的两条**已被用户裁定**的口径

1. **`配料` 不是工序 ⇒ 退场**：它在行业里对应「**物料分配**」（§2.1 第三条引文），是**收发人员的活**；
   ⇒ 布料单的加工工序改为 **`裁剪`**（用户裁定逐字：「**是裁剪**」）。
   实施单 = issue **#4676**（迁移 **V88**）。
2. **`打包` 计件 ⇒ 必须留在表里**（用户裁定逐字：「**打包需要计件**」），
   但它**不改变产品** ⇒ 归**交付环节**（与「加工工序」分层）。

⇒ 因此 **布料单 = `裁剪` + `打包`**（旧口径 `配料` + `打包` **已作废**，
回改见 `docs/design/craft-calc-and-fabric-routing.md` 的判据 #10 及其「口径变更」注）。
