# 终端壳差异验收矩阵（issue #8609 **C 包**）

> 一句话：**同一份业务面，跑遍所有壳档案** —— 页面显隐的差异**只允许**来自本机能力
> （`window.migaoTerminal.capabilities`），不允许来自「这是 Windows / 这是安卓」这类设备类型判断。
> 判据真值 = `frontend/worker-h5/tests/worker-h5-8609-shell-matrix.test.mjs`（本文件是它的**人读矩阵**，
> 两者由元守卫 d 钉在同一份档位清单上：文档缺档名 ⇒ 判据红）。
> 迁移期三态（`absent` / `unknown` / `present`）与 fail-closed 主体在 B 包
> （`frontend/worker-h5/tests/worker-h5-8609-capabilities.test.mjs`，**本包不重造**）。

口径来源（用户 2026-11-04 逐字三条，同一次裁定）：
「安卓一体机和 window 一体机功能完全一样，也有串口和下发动作」/「手持标签机不需要裁高计算/下发」/「接受，我也希望一个包搞定」。

## 1. 形态：一份业务面 + 两个薄壳 + 一个 apk

- **业务面只有一份**：`https://app.migaozn.com/w/`（worker-h5）。exe / apk 都只是壳，壳只做
  WebView 宿主 + 能力桥 + 串口/蓝牙/更新，**不把业务搬进壳**。
- **菜单 = 三轴与**：`users.worker_pages`（第一轴）∩ 租户页面开关 ∩ **本机 capabilities**（第三轴，issue #8609）。
  三轴里只有第三轴是「同一账号在两台机器上看到不同菜单」的合法原因 —— 不按工人账号拆菜单
  （同一工人今天一体机、明天手持机 ⇒ 写进账号 = 运维灾难，issue 边界「有意不做」）。
- **一个 apk 覆盖两种安卓设备**：手持标签机与安卓一体机同一个安装包，靠运行时能力探测收敛菜单。

## 2. 设备档案矩阵（档 × 能力 × 期望入口）

| 档案 id | 桥形态 | 三态 | 关键能力 | 裁高计算入口 | 打印入库标签 |
|---|---|---|---|---|---|
| `windows-all-in-one` | `{ capabilities }` | `present` | `cut.link=serial:COM3`、`scan.camera=true`、`update.channel=exe` | ✅ | ❌ |
| `android-all-in-one` | `{ capabilities }` | `present` | `cut.link=serial:/dev/ttyS1`、`scan.camera=true`、`update.channel=apk` | ✅ | ❌ |
| `handheld-label` | `{ capabilities }` | `present` | `cut.link=null`、`print.label=ble` | ❌ | ✅ |
| `old-shell-1.0.2` | `{ post }`（无能力表） | `unknown` | 能力未知 | ✅（迁移期：未知 ≠ 没有） | ✅（同上） |
| `no-shell` | 整块缺失 | `absent` | 真没有串口/蓝牙 | ❌ | ❌ |

- `windows-all-in-one` 与 `android-all-in-one` **功能逐项一致**：两者唯一的能力差异是
  `cut.link` 的**凭据串**（`serial:COM3` ⇄ `serial:/dev/ttyS1`）与更新通道（`update.channel`，无 UI 面）。
- 期望入口**不是按档名手写的业务真相**：它由台账按能力逐档复算（`capabilityShown`），
  档位期望与能力判定对不上 ⇒ 判据红（防「矩阵变成第二份真值」）。
- `print.label` 的取值**不是白名单**（`ble` / `builtin` / 其它非空字符串都算能打，判据 MC-234 已钉）。

## 3. 同一批页面面（五档 × 五面）

同一批判据跑遍每一档，每一面只判「本屏**能**出现的硬件入口」：

| 页面面 | 非硬件锚点 | 可出现的硬件入口 |
|---|---|---|
| 登录卡（无页头） | `#wh5-login` | （无 —— 连能力表都不该在这一屏凭空造入口） |
| 扫码页 | `#wh5-scan-hint` | 裁高计算（页头入口栏） |
| 选套 / 部位 | `#wh5-legacy-hint` | 裁高计算 |
| 报工（工序已定 + 成品入库卡） | `#wh5-set` | 裁高计算 + 打印入库标签 |
| 报工（工序未确定 + 成品入库卡） | `#wh5-no-operation` | 裁高计算 + 打印入库标签 |

**「差异只允许来自 capabilities」的可判形态**：把两个硬件入口块（`#wh5-machine-entry` 与
`#wh5-fi-print` 所在的 action 行）剥掉、把能力凭据串归一后，**五档 × 五面渲染必须逐字相同**。
任何「按端 / 按档分叉」的渲染（端名文案、端专属提示、端专属分支）都会当场红。
剥离自身的非空转由判据自证：有入口 ⇒ 剥离必须真的变短；没入口 ⇒ 一个字节都不许动。

## 4. 失败形态矩阵（串口 × 蓝牙 × 摄像头，2³ = 8 组）

| 串口 | 蓝牙 | 摄像头 | 裁高计算 | 打印入库标签 | 其余面 |
|---|---|---|---|---|---|
| 在 | 在 | 在 | ✅ | ✅ | 报工可用、不整页禁用 |
| 在 | 在 | 不在 | ✅ | ✅ | 同上（摄像头零影响） |
| 在 | 不在 | 在 | ✅ | ❌ | 同上 |
| 在 | 不在 | 不在 | ✅ | ❌ | 同上 |
| 不在 | 在 | 在 | ❌ | ✅ | 同上 |
| 不在 | 在 | 不在 | ❌ | ✅ | 同上 |
| 不在 | 不在 | 在 | ❌ | ❌ | 同上（不整页禁用：报工按钮在且未禁用） |
| 不在 | 不在 | 不在 | ❌ | ❌ | 同上 |

- **缺省 = 隐藏（fail-closed）**：没有该能力 ⇒ **不渲染**入口（不是点了再报错）。
- **无硬件不阻断其它功能**：裁高机 / 标签机都缺席时，报工按钮、套号部位、返工入口、成品入库信息面照旧。
- **三态语义不变**（B 包已定，本包不改）：`unknown`（旧壳，桥在无能力表）= **未知 ≠ 没有** ⇒ 两条都渲染；
  `absent`（无壳）= 真没有 ⇒ 两条都不渲染。

## 5. 负向：三条没有 UI 面的能力键

`scan.hid` / `scan.camera` / `update.channel` 在 `/w/` 上**没有任何 UI 差异**（扫码是键盘楔，
扫码枪与摄像头在页面看来一样；更新通道是壳自己的事）⇒ **有意不进能力台账**（读了不用 = 假轴）：
对这三键注入任意取值（在场 / 缺省 / `null` / 布尔 / 空串 / 数字 / 数组 / 对象 / 怪字符串）
⇒ 五个页面面渲染**逐字不变**、能力读取器不变。给其中一键加一条 UI 分支 ⇒ 当场红。

## 7. 本仓能测 / 本仓测不了（边界，照实登记）

**本仓能测（已机械化）**：页面面渲染（入口集合、非硬件面逐字、两端逐字等价、2³ 组合、三态语义）、
能力台账与文档的同源（元守卫 d）。

**本仓测不了（`migao-terminal` / 真机负责，本包不伪造可测性）**：

| 测不了的项 | 归属 | 为什么本仓测不了 |
|---|---|---|
| 真实串口下发（Modbus RTU 帧：9600 / 8E1 / 寄存器 / CRC 逐字节） | A 包 `zhaokai-mgzn/migao-terminal` | 需要裁高机与串口适配器真机；本仓只有页面渲染 |
| USB-OTG 串口自动发现 / USB 权限弹窗 / 错误分类（`connected:<port>` / `error:<code>`） | A 包（终端仓） | 依赖 Android 运行时与真实适配器 |
| 单 apk 打包 + 一个包覆盖两种安卓设备（同一 APK 哈希两种菜单） | A 包（终端仓） | 需要构建产物与真机安装 |
| 更新通道（exe 读 `/terminal/latest.json`、apk 读 `/terminal/android/latest.json`） | A 包（终端仓）+ 发布侧 | 需要真实发布清单与设备 |
| 壳把能力注入 `window.migaoTerminal.capabilities`（桥的真实形态 / 注入时机） | A 包（终端仓） | 本仓只能**模拟**桥形态（判据 ⑤ 的五档） |
| 真浏览器 / 真机四场景复探（同一账号、两台设备、菜单差异只来自能力） | 集成侧 + 真机 | 需要真实设备与已部署产物 |

⚠️ 页面侧**有意不做**：`cut.link` 三态里 `error:<code>` 的「可读原因 + 下一步」呈现
（现按「非空字符串 = 有能力」判定）—— 属 A 包到设备后另派包，不在本包。

## 8. 重启条件（什么时候回来复探 / 收口）

A 包（`zhaokai-mgzn/migao-terminal`）的 `capabilities` 能力桥**全量到达设备之后**：

1. **真机复探四场景**（同一 apk、两台设备、同一账号、同一份全开页面集，只改桥形态）：
   手持标签机 = 无裁高 / 有打印；安卓一体机 = 有裁高 / 无打印；旧壳 = 两条都在；无壳 = 两条都没有。
2. **收掉迁移期分支**：把 `CAP_STATE_UNKNOWN` 并入 `CAP_STATE_ABSENT`，同批把 B 包判据 ①′ 从
   「两条都在」改成「两条都隐藏」，并删掉本矩阵的 `old-shell-1.0.2` 档（元守卫 d 的档位清单同批改）。
3. 真机取到 `cut.link` / `print.label` 的实际取值后，核对本矩阵第 2 节的凭据串与能力键是否与壳一致
   （取值不是白名单；`builtin` 已在 MC-234 覆盖）。

## 9. 有意不做 + 若要新增 UI 能力轴

- ❌ 不按**工人账号**拆菜单（差异只能来自本机能力）。
- ❌ 不合并两条更新通道（版本号可以不同，业务面必须一致）。
- ❌ 不新造第二份页面真值（页面显隐仍由 H5 一份实现，壳只报能力）。
- ❌ 本包**不新造 UI 能力轴**：`scan.hid` / `scan.camera` / `update.channel` 有意没有页面面。
  若某个键将来确实需要 UI 面（例如「摄像头扫码」按钮），**必须先裁定**（会改 B 包判据面与台账契约），
  再按顺序做：台账新增键（必须有 UI 面）→ 本矩阵新增档/组合与期望 → 对应负向判据同步收窄。
  本文件的负向判据变红 = **停手信号**，不是「放宽一下」。
