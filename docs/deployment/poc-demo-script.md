# 米高 POC 演示脚本（30 分钟版）

> 面向窗帘加工/布料批发老板（决策人）的现场演示脚本。
> 目标：30 分钟内让老板看到"AI 替我接客、算料、成交"，并算清 ROI。

## 演示前准备（前一天）

- [ ] 部署最新代码（admin-api + ai-agent-service + admin-web）
- [ ] 执行演示数据 seed：`psql "$DATABASE_URL" -v tenant_id=1 -f docs/deployment/demo-seed.sql`
- [ ] 配置 `SMS_BYPASS_CODE=123456`（与 admin-api `sms.bypass-code` 对齐，POC 阶段验证码 bypass）
- [ ] 注册演示租户 + 微信小程序绑定
- [ ] 准备两台手机：一台当"顾客"（小程序），一台当"老板"（管理后台/米宝）
- [ ] 预跑一遍完整链路，记录耗时

## 脚本（30 分钟）

### 第 1 幕：开场 · 痛点共鸣（2 分钟）
- **话术**："您店里一天接多少个咨询？夜里、忙时漏了多少单？报价算料是不是还得靠老手算半天？"
- 一句话定位：**米高 = 窗帘店的 AI 接单员 + 算料师傅 + 记账员，7×24 不休息**

### 第 2 幕：小布 AI 客服 · 算料报价（8 分钟，核心）
- 演示"顾客"手机小程序，对话：
  1. 顾客："3米宽的窗，2倍褶皱，遮光布，帮我算下要多少钱"
  2. 小布 → 路由算料 → 报价单卡片（面料 6.6 米、明细、总价）
  3. **对比**：让老板现场手算同一单，验证 AI 算得对、算得快
- 加戏：顾客换"2.7 米高窗" → 小布自动识别"超定高上限"，改定宽布并提示——**展示行业专业性**（这是通用 SaaS 做不到的）
- 金句："褶皱倍数、门幅、对花损耗，这些老师傅脑子里才有的经验，米高都装进去了"

### 第 3 幕：小布下单闭环（5 分钟）
- 顾客点报价单"确认下单" → 小布收集姓名/手机号 → 确认卡片 → 输入验证码（123456）→ 下单成功
- 老板手机管理后台：**订单列表实时出现新订单**（"生产中"状态）
- 金句："从咨询到成交，一条龙，顾客不用等，您不用守"

### 第 4 幕：米宝 B 端助手 · 问数（3 分钟）
- 老板（后台）对米宝说："这个月哪个花色卖得最好？谁欠款最多？"
- 米宝 → 数据分析卡片
- 金句："以前查账翻 Excel 半小时，现在一句话"

### 第 5 幕：图片识别 · 拍照找布（3 分钟）
- 顾客拍一张窗帘照片："这款有吗？"
- 小布识别颜色/风格 → 推荐相似商品
- 金句："客户发的图，AI 一眼认出来，还能推同款"

### 第 6 幕：后台看板 + ROI 测算（5 分钟，促单）
- 展示：数据看板（今日订单/营收/转人工率）、商品 SKU 矩阵、订单生命周期
- **算钱**（用客户真实数字填空）：
  - 省人工：AI 接单省客服 × 小时/天 = ¥X/月
  - 少漏单：夜里/忙时漏单 × 单/月 × 客单价 = ¥Y/月
  - 回款快：赊账台账 + 催款提醒提速 × 天 = 现金流 +¥Z
- 收尾："¥1999/月起，第一单漏单就回本了。今天签约，1 周上线"

### 第 7 幕：答疑 + 部署承诺（4 分钟）
- 常见问题：
  - "怎么接入微信？" → 小程序 + 企业微信/公众号（POC 后上线）
  - "布料怎么录？" → 拍照建档 / Excel 导入 / 米宝对话录入
  - "不会用怎么办？" → 零培训，手机微信就能用，我们上门实施

## 演示风险与应对

| 风险 | 应对 |
|---|---|
| 网络慢 / LLM 延迟 | 提前预热，备好录屏兜底 |
| AI 答非所问 | 预演 3 遍固定话术，现场只走脚本内问题 |
| 算料数字被质疑 | 提前用真值算例核对，现场让老板手算验证 |
| 演示数据太假 | seed 用真实感数据（林女士/王先生 + 真实商品） |
