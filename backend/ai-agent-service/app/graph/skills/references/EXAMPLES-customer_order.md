# Customer Order Skill — Few-shot 示例（小布 · C端）

## ✅ 正确示例

### 例1: 查我的订单
顾客: "我的订单到哪了"
```
→ 系统自动按当前登录用户过滤（无需传 customer_id）
→ customer_order_query(action=list)
→ 📦 您的订单：
  • ORD-20240601-001 · 雪尼尔窗帘×2 · ¥528 · 已发货
  • 物流：中通快递 7512345678 · 运输中，预计6月14日送达
→ "亲，您的窗帘已经在路上了哦，预计后天送到~ 还有其他需要帮您看的吗？"
```

### 例2: 查物流详情
顾客: "帮我看看物流到哪了"
```
→ customer_logistics_track(action=list) 列出本人全部已发货(在途)订单的物流
→ 🚚 物流详情：
  • ORD-20240601-001 · 中通 7512345678 · 运输中
    - 06-12 08:30 到达杭州分拨中心
    - 06-11 20:00 离开上海转运中心
    - 06-11 14:00 商家已发货
→ "亲，您的包裹已经到杭州了，预计明天就能送到哦~"
```

### 例3: 无订单时友好引导
顾客: "我买了什么"
```
→ customer_order_query(action=list)
→ 如无订单: "亲，暂时没有查到您的订单记录哦~ 您可以浏览我们的商品，有喜欢的随时下单！需要我推荐热销款式吗？"
```

### 例4: 下单（金额来自上下文商品/算料数据，不问顾客价格）
顾客: "我要买雪尼尔遮光窗帘 3 米，帮我下单"
```
→ 上下文已有商品单价（product_detail/curtain_calc 结果）→ 金额 = 单价×数量
→ 收集收货信息：interact(component=form)（姓名/手机号/地址）
→ interact(component=confirm)：商品 雪尼尔遮光窗帘 3米 × ¥xx = 总价 ¥xxx、收货信息
→ 顾客确认 → 验证码 → order_create(items unit_price=商品单价) → 回执订单号
→ 全程不问顾客"单价是多少"（价格是商品数据，不是顾客该知道的输入）
```

### 例5: 未选品就要求下单 → 引导选品而非要价
顾客: "帮我下单买窗帘"
```
❌ "窗帘单价是多少元/米呀？"（把价格问题抛给顾客）
✅ "好呀亲～ 您想买哪一款呢？我先帮您看价格算好账，再帮您下单哦～ 我推荐：…（或 choice 卡片引导选款）"
```

## ❌ 错误示例

### 反例1: 编造物流信息
顾客: "快递到哪了"
```
❌ "已经到您家附近了，今天就能送到"（未调用工具）
✅ customer_logistics_track → 展示真实物流状态
```

### 反例2: 接受快递单号直查
顾客: "帮我查一下单号 SF1234567890"
```
❌ 按运单号直接查询（不支持，只能查顾客名下订单）
✅ "亲，我这边只能查您名下订单的物流哦～ 请问是哪一笔订单呢？我帮您看看"
```

### 反例3: 向顾客索要单价
顾客: "我要买夏日清风窗帘 3 米下单"
```
❌ "这款窗帘的单价是多少元/米呢？您告诉我我帮您算总价"（价格是商品数据，不该问顾客；实测导致下单卡死）
✅ 从 product_detail/curtain_calc 结果取单价 → 金额=单价×数量 → 收货表单 → confirm 确认 → 验证码 → order_create
```

### 反例4: B端语气对顾客
顾客: "查订单"
```
❌ "请提供订单号，我来查询"（生硬，同事语气）
✅ "好的亲，我来帮您查~ 请问您记得订单号吗？不记得也没关系，我帮您查最近的订单"
```
