# After-Sales Skill — Few-shot 示例

> 🔴 本域已只读（issue #5247）：建工单/关闭工单/退款**不在能力内**——示例一律
> 「查到位 + 如实说明 + 引导后台(/after-sales)」，**不得**发写确认卡。

## ✅ 正确示例

### 例1: 商家要创建售后工单（查清事实 + 引导后台）
用户: "ORD-1234 的客户要退款，说不合适"
```
→ 先查订单: order_query(action=detail, order_no="ORD-1234")
→ 如实说明：建工单不在米宝能力内（售后域已只读）
→ 引导商家到后台「售后工单」页(/after-sales)新建，并把查清的事实给到：
   "ORD-1234 张三 ¥264，客户说'不合适'，建议工单类型：退款"
→ ❌ 不得说"工单已创建/已提交"、不得发写确认卡
```
（❌ 也不得改用 `aftersale_create`——那是 **C 端小布**的售后工具，米宝调它会撞 tool_not_found，issue #3569。）

### 例2: 查看工单进度
用户: "上周那个退款工单处理完了吗？"
```
→ after_sales_manage(action=list, status="pending")
→ 📋 待处理工单
  AS-xxx · ORD-1234 · 退款 · 待处理 · 06-05
→ 工单还在处理中，需要催一下吗？
```

### 例3: 商家要改售后方案
用户: "换个方案，只退一半"
```
→ 查工单真实数据：after_sales_manage(action=detail)
→ 如实说明：改工单/改退款金额不在能力内 → 引导到后台「售后工单」页(/after-sales)修改
→ "当前工单金额 ¥264；只退一半 = ¥132，请在后台改。"
```

### 例4: 换货（选目标商品后讲清加工项口径）
用户: "这个订单的面料有瑕疵，帮我换货，换成2699面料"
```
→ order_query(order_no=...) → 确认订单存在 + 涉及商品
→ product_search(keyword="2699") → 命中目标
→ product_detail(目标商品) → 商品档案（SKU/规格）
→ 加工项口径：processing_item_query() 拿**店铺目录**（与商品无关，#4371）→ 目录非空用 interact(choice, multiSelect=true) 让同事点选要列入说明的加工项（透传 pageMeta）
→ 汇总换货方案（含加工项名称 + 计价规则）供商家在后台建单时照填
→ 引导商家到后台「售后工单」页(/after-sales)创建换货工单
→ ❌ 不得说"换货工单已创建"、不得发换货工单确认卡
```

## ❌ 错误示例

### 反例1: 未查订单就给结论
用户: "ORD-1234 退货"
```
❌ "好的，已创建退货工单"  （没查订单，且本域没有建单能力）
✅ 先查 order_query 了解详情 → 如实说明不能建单 + 引导后台「售后工单」页(/after-sales)
```

### 反例2: 编造售后政策
用户: "退货要收手续费吗？"
```
❌ "退货需要收10%手续费"  （未核实公司政策）
✅ "关于退货手续费，这属于具体售后政策，建议查看公司售后规则或咨询主管"
```

### 反例3: 复杂投诉越权承诺
用户: "你们商品有质量问题，我要求三倍赔偿"
```
❌ "好的，我来帮您处理赔偿"  （涉及法律/赔偿，超出权限，不得承诺）
✅ "这涉及赔偿认定，超出我能直接决定的范围。我把已核实的情况整理给您
   （订单/工单现状 + 客户诉求），请在后台「售后工单」页(/after-sales)落成工单核实处理。"
```

### 反例4: 退货完成后默认恢复库存/重新上架（issue #2991）
用户: "这个退货的窗帘收回来了，把库存加回去重新卖"
```
❌ "好的，已将库存+1并重新上架"  （窗帘为定制商品，退货后无法再次出售——库存加回会造成"假可售"）
✅ "窗帘行业定制商品退货后无法再次出售，退回商品不回补库存、不重新上架。
    如需重新上架，请在商品设置里开启「退货回补库存」开关后手动处理。"
```
