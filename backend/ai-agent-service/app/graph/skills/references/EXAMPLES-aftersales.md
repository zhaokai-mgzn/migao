# After-Sales Skill — Few-shot 示例

## ✅ 正确示例

### 例1: 创建售后工单
用户: "ORD-1234 的客户要退款，说不合适"
```
→ 先查订单: order_query(action=detail, order_no="ORD-1234")
→ 了解订单详情后确认问题
→ ask: "请确认退款原因和金额？订单金额¥264，客户说'不合适'"
→ 用户: "全退，金额264"
→ confirm: "确认创建退款工单？ORD-1234 张三 ¥264 原因:不合适"
→ after_sales_manage(action=create, ...) → "工单已创建 AS-xxx"
```

### 例2: 查看工单进度
用户: "上周那个退款工单处理完了吗？"
```
→ after_sales_manage(action=list, status="pending")
→ 📋 待处理工单
  AS-xxx · ORD-1234 · 退款 · 待处理 · 06-05
→ 工单还在处理中，需要催一下吗？
```

### 例3: 修改售后方案
用户: "换个方案，只退一半"
```
→ 识别修正意图 → 更新 reason/amount
→ "好的，已更新退款方案：退款¥132（50%）。确认创建工单？"
```

### 例4: 换货（选目标商品后必须确认加工项）
用户: "这个订单的面料有瑕疵，帮我换货，换成2699面料"
```
→ order_query(order_no=...) → 确认订单存在 + 涉及商品
→ product_search(keyword="2699") → 命中目标
→ product_detail(目标商品) → 档案含 processing_items（若有加工项）
→ **加工项环节（confirm 前必做）**：interact(choice, multiSelect=true) 展示目标商品加工项
   （透传 pageMeta；processing_items 为空则告知"该商品无可用加工项"继续）
→ 用户: "波浪定型 + 双折边" / "不需要加工项"
→ 汇总换货方案（含加工项名称+计价，写入 description）
→ confirm: "确认创建换货工单？…换货目标 2699面料 加工项：波浪定型 ¥8/米"
→ after_sales_manage(action=create, ticket_type="exchange", ...) → "换货工单已创建 AS-xxx"
```

## ❌ 错误示例

### 反例1: 未查订单直接处理
用户: "ORD-1234 退货"
```
❌ "好的，已创建退货工单"  （没查订单详情）
✅ 先查 order_query → 确认订单存在 + 了解详情 → 再处理
```

### 反例2: 编造售后政策
用户: "退货要收手续费吗？"
```
❌ "退货需要收10%手续费"  （未核实公司政策）
✅ "关于退货手续费，这属于具体售后政策，建议查看公司售后规则或咨询主管"
```

### 反例3: 复杂投诉不转人工
用户: "你们商品有质量问题，我要求三倍赔偿"
```
❌ "好的，我来帮您处理赔偿"  （涉及法律/赔偿应转人工）
✅ "这涉及赔偿问题，需要人工客服介入处理。我会帮您记录情况并转交专人跟进。"
```

### 反例4: 退货完成后默认恢复库存/重新上架（issue #2991）
用户: "这个退货的窗帘收回来了，把库存加回去重新卖"
```
❌ "好的，已将库存+1并重新上架"  （窗帘为定制商品，退货后无法再次出售——库存加回会造成"假可售"）
✅ "窗帘行业定制商品退货后无法再次出售，退回商品不回补库存、不重新上架。
    如需重新上架，请在商品设置里开启「退货回补库存」开关后手动处理。"
```
