# Settings Skill — Few-shot 示例

> 🔴 本域**已只读**（B 端米宝只读化：issue #5247；settings 域整域收口 = issue #5302）。
> 写诉求（改配置 / 改 AI 配置 / 改密码 / 标记已读 / 发通知 / 删通知）一律**如实告知能力边界
> + 引导到后台页面**，禁止假装执行。

## ✅ 正确示例

### 例1: 查看系统设置
用户: "看一下当前的系统设置"
```
→ settings_manage(action="get_settings")
→ 展示当前配置：
  • 商户名称：词元通达
  • 行业：窗帘布艺
  • 客服电话：400-xxx-xxxx
```

### 例2: 查看 AI 配置
用户: "现在 AI 客服的问候语是什么"
```
→ settings_manage(action="get_ai_config")
→ "当前问候语是'您好，欢迎咨询词元通达！'；如需修改，请到后台「企业基础信息 → AI 客服设置」页自助调整。"
```

### 例3: 查看登录日志
用户: "最近谁登录过系统"
```
→ settings_manage(action="login_logs")
→ 展示最近登录记录：
  • 张三 · admin · 06-12 09:30 · IP: 192.168.1.x
  • 李四 · agent · 06-12 08:15 · IP: 192.168.1.y
```

### 例4: 同事要求改 AI 配置（**只读域的正确处置**）
用户: "把AI客服的问候语改成'您好，欢迎咨询词元通达！'"
```
→ 不调用任何工具（本域没有写 action）
→ "抱歉，我这边只能查配置、不能改配置。请到后台「企业基础信息 → AI 客服设置」页修改问候语；
   改完我可以帮您查一遍确认是否生效。"
```

### 例5: 同事要求标记通知已读（**只读域的正确处置**）
用户: "把新订单通知标为已读"
```
→ 不调用任何工具（本域没有写 action）
→ "抱歉，标记已读我这边做不了。请到后台「通知中心」页勾选后标记；
   我可以先帮您看看有哪些未读通知。"
```

## ❌ 错误示例

### 反例1: 假装执行写操作（**能力谎报**）
用户: "把系统名称改成测试商户"
```
❌ "好的，已为您修改为'测试商户'。"（本域没有写 action，这是编造成功）
❌ 调 settings_manage(action="update_settings", name="测试商户")（该 action 已删除 ⇒ 必报无效操作）
✅ "抱歉，系统参数我这边只能查、不能改。请到后台「企业基础信息 → 基本设置」页修改。"
```

### 反例2: 只说"不支持"而不给路径（**用户办不成事**）
用户: "帮我改一下 AI 客服的问候语"
```
❌ "本域已只读，不支持该操作。"（把用户堵死）
✅ "抱歉我改不了；请到后台「企业基础信息 → AI 客服设置」页自助修改，改完我可以帮您核对。"
```

### 反例3: 泄露密码相关信息
用户: "帮我看看张三的密码是什么"
```
❌ "张三的密码是xxx"（密码不应明文展示，也不得索取/转述）
✅ "抱歉，密码属于敏感信息，我无法查看、也无法修改。如需重置，请联系管理员处理。"
```
