# 米高商业化收费设计 — AI 流量包模式

> v3.2 ｜ 2026-08-30 ｜ 计费单位：**AI 流量**（内部按 token 计量）；收费形式：**纯年费、无免费版、基础版起步；全部以年为单位**（年费 / 年流量 / 年咨询量）；**不设人工坐席概念，人工转接全版本标配**
> 配套：本文件是 [commercialization-plan.md](commercialization-plan.md)（商业化总方案）的收费设计细则；[business-plan.md](business-plan.md) 为战略蓝图。**状态：方案已定，暂不落地，等 POC 结束后实施**（见商业化方案第六~七节）。

## 一、定价原则

| 原则 | 内容 |
|------|------|
| 锚点 | 布艺店**一个客服年成本 6~8 万**（时薪约 ¥35）；年费 = 客服成本的 5%~27%，且必须能算 ROI |
| 单位 | 「AI 流量」——借手机流量包心智（套餐/加油包），老板娘零学习成本 |
| 形式 | 纯年费（不设月付档）、无免费版；**全部以年为单位：年费、年流量总量、年咨询量**（无月度重置，一年一个数，客户最好记） |
| 成本约束 | LLM 调用是唯一显著可变成本（实测单店年成本 ¥540~3,960）；毛利目标 ≥ 60%，即便配额被打爆 2 倍仍 ≥ 46% |

## 二、计费单位：AI 流量（内部 token 计量）

- **对外**：`AI 流量`（单位：G/MB），客户只看"今年还剩多少流量 + 够不够用"
- **对内换算**：**1G AI 流量 = 100 万 tokens**（1MB = 1,000 tokens），系数放配置，随模型降价/缓存命中率可调，不影响对外价格
- **计量口径**：每次 LLM 调用（含意图分类、ReAct 循环、自修复重试、会话总结、图片识别等**全部幕后调用**）的 input+output tokens 都计入流量——防成本漏算

### 场景消耗参考表（给客户看的透明换算，取实测模型值取整）

| 客户场景 | 大约消耗 AI 流量 |
|---|---|
| 一句问候 / 闲聊 | 10~20 MB |
| 查一个订单 / 查物流 | 20~40 MB |
| 算窗帘尺寸 / 出报价 | 40~60 MB |
| 完整下一单（含确认流程、多轮） | 80~120 MB |
| 传一张图识别咨询 | 另加 30~60 MB |

> **销售引导句**：1G AI 流量 ≈ 10 次完整下单咨询。一般窗帘店一年用 40~60G，基础版 120G 够用。

## 三、价格表（纯年费，全部年口径）

| 档位 | 年费 | AI 流量/年 | 约支撑咨询量 | LLM 成本/年 | 毛利 |
|---|---|---|---|---|---|
| **基础版** | **¥3,980/年** | 120G | ~1,200 次/年（日均 3~4） | ~¥540 | 86% |
| **专业版** | **¥7,980/年** | 360G | ~3,600 次/年（日均 10） | ~¥1,500 | 81% |
| **旗舰版** | **¥15,980/年** | 960G | ~9,600 次/年（日均 26） | ~¥3,960 | 75% |
| **AI 加油包** | **¥59 / 1G** | 即时生效 | ~10 次完整咨询 | ~¥4 | 93%* |

\* 加油包单价刻意高于升级专业版的增量单价（¥16.7/G），引导超量客户升级而非长期买包；仅用于临时超量。加油包按 G 计、即买即用，不占用套餐年流量。

**人工转接：全版本标配、不限人数** —— AI 解决不了的咨询，自动转给店内**现有**客服，店里有几个客服就能同时接几个；**不按坐席计费、不限制在线人数**（坐席是人工计量单位，AI 时代按坐席收费已被行业淘汰——按坐席模式与 AI 经济学冲突，行业正向按用量/结果迁移；且"限制转接人数"既不产生成本收益，又伤客户信任）。

**一次性费用（独立于订阅）**：

| 项目 | 价格 | 内容 |
|------|------|------|
| 标准开店包 | ¥2,000~5,000 | 模板化交付：知识库整理 + 商品/加工项录入 + 小程序上线 + 培训（二郎神标准化流程） |
| 深度定制 | 另议 | 专属知识库深度训练 / ERP·物流接口对接 / SLA |
| 首年开店组合 | 年费 + 开店包 9 折 | 大店打包优惠 |

### ROI 话术（对老板娘的 3 句话）

1. "您一个客服一年 6~8 万，米高一年 ¥3,980 起。"
2. "AI 每天只要替您接 **2 个咨询就回本**，剩下全是赚的。"
3. "AI 是 7×24 的——半夜的咨询、忙不过来的咨询，它先接着，不会丢单。"

| 档位 | 占客服成本 | 年省人力（按 8~10 分钟/咨询 折算） | ROI |
|---|---|---|---|
| 基础版 | 5~6.6% | ~¥6,600 | 1.6 倍 |
| 专业版 | 10~13% | ~¥19,800 | 2.5 倍 |
| 旗舰版 | 20~27% | ~¥52,800 | 3.3 倍 |

## 四、超量策略（不硬断，生意优先）

1. **80% 预警**：年度用量看板变黄 + 站内通知 + 可配短信提醒运营；
2. **用完**：AI 自动转人工 + 引导购买加油包（¥59/1G，即时生效），不打断客户；
3. **企业版可选硬停**：租户级配额硬阻断（429/降级话术）——同时补审计 06 A2「无租户级 LLM 配额」；
4. 预警阈值、是否硬停按租户可配置。

## 五、获客与续费（无免费版的替代入口）

| 方案 | 做法 | 成本 |
|---|---|---|
| A. 付费试用期 | 首 14 天内不满意全额退款（看转人工率/解决率） | 纯承诺 |
| B. 标杆 POC | 前 1~2 家布艺店免费用，换行业案例（延续 business-plan Q1 打法） | 交付成本 |
| C. 演示租户 | 只读演示账号 + 销售带看 | 最低 |

> 建议 A + B 组合：A 给所有付费客户兜底，B 定向打标杆；C 标配。

## 六、系统前置改动（计量/配额/看板）

### 6.1 计量落库（ai-agent-service → DB）

现有 `cost_tracker.py` 已按 `MODEL_PRICING` 计算每次调用成本（仅进程内 + 结构化日志），缺落库聚合。

```sql
-- 租户级 LLM 用量明细（AI 流量计量）
CREATE TABLE llm_usage (
    id            BIGSERIAL PRIMARY KEY,
    tenant_id     BIGINT      NOT NULL,
    session_id    VARCHAR(64),
    model         VARCHAR(32) NOT NULL,
    input_tokens  INT         NOT NULL,
    output_tokens INT         NOT NULL,
    total_tokens  INT         GENERATED ALWAYS AS (input_tokens + output_tokens) STORED,
    flow_mb       NUMERIC(12,3) GENERATED ALWAYS AS ((input_tokens + output_tokens) / 1000.0) STORED,  -- 1MB = 1000 tokens
    cost_cny      NUMERIC(12,6) NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_llm_usage_tenant_month ON llm_usage (tenant_id, created_at);

-- 租户订阅与配额（年费周期 + 年度流量总量，无月度重置）
CREATE TABLE tenant_subscription (
    tenant_id     BIGINT PRIMARY KEY,
    plan          VARCHAR(16)  NOT NULL,              -- basic / pro / flagship
    flow_quota_g  INT          NOT NULL,              -- 年度流量配额（G）
    flow_used_g   NUMERIC(10,3) NOT NULL DEFAULT 0,   -- 年度已用（G），跨年（period_end）重置
    period_start  DATE         NOT NULL,              -- 年费周期起
    period_end    DATE         NOT NULL,              -- 年费周期止
    status        VARCHAR(16)  NOT NULL DEFAULT 'active'  -- active / expired / suspended
);
```

### 6.2 配额硬阻断（ai-agent-service）

- 每次 LLM 调用后累计 `flow_used_g`；超 100% → 按租户策略：转人工（默认）/ 429 硬停 + 降级话术；
- 用 Redis 分布式累计（替代进程内 `check_budget` 仅告警）。

### 6.3 用量看板（admin-api + admin-web）

- `GET /api/v1/tenant/usage/annual` → { quota_g, used_g, by_model, 按月趋势 }；
- admin-web 设置页加「AI 流量」卡片：**年度**进度条（绿/黄/红）+ 加油包购买入口；
- 80% 预警通知（复用现有通知体系）。

### 6.4 计费口径边界

- 只统计**AI 相关调用**（LLM 调用全部计入），管理员人工操作、工具内部 HTTP 调用不计流量；
- 免费/内部演示租户使用独立配额表，不挤占客户流量。

## 八、关键决策记录（ADR 简表）

| 决策 | 结论 | 理由 |
|------|------|------|
| 计费单位 | AI 流量（token 内部计量） | 老板可理解；按用量公平；避免会话深浅不均 |
| 收费形式 | 纯年费、无免费版 | 现金流稳、留存验证；低价锚点冲决策门槛 |
| 价格档位 | 3,980 / 7,980 / 15,980 + 加油包 59/G | 客服成本 6~8 万的 5%~27%；毛利 75%~86% |
| 配额口径 | **全部年口径：年费 / 年流量总量 / 年咨询量**，无月度重置 | 客户只记一个数（一年 120G），最简单；续费年重置 |
| 超量策略 | 转人工为主、硬停可配；加油包 ¥59/1G 即买即用 | 生意优先；硬停补审计 A2 |
| 人工坐席 | **不设坐席概念**：人工转接全版本标配、不限人数、不按坐席计费 | 按坐席收费是人工时代的计量方式，与 AI 经济学冲突（AI 无座位）；限制转接人数无成本收益且伤信任 |
| 获客入口 | 14 天退款承诺 + 标杆 POC + 演示租户 | 无免费版但不卡冷启动 |
