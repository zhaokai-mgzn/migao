# 中型企业能力差距评估（2026-10-20）

> **这是什么**：对「30 人 POC 客户够用 ⇒ 能否支撑中型企业经营管理」的评估与排序。
> **结论一句话**：缺的不是「更多单据」，是 **管住** —— 组织分层、资金往来、多仓多渠道、数据量与集成。
> **权威口径**：本页只做评估与验收判据；**未实现**的模块一律标「缺口」，不写成「已规划」。
> 关联：[commercialization-plan.md](commercialization-plan.md)（收费与落地节奏）· [business-plan.md](business-plan.md)（定位与客户画像）

## 一、为什么 30 人够用、中型不够

30 人客户的经营特征是：**单仓、老板一人决策、钱走微信、库存靠记忆**。
中型企业不是「人数多几倍」，而是四个结构性变化：

| 变化 | 后果 | 对系统的要求 |
|---|---|---|
| 有了分层（部门/门店/业务员） | 信息不能再全员可见 | **数据范围（data scope）**、审批、审计 |
| 资金有了往来（赊销/账期/采购付款） | 现金流 ≠ 利润 | **应收应付 + 授信 + 成本毛利** |
| 货物多了仓/多了渠道（门店仓+加工仓、线上+线下） | 库存准不住 | **多仓/调拨/盘点**、批次追溯 |
| 数据量与外部系统 | Excel 撑不住 | **报表、导入迁移、开放 API/集成** |

参考划型（中国行业惯例）：批发业「中型」≈ 从业人员 20 人以上 **且** 营业收入 5000 万元以上；
本页的判据不看人数，看**「是否出现了需要被约束的第二个责任主体」**（见 §五 的 6 问）。

## 三、缺口（按「不补就上不了中型客户」排序）

### P0 · 四项（不做则上线即破）

| # | 缺口 | 现状证据 | 最小形态 |
|---|---|---|---|
| 1 | **采购与供应商** | 入库单的供应商是**文本**，`InboundLabelView` 自注「MVP 不建主数据」；无采购订单、无应付 | 供应商档案 + 采购单→收货→退货 + 应付与付款 + 供应商对账/账期 |
| 2 | **客户授信与往来** | `finance_transactions` 只有 `income` / `refund`（现金流），无账龄、无授信；客户「等级」字段存在但**没有地方拿它控额度或定价** | 授信额度与超限拦截、账期、应收账龄分档、收款核销、催收清单 |
| 3 | **成本与毛利** | 批次/缸号已有，但**进价没进核算** ⇒ 算不出真实毛利 | 批次成本 → 订单毛利 → 退货/加工/质量成本；员工业绩 |
| 4 | **数据范围（data scope）** | RBAC 只到「模块 + 读写」；全仓**零数据范围实现** | 按门店/部门/业务员过滤客户与订单；越权返回空而非 403 泄形 |

### P1 · 五项（决定「管不管得住」）

- **多仓 / 调拨 / 仓位 / 盘点单**：现在 `warehouse` 只是字段；只有按批次的最小盘点回执（V143 明示「不做盘点单实体」）。
- **具名审批流**（改价 / 超授信 / 退款 / 采购 / 领料）——**只做 5 个具名审批，不造 BPM 引擎**。
- **价格体系**（客户等级价 / 协议价 / 阶梯价）：现有 `pricing_type` 是**计价方式**，不是价格策略。
- **报表中心**（库存周转、滞销、毛利、应收账龄、员工业绩）——现在只有 dashboard 与经营日报。
- **售后→返工→质量成本闭环**（质检录入在推进中，返工成本未进账）。

### P2 · 四项（决定「能不能批量复制客户」）

开放 API / Webhook；**Excel 双向导入导出**（迁移是中型客户最大实施成本）；电商 / ERP / 财务软件 / 物流面单对接；
多主体与合并报表。

### 明确不做

❌ 财务总账（做凭证/对账接口，接金蝶用友）· ❌ 通用审批引擎 · ❌ 自建 MES/WMS 全集 · ❌ 自研 IM。
判据：**「这块要比 Excel 强、且不添乱」**，不是「又一个实施半年的大系统」。建模侧的克制见
[Domain-Modeling](../wiki/Domain-Modeling.md)。

## 四、验收判据（每项落地时必须给会红的读数）

| 项 | 判据形态（示意） |
|---|---|
| 采购 | 采购单 → 收货 → 应付：收货后应付余额 = 采购金额 - 已付；**跨批收/部分收**都有单据；删单不删应付（红） |
| 授信 | 超额度下单 ⇒ 拦截并给出「超多少 + 谁可批」；审批通过后放行；**额度为 0 ≠ 不限** |
| 成本毛利 | 同一订单的毛利 = 收入 - Σ(批次进价×用量) - 加工/运费；**批次进价缺失 ⇒ 明确显示「成本未知」，不填 0** |
| 数据范围 | 业务员 A 的列表**与详情/导出/agent 查询**四处口径一致（只过滤列表 = 没做） |

## 五、怎么判断客户真的到了「中型」（6 问，零成本）

1. 有几个仓？2. 销售提成怎么算？3. 应收账款谁在跟、多久对一次？
4. 退换货谁批？5. 采购谁定、谁付钱？6. 现在数据在 Excel 还是 ERP？

> 答案里出现**「两个人以上各自负责」**的，才需要 P0 这套。只有第 6 问是「Excel」时，先做 P2 的迁移能力。

## 六、建议落地顺序

1. **授信/账期 + 成本毛利**（复用现有批次与订单数据，工作量最小、老板感知最强）；
2. **采购/供应商 + 应付**（补齐唯一缺的供应链头部）；
3. **数据范围 + 多仓/审批**（组织变大的入场券）。

## 七、一条比缺模块更硬的风险

中型客户买的是「**不出事**」。评估时线上仍有部署腿失败与 Post-Deploy 回归失败在跟踪
（见 issue #7357 · #7243 · #7242 · #7241 · #7296）—— **交付可靠性优先于功能数量**；
中型客户不会容忍「合了但没上线」。
