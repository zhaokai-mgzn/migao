## 一、一句话（客户听完能转述给别人的那句）

> **别的软件帮你记账，观星台帮你做事。**

三个版本，按对方身份用：

| 对象 | 一句话 |
|---|---|
| 老板娘（决策人） | 「你店里那些**没人回的消息、算错的价、问到烦的‘我的货到哪了’**，它替你接住。」 |
| 老板（看经营） | 「你缺的不是数据，是**结论**——每天早上一句话告诉你今天哪几单要出问题。」 |
| 店长/客服主管 | 「新人第一天就能答客户，**老人走了经验不走**。」 |

**为什么不是「AI 客服」四个字**：客户听「AI 客服」会拿去和 9.9 万/年的呼叫中心比价。
要听的是「**少请一个人、少丢几单、少赔几笔**」——那是损益表语言，不是软件语言。

## 二、第一性原理：Agent 唯一不可替代的商业价值

企业里同时存在三套语言，**没有任何一个系统能同时说**：

| 语言 | 例子 | 谁说 |
|---|---|---|
| **客户的话** | 「我这单还能赶在国庆前装上吗，急用」 | 消费者 |
| **业务系统的话** | 订单状态、工序、报工记录、SKU、加工项、门幅 | 后台/车间 |
| **老板的话** | 毛利率、逾期、复购、库存周转 | 报表 |

工作流（按钮/表单）只能在**固定的两套语言之间**翻译：点「查订单」→ 出状态。
但客户问的是**混合问题**——「赶不赶得上」要同时拆开：订单 → 当前工序 → 待完工序 → 预计交期 → 物流时效 → 再判断。

**只有 Agent 能拆混合问题。** 这就是它全部的不可替代性，其余价值都是它的推论。

> **反过来说**：如果客户的问题都能拆成「点一个按钮就出答案」，那就不需要 Agent ——
> 这也是为什么观星台**主动砍掉了 B 端 Agent 的建单/建品/改单**（2026-10-02 裁定）：
> 页面做得更好的事，Agent 不做。**不做的部分，是价值主张的一部分，不是缺陷。**

## 三、七笔账：客户的钱从哪里漏，Agent 堵哪一笔

> 用法：POC 访谈时逐条问「这笔您一年大概漏多少」，客户自己填数 ——
> **客户自己算出来的账，比销售算给他的账可信十倍。**

### 账 1 · 漏单账（夜间与忙时没人接）

| 项 | 内容 |
|---|---|
| **痛点** | 定制窗帘客单价数千元。客户晚上 9 点在小程序问「这款遮光率多少」，第二天早上才回——人已经在别家下单了。周末、节假日、客服请假同理。 |
| **Agent 怎么堵** | 元元 7×24 秒级响应；**能直接下单**（不是只答疑）；问「怎么付款」直接发商家收款码卡片。咨询 → 下单 → 付款在同一个对话里闭环。 |
| **算账口径** | 年咨询量 × 非营业时间占比 × 流失率 × 客单价。**这笔账通常是一家店最大的一笔**，因为它直接是 GMV，不是成本。 |
| **能力证据** | 元元工具集含 `order_create`（确认闸全覆盖，服务端取价校验）· `payment_qrcode_query`（收款码卡片） |
| **差异化** | **通用客服 SaaS 的机器人止于答疑**：它没有商品 SKU、没有加工项计价、没有订单，接住了也成不了单。 |

### 账 2 · 报价账（算错一件，白干十件）

| 项 | 内容 |
|---|---|
| **痛点** | 锁边、褶皱、挂钩、罗马杆、门幅、帘宽帘高……**新手客服报错价是常态**。报低了亏钱，报高了丢单；定制产品还不能退货，报错的单只能自己吃。 |
| **Agent 怎么堵** | 算料/计价规则固化在系统里（不是模型心算）；**服务端二次取价**——AI 报出的单价必须与 SKU 权威价严格一致，不一致直接拒绝，一个 HTTP 都不发。 |
| **算账口径** | 年订单量 × 错价率 × 单均损失。**问客户：「上个月有没有算错过价的单？」** 几乎每家都有。 |
| **能力证据** | `curtain_calc`（算料规则真值源 `docs/curtain-fabric-quote-rules.md`）· M3 服务端取价校验（issue #2806）· 缺单价即失败引导，无静默默认价 |
| **差异化** | 通用客服**算不了窗帘**——它没有门幅、没有褶皱倍数、没有加工项目录。 |

### 账 3 · 追问账（「我的货到哪了」）

| 项 | 内容 |
|---|---|
| **痛点** | 定制行业客户最大的焦虑是「**什么时候好**」。一天三个电话问进度，客服答不上来，只能跑去车间问；问回来客户又打一遍。**这类咨询不产生收入，却吃掉客服大量时间。** |
| **Agent 怎么堵** | 顾客问「我的单做到哪了/还要多久」，AI 直接答：进度百分比、当前工序、待完工序、预计交期——**数据来自生产系统，不是编的**。查不到就如实说查不到（禁止编造）。 |
| **算账口径** | 进度类咨询占比（**通常 20~40%**，POC 时可标注统计）× 单次处理时长（含跑去车间）× 客服时薪。 |
| **能力证据** | `production_progress_query`（双端只读，issue #3996）· 商家侧还能穿透到 `production_worklog_query`（谁报的/合格/返工/报废） |
| **差异化** | **这是通用客服 SaaS 结构上做不到的**——它没有生产车间数据。也是行业 ERP 做不到的——它没有对话入口。 |

### 账 4 · 培训账（人走了，经验也走了）

| 项 | 内容 |
|---|---|
| **痛点** | 新客服要背：颜色 × 售卖方式 × 门幅 × 加工项 × 面料特性 × ERP 操作。**新人 2 周才能独立**；老客服一离职，客户关系和对货的理解一起带走。老板最怕的就是这个。 |
| **Agent 怎么堵** | 知识卡片（行业模板一键套用 + 商品自动派生 + 会话提炼）+ 页面上下文解释（在哪个页面只答那一页的事）。新人第一天就能上岗，**知识沉在系统里，不在人脑子里**。 |
| **算账口径** | (培训周期 × 新人工资) + (年离职人数 × 重置成本) 。外加隐性的：**老板自己带新人花的时间**。 |
| **能力证据** | 知识卡片（LLM WIKI，结构化检索）· 黄金策族 4「页面上下文解释与教学」· 行业模板套用 |
| **差异化** | 竞品给的是「话术库」，需要人去找；观星台是**问出来的**，且答错会被真值源约束。 |

### 账 5 · 漏客账（买完就沉默）

| 项 | 内容 |
|---|---|
| **痛点** | 窗帘是**低频高客单 + 有复购场景**（换季、搬家、多套房、介绍亲戚）。客户买完就沉默，几万块的复购靠老板记性。 |
| **Agent 怎么堵** | 客户画像跨域视图（订单 + 售后 + 标签 + 复购）+ RFM 评分 → 谁该回访了、谁快流失了，**一个视图说清**。 |
| **算账口径** | 老客数 × 复购率提升几个点 × 客单价。**只要多回来 3 个客户，年费就回来了。** |
| **能力证据** | `customer_profile` / `customer_value` 跨域视图 · RFM（后台 CRM）· 客户标签 |
| **差异化** | 通用 CRM 只给列表，**不给结论**；「这个客户值不值得留」要人自己判断。 |

### 账 6 · 事后账（月底才发现）

| 项 | 内容 |
|---|---|
| **痛点** | 库存告急、超期未发货要赔付、客户欠款逾期、低于成本价卖出去的单——**全都是月底算账才知道**。发现的时候，钱已经没了。 |
| **Agent 怎么堵** | 后台日报主动扫描：低于成本价的订单 / 超 N 天未发货 / 库存告急 / 连续退货 / 改价幅度超阈值。**规则触发，不是 AI 觉得异常** —— 每条都可复算、可解释「为什么推给你」。 |
| **算账口径** | 年超期赔付 + 资金占用成本 + 亏本单金额。 |
| **能力证据** | `briefing_query`（经营日报只读工具）· 规则引擎 · 四态可见化 |
| **差异化** | 页面只能**等人来点**；这是唯一「不等你问就告诉你」的形态。 |
| ⚠️ **当前边界** | **推送目前是后台站内可见，微信/短信外推送面未建**（见 §六）。对客户口径：「登录后台就能看到今天的异常日报」，**不要说「AI 会主动微信提醒你」**。 |

### 账 7 · 说法账（纠纷时没证据）

| 项 | 内容 |
|---|---|
| **痛点** | 客户说「你当时说包安装/包拆旧」，定制产品不退不换，各说各话。赔一笔，或者吃一个差评。 |
| **Agent 怎么堵** | 全链路会话留痕（可查）；消息级标识「AI / 人工」；**AI 被明确禁止承诺退款/改价/取消**——它只会解释规则、收集材料、转人工。 |
| **算账口径** | 年纠纷件数 × 单件赔付 + 差评对进店转化的影响。 |
| **能力证据** | 元元无退款/改价/取消工具（物理白名单）· 写工具确认闸全覆盖 · 转人工携带 AI 对话快照（GB-01）· 会话落库 |
| **差异化** | 大多数 AI 客服**敢乱承诺**，因为它没有护栏；观星台的 AI 承诺边界是**代码级**的，不是提示词级的。 |

## 四、四条「别人给不了」的链（差异化 / 防守话术）

客户会问：「这不就是个客服机器人吗？七鱼/智齿也能做。」
答：**客服机器人是「一句话进、一句话出」。观星台是四条链，每条都通到底。**

| 链 | 从 | 到 | 通用客服 SaaS | 行业 ERP |
|---|---|---|---|---|
| **A 成交链** | 客户随口一问 | 下单 + 收款码 | ❌ 只能答疑 | ❌ 没有对话入口 |
| **B 生产链** | 客户问「还要多久」 | 工序进度 / 报工记录 / 计件 | ❌ 无车间数据 | ⚠️ 有数据，但要登录后台自己查 |
| **C 决策链** | 老板问「这个月哪些货赔钱」 | 跨域视图 + 异常日报 | ❌ 无业务数据 | ⚠️ 有报表，但要自己找指标 |
| **D 合规链** | 监管/客户质疑 | 遵循 GB/T 47746-2026 的证据链 | ⚠️ 各家自有说法 | ❌ 不涉及 |

**A 链是最硬的**：AI 会话 → 订单 → GMV 是可归因的。这是**未来按结果收费的地基**
（见商业化方案 §四 L3）——**别的客服 SaaS 收不了这个钱，因为它证明不了是自己带来的成交**。

## 六、不可宣称清单（销售红线）

> 依据：GB-05「宣传真实性」+ 本文写作纪律。**违反这些，交付即崩塌。**

| ❌ 不能说 | ✅ 应该说 | 理由 |
|---|---|---|
| 「AI 会主动微信提醒你」 | 「登录后台能看到今天的异常日报」 | 外推送面未建（能力地图族 1 标注 ⚠️） |
| 「AI 帮你建单、改单、发货」 | 「AI 帮你**查、分析、批量改价**；建单发货在页面上更快」 | 2026-10-02 用户裁定砍掉复杂创建类 |
| 「AI 能退款/改价/取消订单」 | 「AI 只解释规则、收集材料，退款走人工审核」 | 元元无此类工具（物理隔离） |
| 「AI 自动学习、越用越懂你」 | 「知识卡片由你确认后生效」 | GB-05 已移除的夸大表述 |
| 「通过国标认证」 | 「遵循/对标 GB/T 47746-2026」 | 推荐性国标无认证机制 |
| 「AI 解决率 95%」 | 「POC 实测解决率 X%」（有数据再说） | 无数据不得宣称 |

## 八、三分钟演示脚本（销售必背）

> 目的：让客户在 3 分钟内**亲眼看到**账 1/2/3 ——不是听讲，是看到。

1. **（30 秒）** 打开小程序，用手机当面问元元：「我想给卧室做遮光窗帘，3 米宽，要打孔加工，多少钱？」
   → 客户看到 AI 报出**带加工项的完整价格**。
2. **（30 秒）** 继续问：「这款晚上会不会透光？」「能做多高？」
   → 客户看到 AI **懂行业**，不是通用机器人。
3. **（45 秒）** 追问：「那我的单什么时候能好？」
   → 客户看到 AI 答**工序进度**（账 3）。**这一秒是全场最贵的** ——竞品在这里会说「请稍等，我帮您查询」。
4. **（45 秒）** 打开后台，问黄金策：「这个月哪些商品在赔钱？」
   → 客户看到**跨域视图**，不是报表列表（账 6）。
5. **（30 秒）** 问：「你能帮我退款吗？」
   → AI 说「不能，我帮您转人工」并**带上上下文**（账 7）。
   → **故意演示边界**：客户对 AI 的信任来自它知道自己不能做什么。
