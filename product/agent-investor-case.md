## 一、先说结论（一句话）

> **C 端 Agent 决定我们「能不能卖出去」，B 端 Agent 决定我们「能卖多贵、留多久」。**

三个财务口径 + 一个定价权，四句话讲完：

1. **它压交付成本** —— 客户不用被培训三天，规模化瓶颈从「人」变成「产品」。
2. **它压支持成本** —— 客户问题先进 AI，人工只兜 P0（¥500 → ¥100/客户/年）。
3. **它抬续费率** —— 后台功能被真正用起来，沉默流失减少（80% → 90%）。
4. **它解开定价天花板** —— 现在的年费被「客服工资」钉死，只有 B 端能换锚点。

前三条是**改善单位经济**，第四条是**改变估值逻辑**。

## 二、不要用 C 端的坐标系讲 B 端（最重要的方法论）

股东会上最容易犯的错，是拿 C 端的讲法套 B 端，然后被一句话问倒：

> 股东：「你说 B 端 Agent 有价值 —— 那它一年能带来多少 GMV？」

**答不上来，就输了。** 因为 B 端 Agent **本来就不产生 GMV**，它服务的是已经在用系统的人，它的价值是「让系统被用起来、用得好、离不开」。

正确的坐标系是 **SaaS 单位经济模型**，不是 GMV：

| 指标 | C 端 Agent 贡献 | B 端 Agent 贡献 |
|---|---|---|
| **ARR**（收入） | ⚠️ 间接（靠「能成交」作为卖点） | ❌ 不直接贡献 |
| **CAC**（获客/交付成本） | ❌ 不贡献 | ✅ **直接降低** |
| **COGS**（服务成本） | ✅ 降低（替代客服人力） | ✅ **直接降低**（替代支持人力） |
| **LTV**（续费） | ⚠️ 间接 | ✅ **直接提升** |
| **ARPU**（客单价） | ❌ 天花板锁死 | ✅ **唯一的解锁通道** |
| **壁垒** | ⚠️ 可被垂直竞品模仿 | ✅ **行业 know-how 编码，越积越厚** |

> **一句话**：C 端 Agent 是**获客与留存的钩子**，B 端 Agent 是**毛利与定价权的杠杆**。
> 两个都要讲，但**不能互换坐标系**。

## 三、三个财务口径（有数字，可复算）

> 口径来源：商业化方案与定价设计中的既有假设。**标注「假设」的必须在 POC 后用实测替换**，
> 对股东汇报时说明「这是模型值还是实测值」—— 混着讲一次，后面所有数字都不再被信。

### 口径 1 · 支持成本（COGS）：最硬的一笔

商业化方案 P1 已明确：「**AI 客户支持通道 —— 观星台自己的客户问题先进 AI，人工只兜 P0（支持成本 ¥500→¥100）**」。

| 项 | 数值 | 出处 |
|---|---|---|
| 单客户年支持成本（现状） | ~¥500 | 商业化方案 P1（假设） |
| 单客户年支持成本（AI 兜底后） | ~¥100 | 同上（假设） |
| 稳态客户数 | 200 家 | 商业化方案 §5.2 |
| **年节省** | **~¥8 万** | 200 × 400 |

**对股东的说法**：这不是「省钱」，这是**把毛利从 81% 抬向 83%**，而且**不依赖涨价**。
在 100 万年利润的目标里，这 8 万是 8%。

### 口径 2 · 交付成本（CAC 的一部分）：决定规模化斜率

标准开店包 ¥2,000~5,000 里，「培训」是纯人力（pricing-design 一次性费用表）。
B 端 Agent 承担了其中**「解答为什么」**的部分：页面上下文解释（在哪一页只答那一页）+ 操作引导 + 追问。

| 项 | 现状 | B 端 Agent 介入后 |
|---|---|---|
| 交付方式 | 人工培训，讲一遍 | 自助为主，AI 随时答 |
| 规模化瓶颈 | **交付人力**（接单量被人卡住） | **产品**（接单量不被卡） |
| 单客户交付人天 | 假设 2~3 天 | 待 POC 实测 |

**对股东的说法**：这一条的价值不在「省了多少钱」，而在**「增长曲线从线性变成可加速」**。
只要交付还靠人一天一天讲，客户数就被人头卡住 —— 这是 SaaS 最容易死在的地方。

> ⚠️ **诚实的边界**：这一条目前**没有实测人天数据**。汇报时必须说「待 POC 校准」，
> 不能给一个编出来的百分比。股东最恨的就是模型值伪装成实测值。

### 口径 3 · 续费率（LTV）：最容易被低估

商业化方案 §5.2 的敏感性分析已写明：**「续费率 80%→90%，所需客户数再降 ~10%」**。

| 项 | 续费率 80% | 续费率 90% |
|---|---|---|
| 达到 100 万年利润所需客户数 | ~200 家 | ~180 家 |
| 少获客 | — | **20 家** |

为什么 B 端 Agent 能抬续费率？**因为 SaaS 的流失不是「不想买」，是「买了没用起来」。**
后台有 12+ 模块、SKU 矩阵、加工项、RFM、看板 —— 大多数店主**只会用其中 3 个**。
用得少 → 感知价值低 → 到期不续。

B 端 Agent 是**激活器**：客户问一句就有答案，功能被真正用起来，感知价值才成立。
**跨域视图**更是直接制造「离不开」的理由（「这个客户值不值得留」这种问题，别处问不到）。

## 四、定价权：解开 ARPU 的天花板（**本轮最强的论证**）

这是 B 端 Agent 对股东**最重要的价值**，也是最容易被漏讲的。

### 现状：我们的定价被钉死在「客服工资」上

pricing-design 的定价锚点原文：

> 「锚点：布艺店**一个客服年成本 6~8 万**；年费 = 客服成本的 5%~27%」

翻译成股东语言：**我们卖的是「客服替代品」，所以年费的上限 = 客户愿意为一个客服付的钱 = 1~2 万。**

后果：
- 基础版 3,980 / 专业版 7,980 / 旗舰版 15,980 —— **已经摸到这个锚点的顶了**
- 再往上加价，客户会算：「这都够请两个客服了，我为什么不请人？」
- **ARPU 结构性封顶**

### B 端 Agent 是唯一能换锚点的东西

| 锚点 | 客户心里的比较对象 | 可接受年费区间 | 谁能提供 |
|---|---|---|---|
| **客服成本** | 一个客服 6~8 万/年 | 3,980 ~ 15,980 | C 端 Agent（已有） |
| **经营决策** | 老板自己的时间 / 一次错误决策的损失 | **3 万 ~ 10 万+** | **只有 B 端 Agent** |

为什么「经营决策」这个锚点能撑起 3~10 万？
- 一次「超期未发货」的赔付 + 差评，可能就是几千
- 一次「低于成本价卖」的批量错误，可能上万
- 一个客户流失（复购客单价数千 × 年），几千到几万
- **老板的时间**：每天翻 8 个页面拼数据 vs 早上一句话看结论

**对股东的一句话**：
> 「只要我们的产品只有 C 端 Agent，我们就是一家**客服软件公司**，ARPU 天花板 1.5 万。
> 有 B 端 Agent，我们才有机会成为**经营中台**，ARPU 天花板 5 万以上。
> **这不是功能问题，是估值倍数问题。**」

## 五、反向论证：如果砍掉 B 端 Agent 会怎样（股东最爱听的）

> 股东提问方式：「能不能砍掉省成本？」——用这张表正面回答。

| 砍掉之后 | 后果 | 对财务指标的影响 |
|---|---|---|
| ① 支持回到人工 | 客户问题全进人工，¥100 → ¥500 | COGS 上升，毛利 -2pt |
| ② 交付回到纯人工 | 接单量被人头卡住 | **增长曲线从可加速退回线性** |
| ③ 后台「买了不会用」 | 使用深度下降 → 沉默流失 | 续费率回落，需多获客 20 家 |
| ④ 失去跨域视图 | 产品退化为「更好的后台 + 客服机器人」 | **与七鱼/智齿同质 → 只能拼价格** |
| ⑤ **定价锚点锁死** | 只能卖「客服替代品」 | **ARPU 封顶 1.5 万，再无提价路径** |
| ⑥ 失去「老板入口」 | 老板每天打开的第一个界面不是我们 | 增购/交叉销售的通道关闭 |

**第 ⑤ 条是致命的**：砍掉 B 端 Agent 省下的研发成本（一个人几个月），
换来的却是**永久失去 ARPU 提升的能力**。这是一笔**用一次性成本换掉长期定价权**的交易。

> 一句话答辩：
> **「砍掉它省的钱，是一次性的；砍掉它失去的定价权，是永久的。」**

## 六、两个战略资产（软价值，但要讲成硬逻辑）

### 资产 1 · 「老板入口」

C 端 Agent 抢的是**消费者的入口**（微信小程序）。
B 端 Agent 抢的是**老板每天打开的第一个界面**。

谁占据了这个位置：
- 谁就能做**增购**（新的分析视图、新的行业模板）
- 谁就能做**交叉销售**（从客服 → 到生产 → 到财务）
- 谁的**替换成本**就最高（换掉它 = 换掉老板的习惯）

对股东：**这不是功能，是渠道。** 入口价值在 SaaS 里从来不体现在功能清单上，体现在**净收入留存率（NRR）**上。

### 资产 2 · 行业 know-how 的编码（壁垒厚度）

能力地图族 3 的判据是：**「加一个跨域问题 = 加一个具名工具」**。

| 已交付视图 | 组合了什么 |
|---|---|
| `product_health` 商品健康度 | 销量 + 库存 + 退货率 + 毛利 |
| `customer_profile` 客户画像 | 订单 + 售后 + 标签 + 复购 |
| `customer_value` 客户价值 | 消费额 + 频次 + 最近购买 |
| `delivery_risk` 交付风险 | 逾期 + 欠款 + 客户信用 |

**每一个视图 = 一段只有布艺行业老手才知道「该看什么指标」的知识，被编码成了产品。**

通用 SaaS（七鱼/智齿/Udesk）**抄不了**，因为它不知道窗帘店的「商品健康度」要看门幅和退货率的组合。
行业 ERP **抄不了**，因为它没有对话入口。

对股东：**视图数量 = 壁垒厚度**。这是可累积的、可度量的资产（不是形容词）。

## 七、股东 Q&A 答辩（预设刁钻问题）

| 股东会问 | 不要这样答 | 应该这样答 |
|---|---|---|
| **「既然页面都能做，为什么还要它？」** | 「AI 更智能」 | 「页面只能等人来点。**对话外主动发现**和**跨域分析**，页面结构上做不到 —— 这正是 2026-10-02 裁定的三条。」 |
| **「它能带来多少收入？」** | 编一个 GMV | 「它不直接带收入。它带的是**毛利（支持成本 -80%）、交付斜率、续费率、定价权**。」 |
| **「能不能砍掉？」** | 「也可以」 | 「可以，代价是**永久失去 ARPU 提升路径**——砍掉省的钱是一次性的。」 |
| **「为什么客户不多用后台？」** | 「客户懒」 | 「后台 12 个模块，店主平均只用 3 个。**不是懒，是没人教、没人答**。」 |
| **「和七鱼/智齿有什么不同？」** | 「我们更垂直」 | 「他们有对话，没有车间数据；ERP 有数据，没有对话。**中间那层是我们的**。」 |
| **「AI 会不会乱来？」** | 「不会」 | 「边界在**代码**里，不在提示词里：元元物理上没有退款/改价/取消工具；黄金策写操作已收窄。」 |
| **「这块投入产出怎么算？」** | 讲功能数量 | 「研发成本 ≈ 一个人几个月；**换回的是定价锚点从『客服工资』换成『经营决策』**。」 |

## 八、汇报口径（三句话，一页纸）

> 给股东 / 董事会用的最终版本。不要超过这三句，多了就散。

1. **C 端 Agent 让我们能卖出去，B 端 Agent 让我们能卖得贵、留得久。**
2. **它不产生 GMV，但它把支持成本降 80%、把交付从「靠人」变成「靠产品」、把续费率往上抬。**
3. **最重要的一条：没有它，我们的年费天花板是「一个客服的工资」；有它，天花板才是「老板的一次错误决策」。**

## 九、诚实边界（本文的负向约束）

> 与 [agent-value-proposition.md](agent-value-proposition.md) §六「不可宣称清单」同源。
> 对股东过度承诺，比对客户过度承诺更危险 —— 客户退费，股东撤资。

| ❌ 对股东不能说 | ✅ 应该说 |
|---|---|
| 「B 端 Agent 带来 XX 万收入」 | 「B 端 Agent 改善的是毛利/续费/定价权」 |
| 「交付成本能降 50%」 | 「交付人天待 POC 实测校准」 |
| 「续费率肯定到 90%」 | 「商业化方案测算 80%→90% 需客户数 -10%」 |
| 「AI 会主动推送提醒」 | 「日报目前是后台站内可见，外推送未建」 |
| 「国标认证」 | 「遵循/对标 GB/T 47746-2026」 |
