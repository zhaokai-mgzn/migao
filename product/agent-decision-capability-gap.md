## 一、先对名字负责：「黄金策」的「策」是什么

「策」是**决策**，不是**查询**。

决策的完整链路是五步：
**察（发现问题）→ 谋（有哪些选择）→ 决（选哪个、为什么）→ 行（去做）→ 复（效果如何）**

**当前结论一句话：**

> **黄金策已经是一只很准的眼睛（察），但还不是一颗会做判断的脑子（谋/决/复）。**

这不是贬低 —— 把「察」做到当前这个程度（确定性规则 + 未知≠0 + 四态可解释）本身很难。
但产品定位说的是「帮老板做决定」，那就必须把后面几步补上。

## 二、决策能力八层阶梯 · 现状盘点

| # | 决策要素 | 现状 | 证据 / 缺口 |
|---|---|---|---|
| **1 察** | 发现异常 | ✅ **强** | 规则引擎（`app/briefing/proactive.py`）+ 四态可见化 + 4 个跨域视图 |
| **2 解释** | 为什么推给你 | ✅ **强** | 每条推送带判据；`reason is None ⟺ wired` 不变式 |
| **3 归因** | 为什么会这样 | ⚠️ **弱** | 简报 `suggestions` 由 LLM 组织，**归因不可验证**；无规则化根因分析 |
| **4 判断** | 这算好还是坏 | ✅ **已补**（P0, #8234） | 同一快照内的同行基线（中位 / 上四分位 / 样本量）+ `good`/`watch`/`bad`/`unknown`。**是相对基线，不是绝对行业标准**；历史基线与客户目标值仍未做（见 §四） |
| **5 谋** | 我有哪些选择 | ✅ **已补**（P3, #8251） | 每个 `bad`/`watch` 行给 2~3 个可选动作（确定性规则表，不交给 LLM 自由发挥）；`good`/`unknown` 不给（没问题时推荐动作是噪音） |
| **6 权衡** | 每个选择的代价 | ⚠️ **部分**（P3） | 每个选项带 `cost`（low/medium/high）+ `reversible` + `verify`（怎么验证它有用）。**没有多目标优化**，也没有具体金额（需真实成本数据，不编） |
| **7 推演** | 如果选这个会怎样 | ❌ **无** | 无模拟内核；现有能力只能查**已发生的事实** |
| **8 行** | 选定后去做 | ⚠️ **连了一根线**（P1, #8236） | 日报每条（含无 `link` 的建议/风险类）都有「问黄金策」→ 打开浮窗并预置带上下文的问题。**执行仍由人确认**（2026-10-02 裁定：提交永远是人的动作） |
| **9 复** | 做了之后效果如何 | ⚠️ **给了原料**（P2, #8253） | 历史简报可回溯（`GET /briefing/history` + `view=history`），空历史自述「没有记录」。**没有采纳记录、没有效果跟踪**（需决策事件表，另行） |

> 注：第 1/2 层是「察」，5/6/7 是「谋」，4/8 是「决」的前置与落地，9 是「复」。
> **9 层里 3 层强（察 / 解释 / 判断）、1 层基本可用（谋）、2 层部分（权衡 / 复盘）、2 层弱（归因 / 行）、1 层空（推演）。**
>
> 📌 **2026-10-31 进展**：本轮把「没有参照系」「只给一个方案」「没有复盘」三个缺口各补了一刀 ——
> 详见 §四 / §五 / §六 的 ✅ 标记。**但补的是「能说」，不是「能证明」**：
> 判断用的是相对基线（不是绝对标准）、权衡只有等级（没有金额）、复盘只有回忆（没有采纳记录）。

## 三、已具备（可以立刻对客户讲）

### 3.1 主动发现引擎 ✅

| 能力 | 位置 | 成熟度 |
|---|---|---|
| 规则引擎（低于成本价 / 超期未发 / 库存告急 / 连续退货 / 改价超阈） | `app/briefing/proactive.py` | 确定性、可复算 |
| 四态可见化（`wired` / `not_wired` / `incomplete` / `not_enabled`） | `#5955` / PR #5967 | 已交付 |
| 「未知 ≠ 0」「未采集不渲染」 | `product_health.py` / `delivery_risk.py` 三态纪律 | 已交付 |
| 经营日报四区块（回顾 / 必办 / 风险 / 建议） | `app/briefing/generator.py` | 已交付 |
| **简报数字对账**（LLM 只能引用快照数字，不一致即丢弃） | `generator.py` 铁律 1-2 + admin-api 校验层 | 已交付 **（这条是硬功夫）** |

> **这一层的工程品质被低估了**：别的 AI 产品是「让模型随便说」，这里是「**模型只许组织，数字全部来自快照且逐条对账**」。
> 这正好是「AI 乱报数」恐惧的解药，销售上可以直接讲。

### 3.2 跨域视图 4 个 ✅

| 视图 | 组合 | 独特价值 |
|---|---|---|
| `product_health` | 销量 + 库存 + 退货率 + 成本毛利 | 找出「卖得好但赔钱」的假繁荣 |
| `customer_profile` | 订单 + 售后 + 标签 + 复购 | 「这个客户值不值得留」 |
| `customer_value` | 消费额 + 频次 + 最近购买 | 沉默流失显性化 |
| `delivery_risk` | 交期 + 工序进度 + 卡点 | **跨单聚合**：哪些单快到期还卡着（生产页是单任务视图，结构上答不出） |

### 3.3 处置入口（雏形）✅

简报 `todo` 每条带 `link`（`/after-sales?status=pending`、`/products?low_stock=true`…）——
「没有处置入口的推送不发」这条硬约束已经落在产品里。

### 3.4 执行能力（有限但真实）✅

族 2 三个具名批量（改价 / 批量更新 / 库存），两段确认 + 可撤销，`N > 50` 拒绝分批。

### 3.5 行业真值 ✅

算料/计价（`curtain_calc` + `docs/curtain-fabric-quote-rules.md`）、生产进度、报工明细、计件 ——
**这些是通用 SaaS 不可能有的**。

## 四、关键缺口①：没有「参照系」（✅ 已补：P0 / #8234，2026-10-31）

> **补了什么**：视图按同一快照内全部 SKU 算同行基线（中位数 / 上四分位 / 样本量），每行给
> `good`/`watch`/`bad`/`unknown`。三条纪律：**未知不装懂**（样本 < 5 ⇒ unknown）、
> **毛利为负是绝对判据**（全店都亏时仍判 bad）、**基线性质自述**（「相对、非绝对」）。
> **还没补**：历史基线（近 N 天自身均值）、客户可配置目标值（退货率上限、安全库存）。

**这是所有决策能力的地基，也是当前最该补的一层。**

现状：系统能给出**数字**，但给不出**判断**。

| 系统现在说 | 老板心里想 | 缺的是 |
|---|---|---|
| 「退货率 18%」 | 这算高吗？ | **没有基准** |
| 「这个月销量下降 12%」 | 正常吗？该慌吗？ | **没有季节/趋势基线** |
| 「库存 30 件」 | 够不够？ | **没有安全库存线（有阈值但没有「你的目标」）** |
| 「毛利 22%」 | 好不好？ | **没有行业参照** |

代码核查：`grep -rn "target\|目标值\|行业均值\|benchmark" app/briefing/` → **零命中**
（命中的 `as_of`/扫描基准日 是日期，不是判断基准）。

> **没有参照系的数字，不能用来做决定。** 老板看到 18% 还是要自己判断 —— 那他为什么需要你？
>
> 补法（成本低、收益最大）：
> ① 自身历史基线（近 6 个月均值 / 去年同期）
> ② 客户自设目标值（月销售目标、安全库存、可接受退货率）
> ③ 行业常见区间（真值可从二郎神交付沉淀里来）
>
> 补完，现有 4 个视图会**立刻**从「数据」变成「洞察」。

## 五、关键缺口②：只给一个方案，不给选择（✅ 已补：P3 / #8251，2026-10-31）

> **补了什么**：`bad` / `watch` 行带 `next_options`，每个选项有 `action` / `cost` / `reversible` /
> `verify`（怎么验证它有用）。**确定性规则表**，不读 LLM。
> **还没补**：不可逆动作（清仓 / 下架 / 换供应商，需业务裁定）、具体金额代价、多目标优化。

**决策的本质是在选项之间取舍。给人一个方案，叫「通知」；给人三个选项带代价，才叫「帮决策」。**

现状（`generator.py` 的 `suggestions` 区块）：每条是 `{title, detail, metrics}` ——
**单条建议，无备选、无代价、无「不做会怎样」**。

理想形态：

> **现象**：A 款遮光帘退货率 18%，高于你的基线 11%。
> **可能原因**：① 色差（退货原因 6/12）② 尺寸不符（4/12）
> **你可以选**：
> - **方案 1 改描述**：加「实物色差」提示 → 预计退货降到 13%，成本 ≈ 0，**但可能影响转化 -2%**
> - **方案 2 换供应商**：成本 +8%，退货预计降到 8%，**但交期 +5 天**
> - **方案 3 清仓下架**：回笼现金 ¥X，**但损失该品类入口流量**
> **我建议**：方案 1（代价最小、可逆），两周后看效果。

**三个要素缺一不可：备选、代价、可逆性。**

## 六、关键缺口③：没有复盘闭环（⚠️ 补了一半：P2 / #8253，2026-10-31）

> **补了什么**：历史简报可回溯（过去 N 天提醒过什么）。
> **还没补**：① 决策采纳记录（谁点了 / 有没有真的做）——需要新表 + 事件；
> ② 效果跟踪（建议后指标怎么变）；③ 季度价值报告（PDF / 推送）。
> 这三件是「复盘」从 🔴 回忆 变成 🔴 证明 的关键。

建议给了，执行了，然后呢？

现在**没有任何机制**回答：「上个月建议你改那 3 个 SKU 的价格，现在效果如何？」

后果：
- 客户无法感知价值（做完就忘）
- 系统无法自我校准（建议质量永远不知道）
- **续费时说不出「这半年我帮你做了什么」**

> 这一条同时也是**续费武器**：季度价值回顾报告 = 复盘闭环的副产品。

## 七、其他缺口（次要但要登记）

| # | 缺口 | 说明 | 影响 |
|---|---|---|---|
| 1 | **洞察与执行断开** | 简报 `link` 跳页面；对话内批量是另一条路 | 「看见了」到「改掉了」之间仍是人工 |
| 2 | **归因不可验证** | 简报的「为什么」由 LLM 组织，无规则化根因 | 老板会问「你怎么知道是这个原因」 |
| 3 | **无决策记录** | 每次对话独立，不记得上次建议了什么 | 无法追踪 |
| 4 | **无推演** | 「如果提价 5% 会怎样」答不了 | **从「查询框」到「决策伙伴」的分水岭** |
| 5 | **视图覆盖慢** | 判据是「加一个问题 = 加一个具名工具」 | 只有 4 个问题，长尾靠开发 |
| 6 | **外推送未建** | 日报只在后台站内可见 | 老板不登录 = 价值为 0 |

## 八、优先级建议

> 排序依据：**「补上后能解锁多少决策能力」÷「投入」**。

| 优先级 | 补什么 | 为什么排这个位置 | 投入 |
|---|---|---|---|
| **P0** | **参照系**（自身基线 / 客户目标值 / 行业区间） | 没有它，后面所有层都建不起来；且能立刻让 4 个视图升级 | 低 |
| **P1** | **洞察 → 执行连通**（简报 `link` 接对话内批量） | 两块都已存在，只差一根线 | 低 |
| **P2** | **复盘闭环**（决策记录 + 效果跟踪 + 季度报告） | 续费武器 + 让建议可校准 | 中 |
| **P3** | **选项与代价**（每个洞察配 2~3 个动作 + 代价 + 可逆性） | 「策」的核心，需要行业知识编码 | 中高 |
| **P4** | **归因规则化**（退货原因分类等） | 让「为什么」可验证 | 中 |
| **P5** | **推演内核**（如果…会怎样） | 最高价值、最高投入；是分水岭 | 高 |

## 九、一句话对客户讲

> **「现在的黄金策，是一个每天帮你看店的店长 —— 它告诉你哪里不对。
> 但『该怎么办』，还得你自己想。」**

要卖「帮老板做决定」的价格，就得把最后那句补上。

补的顺序是：**先给参照系（让它能判断），再给选项（让它能出主意），最后给复盘（让它能证明自己有用）。**
